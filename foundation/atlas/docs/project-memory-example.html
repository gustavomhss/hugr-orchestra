O bloco do charlie · build

Cenário: campanha "migrar o billing pra idempotência". Isto é o que entra sozinho no contexto do charlie, todo turno:

atlas ▸ inject @ turn-startcharlieΣ ~870 / ~5K tok 
▏ AWARENESS — self-model · derivado do root · byte-idêntica
  mission       sistema de billing idempotente ponta-a-ponta
  constitution  nenhum efeito de pagamento sem Idempotency-Key T0
  terrain       gateway · worker · reconcile · ledger — T0: gateway, ledger
  ontology      seat · território · pack · poke · tier · kit
  taste         expand/contract · sem prosa livre · gate verde ou FAILED

ORIENTAÇÃO — compartilhada · derivada do log
  goal     migrar o billing pra idempotência ponta-a-ponta
  last     WP-12 · Idempotency-Key no gateway — selado
  current  WP-13 · retries idempotentes no worker — em andamento
  state    3/5 territórios de billing cobertos · falta worker + reconcile

REGRAS — do charlie · sempre / nunca · a única escrita
  nunca  logar o header Authorization              @ src/http/**    ×12
  sempre rodar `pnpm typecheck` antes de selar     @ *             ×40
  sempre migrations = expand/contract só           @ db/**          ×7
  sempre handlers do worker idempotentes           @ src/worker/**   ×3  ← puxada pelo WP atual

awareness ~360 · orientação ~210 · regras ~300 → Σ ~870, sob o teto ~5K
AWARENESS (o primeiro slab)

O que o projeto É — mission/constitution/terrain/ontology/taste. Rollup do root do Atlas (grounded node@sha), byte-idêntico pra todo membro, não escrito à mão. ~360 tok.

ORIENTAÇÃO (o segundo slab)

Compartilhada — idêntica pra todo membro. Derivada do log: last/current vêm de eventos de milestone, então nunca envelhecem. goal é do walt. ~250 tok.

REGRAS (o terceiro slab — a única escrita)

Do charlie, privadas — o que ELE aprendeu. Note a última: só apareceu porque o milestone atual toca src/worker/** — regra certa, na hora certa. ~300 tok.

O bloco da lucy · revisão

Mesma campanha, mesmo turno. A Orientação é idêntica (é compartilhada); as Regras mudam — são as dela:

atlas ▸ inject @ turn-startlucyΣ ~810 / ~5K tok 
▏ AWARENESS — self-model · byte-idêntica à do charlie
  mission       sistema de billing idempotente ponta-a-ponta
  constitution  nenhum efeito de pagamento sem Idempotency-Key T0
  terrain       gateway · worker · reconcile · ledger — T0: gateway, ledger
  ontology      seat · território · pack · poke · tier · kit
  taste         expand/contract · sem prosa livre · gate verde ou FAILED

ORIENTAÇÃO — compartilhada · idêntica à do charlie
  goal     migrar o billing pra idempotência ponta-a-ponta
  last     WP-12 · Idempotency-Key no gateway — selado
  current  WP-13 · retries idempotentes no worker — em andamento
  state    3/5 territórios de billing cobertos · falta worker + reconcile

REGRAS — da lucy · sempre / nunca · a única escrita
  sempre exigir regressão de decisão no diff        @ *              ×22
  nunca  aprovar T0 sem o billy                     @ {billing,auth}/**  ×9
  sempre checar retry-duplo real em idempotência   @ src/worker/**   ×4  ← puxada pelo WP atual

awareness ~360 (byte-idêntica) · orientação ~210 · regras ~240 → Σ ~810

É esse o ponto: Awareness (o que o projeto É) e Orientação (onde estamos) são compartilhadas, derivadas e byte-idênticas; só as Regras são de cada um, escritas e privadas. Os três slabs injetados juntos, cada membro recebe o seu.

Anatomia, em 5 linhas

o que você acabou de ver 1. Awareness = mission + constitution + terrain + ontology + taste · rollup do root do Atlas · derivada · byte-idêntica · não escrita (~400 tok).
2. Orientação = goal + last/current milestone + state · compartilhada · derivada do log · sempre atual (~250 tok).
3. Regras = as "sempre/nunca" do membro · a ÚNICA escrita · privadas · promovidas de lições, com scope + hits (~500 tok).
4. Só entram regras cujo scope casa com o trabalho atual — relevância, não despejo.
5. Set de regras = slot fixo, top-12 por hits; a que fica com hits==0 em max(20 waves, 30 dias) é evictada pro arquivo (nunca deleta).
