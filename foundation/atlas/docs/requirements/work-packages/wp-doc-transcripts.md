intent: >
A sibling seat closing #193 found documentation transcripts still showing the pre-#107 `next:`/`invariant:`

What the sweep actually found is larger than the brief. #107 rotted the pages on THREE axes, not one: the

same claim in `design/genesis-output-contract.md` and `reference/atlas-architecture.md`. Measured through

- **I4.** The gate names every transcript it could NOT verify, on every run, pass or fail. Zero silent skips.

- **I6.** `docs/adr/ADR-0013-*.md`, `docs/reference/atlas-tools.md` and `docs/requirements/req-tls.md` are

## completeness criteria (set-level closure — GATE)

## What the lead's framing got wrong (measured, not asserted)

**Got right.** A1 held: on every transcript the binary was the truth and the page was stale. A4's ADR-0013
fence is correct — that block is the ADR's own "before" evidence. The instinct that the recurrence, not the
eight edits, was the real deliverable is the whole value of this card.

**1. "Eight" counts a site the card's own A4 forbids touching, and misses a real one.** The brief's list is
7 file-sites; the 8th occurrence of the string pair is `ADR-0013:80-81`, which A4 freezes. So the actionable
set the brief describes is 7. The actual actionable set is 8 — because
`docs/reference/commands/link.md:38-48` is a drifted `atlas query` transcript the list does not contain. It
was missed for a structural reason worth recording: it drifted on the `[<freshness>]`/`advisoryDropped`
axis but NOT on the guidance strings, so a grep for the two strings — which is what produced the list —
could not see it. Re-deriving the list mechanically instead of trusting it is what found it.

**2. The card's `action_surface` cannot satisfy the card's own rule 5.** It permits
`edit(harness/gates/<new-file>.mjs, new file only)` and nothing else outside `docs/**`. But
`harness/gates/gate-directory.test.mjs` asserts that the set of gates named in `.github/workflows/ci.yml`
EQUALS the directory listing. Adding a gate file without editing `ci.yml` and `package.json` turns that test
RED. Measured: with the gate file and the npm script present but the `ci.yml` line removed,
`gate-directory.test.mjs` exits 1 with `expected [ …(6) ] to deeply equal [ …(7) ]`; with the line restored
it exits 0. Two lines were added outside the declared surface, of necessity, and are reported here.

**3. "Build a gate that re-runs each documented command" is not reachable for most of them, and the
obstruction is a product gap, not an implementation choice.** `gate-directory.test.mjs` also enforces that
`harness/` imports NO `@atlas/*` product code. A grounded fact can only be authored by computing the
`subtreeHash` the structural index computes, and the repo's own how-to states no shipped command prints it.
Re-measured through the binary, four ways: `emit`'s refusal names the gate (`ungrounded: …`) and not the
hash; `doctor why` on an unknown key returns `whyBroken: none`; `doctor index` returns the indexer plan;
`mine` abstains. So the gate CANNOT populate a pack, and every transcript showing one is named unverifiable.

Of the eight rotted transcripts it re-runs **three** — `how-to/move-a-repo-in.md#2`,
`reference/commands/query.md#2`, `reference/commands/query.md#4`. **3/8 = 37.5%.** The five out of reach are
`emit-a-grounded-fact.md#2`, `find-and-fix-drift.md#1`, `link.md#2`, `promote.md#6`, `query.md#1`, all of
which show a populated pack. An earlier revision of this card and of the gate's header claimed "four … 50%",
reached by counting empty-pack blocks instead of intersecting the rotted set with the re-run set. It was
wrong, a cold review caught it, and the number above was re-derived independently before being written
here. The remaining coverage comes from the class DEFAULT being VERIFIED: a transcript nobody declares is
run, so a new one arrives red rather than unnoticed.

**4. "The gate must diff a transcript" is only true of a minority of good transcripts.** Of 70 documented
output blocks, 60 are not byte-diffable — and mostly for HONEST reasons the pages already declare in prose:
`init.md` says it shortened the absolute path to `/tmp/demo`; `query.md` says the untrusted-store reason is
one long line it reflowed; `link.md` says it shortened nodeKeys to `bb4094b5…`. The repo's own quality
standard sanctions this. A gate that demanded byte-equality would push every page toward dumping raw output,
which is worse documentation. The design that survives is: elision is a first-class marker the gate
understands, and everything else is named with its reason on every run.

**5. The brief framed this as documentation lag. Part of it is a live product defect.** #107 gave `atlas
query` an advisory band that is exactly `T2`. `promote.md` asserts the opposite in bold, and a mined
candidate promoted through the real door now DOES appear in the pack — verified end to end by staging a
candidate through the product's own staging door, running `atlas promote`, then `atlas query src`, which
returned `advisory T2 0e2d37a6… [FRESH]: greet() returns a greeting for the supplied name`. The same false
claim is in `design/genesis-output-contract.md` and `reference/atlas-architecture.md`; all three are
corrected here. **`atlas promote`'s own guidance string still says "(a T2 fact is bounded OUT of the `atlas
query` pack, TOOLS-6)"** — that is a string in the shipped binary under `packages/**`, which this card
excludes and two live seats own. NOT fixed here. It needs its own card.

**6. My own errors, recorded because the card asks for measurement rather than self-report.**

- I first regenerated `promote.md`'s transcript from an EMPTY fixture, because I could not construct a
  promotion — real output of `atlas query src`, but not of the state the page describes. Exactly the
  approximation A3 forbids, reached by satisfying the letter of "regenerate from a real run". Caught by
  asking what the advisory band does to a `T2` row; discarded via `cp`, redone through the real doors.
- Redone, it was **still wrong**, and the cold review caught what I did not: I staged at
  `src/greet.ts::definition`, so the block carried nodeKey `0e2d37a6…` while the other seven identities on
  that page are `802f2bcd…`, under prose asserting "same repository, immediately after the promotion
  above". Byte-true and page-false — the failure mode no byte comparison can see, and one my own gate is
  structurally blind to because `promote.md#6` is declared unverifiable. **Fixed by making the fixture match
  the page** (`src/util.ts` + `src/app.ts`, staged at `src/util.ts::definition`) rather than by deleting the
  sentence: the staged nodeKey then came back `802f2bcd…`, identical to the page's own promotion line, so
  the sentence is TRUE rather than merely unfalsifiable. The page now carries one nodeKey, 8 occurrences,
  and `0e2d37a6` appears nowhere. The gate header now states plainly that VERIFIED is a claim about bytes
  and not about narrative state.
- The first regeneration fixture had no `.gitignore`, so its re-commit swept the `.atlas/` store into git
  and the provenance tripwire correctly refused — the page briefly received a refusal transcript. Reverted
  by `cp`.
- The gate shipped with three declarations that were not earned (`mine.md#1`, `node.md#2`,
  `promote.md#10` all reproduce byte-exactly) and with blank lines normalised away on both sides. Both were
  cold-review findings, both are now fixed, and both are pinned by the twin so neither can return quietly.

Together these are why regeneration and verification are two independent programs, and why the twin exists.
