pasta igual em todo membro diferença por classe

Igual pra todos · diferente por classeum esqueleto, parametrizado — não sete arquiteturas

O esqueleto (idêntico em todo membro)
  • manifest.json — a identidade + parâmetros do membro.
  • knowledge/ — o que ele possui, escrito só por ele, lido por todos.
  • memory/project.md — injetada, capada, template rígido.
  • memory/task/ · pr/ — consultáveis, arquivam ao fechar/mergear.
As diferenças (todas via manifest + 1 arquivo opcional)
  • orquestrador — ganha logbook.md (memory); caps maiores.
  • revisão — knowledge = invariantes checáveis / restrições (predicate).
  • build — knowledge = padrões-âncora, território (fonte do pack).
  • discovery — knowledge minerado + staging; memory forte em gotchas.
  • manutenção — knowledge pequeno e volátil (staleness).
  • define / arquitetura — knowledge projeto-scoped, denso, sem pack.
O princípio de co-locação A pasta de um membro guarda o knowledge que ELE possui + a memória dele. Escrita é do dono (só charlie escreve em charlie/); leitura é universal (qualquer um lê qualquer pasta). Instâncias efêmeras (jimmy-1..n) escrevem na pasta do membro — a pasta é a identidade do assento, não da instância.

O manifest.json — o único ponto de variaçãoa classe vira parâmetro, não código novo

Todo membro nasce do mesmo template de pasta; o manifest é o que o especializa. Comparando dois:

// charlie — classe build
{
  "member": "charlie", "class": "build", "kit": "FORGE",
  "owns": { "scope": "territory", "write": "knowledge/**" },
  "knowledge": { "template": "anchor-fact-v1", "scope": "territory" },
  "memory": {
    "project": { "injected": true, "cap_tokens": 500, "template": "rule-v1" },
    "task": { "template": "task-v1" }, "pr": { "template": "pr-v1" }
  },
  "options": { "logbook": false }
}

// orchestrator — classe orchestration (mesmo esqueleto, parâmetros diferentes)
{
  "member": "orchestrator", "class": "orchestration", "kit": "PODIUM",
  "knowledge": { "template": "decision-v1", "scope": "project" },
  "memory": { "project": { "injected": true, "cap_tokens": 800, "template": "rule-v1" }, … },
  "options": { "logbook": true }   // ← materializa memory/logbook.md
}
