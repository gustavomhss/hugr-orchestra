Atlas · Genesis · bootstrap sobre repo existente

Semear o atlas num repo que já existe

Esqueleto determinístico, inteligência racionada. Custo escala com a importância, não com o tamanho.

~90% é build mecânico $0-LLM. LLM só gasta na fronteira ranqueada. Git-history é o seed grátis. O humano ratifica só o contestado.

estrutural, não embeddings (a escolha SOTA)

Existem 2 famílias. A rejeitada: GraphRAG / vetores (VoyageCode2 + vector store) — similaridade ANN, probabilístico, custo ∝ tamanho, saída = vetor opaco. A escolhida: estrutural explícito — SCIP/stack-graphs, Glean/Kythe, CodeQL/Semgrep, SZZ, Aider repo-map. Determinístico, e a saída é um fato verificável.

a propriedade que carrega

Nº de calls de LLM = função da fronteira ranqueada (hotspot × SZZ × blast), não de linhas. Dobrar código morto/sem-churn não aumenta o gasto. Custo ∝ superfície de importância. Zero vector store.

Fase por fase

S0$0 · no LLMscan — esqueleto estrutural. AST + tags def/ref via tree-sitter; resolução precisa cross-file/língua via SCIP ou stack-graphs (tree-sitter é parser, não resolvedor). Content-address de todo nó (CAS). Zero fatos — T2/advisory, T0 só flagado.
S1$0 · mecânicomine — o git-history vira ranking. Sinais MSR nomeados (SZZ, hotspots, coupling, ownership) alimentam um PageRank personalizado sobre o grafo def→ref → sites ranqueados, nunca fatos (tabela abaixo).
S2LLM · racionadoextract — a única despesa de LLM. Anda do maior-PPR pro menor; 1 call bounded por site. Fato aterrado por subtreeHash, pela porta da verdade; obviedade vira score armazenado, nunca veto (ADR-0012). Quando é checável, o check vira query CodeQL/Semgrep determinística (= o avaliador do KNOW-16). Budget-capped.
S3humano · batchedinterview — a porta de desambiguação. Owner/tier de território, T0, invariante contestado, intencional-ou-bug → entrevista curta e ranqueada (T0/alto-blast primeiro, nunca 1-a-1). Resposta vira fato human-ratified.
S4handoffhandoff — vira self-hosting. Genesis é seeding único: acabou, entrega pro loop born-from-work (init → enrich-by-blast → wave-close). Nunca fica varrendo em background.

Git-history = o seed grátiscada sinal é uma técnica NOMEADA (MSR) · não heurística caseira

sinal técnica / OSS semeia
hotspots change-freq × complexidade — CodeScene / Tornhill candidato a tier
fragilidade SZZ (Śliwerski-Zimmermann-Zeller '05) · SZZUnleashed — blame do fix → commit que introduziu invariantes frágeis (maior valor)
coupling association-rule sobre commits (temporal/logical coupling) deps ocultas + fronteiras de território
ownership blame por linha — knowledge map / bus-factor (CodeScene) candidato a owner + risco (tier)
rank PageRank personalizado sobre o grafo def→ref (técnica do Aider repo-map; sem embeddings) a ordem em que o LLM visita
Sinal minerado aponta — só vira fato depois de aterrado + ratificado. SZZ é heurística → rank, não verdade.

S2 — o raciocínio do LLM, no arnêspropositor, nunca oráculo · o análogo estático+LLM do Daikon

O LLM não é oráculo — é um propositor dentro de um arnês de verificação. O núcleo elegante: um fato só entra se o check que o próprio modelo sintetizou passar no código real. Ele não consegue mentir — a asserção dele é executável e é executada.

o contexto (determinístico, sem embeddings)

Por site: source@sha + StructRef + o RelationSet (enclosing/deps/blast, do índice) + a cicatriz do git — os commits SZZ que introduziram bug ali. Minerar os bugs pra achar o invariante frágil.

o limite honesto

Um check que passa prova a propriedade no código atual + re-checa no drift — não é prova pra todo input futuro (isso é theorem prover, fora de escopo). São invariantes prováveis machine-checked (como os "likely invariants" do Daikon), não provas — e dizem isso.

Custo & o sweet spotbarato por default · escala por valor · não vira monstro

O loop é poderoso, logo é perigoso. A regra: os mecanismos caros ficam dormentes e ligam só quando um sinal barato diz que o candidato é alto-valor E incerto. O caminho comum é 1 call + 2 gates; o caro é a exceção rara.

mecanismo default (barato) escala só quando
família do fato advisory (sem check) checável e tier≥T1 → predicate
CEGIS refine K=1 nunca além de K — abstém rápido
corroborate OFF (1 sample) T0-cand / alto-blast e incerto
refuter OFF só T0-cand, modelo pequeno
engine do check Semgrep (AST barato) CodeQL só se precisar dataflow (DB 1×)
A maior alavanca: você não semeia o repo inteiro. Só a fronteira quente — o rabo frio o born-from-work cobre de graça. Código que ninguém mexe nunca paga.

A fronteira de determinismohonesto: não é determinístico ponta-a-ponta

O que decide o que entra no store é determinístico; só o rascunho de um candidato é do modelo — e sempre passa pela grade.

S0 + S1puros e reproduzíveis. Mesmo repo@rev → esqueleto + ranking byte-idênticos. Sem modelo no caminho.
S2é LLM (conteúdo não-determinístico), mas a seleção (quais sites, em que ordem) é determinística e todo output é gated por grounding — seed sem âncora nunca entra.
S3humano — o conjunto de perguntas é derivado mecanicamente; só as respostas são do humano.
