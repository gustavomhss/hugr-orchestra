## Subsequent ownership and fixture decisions (before source freeze)

Retained E1 action binding includes actual server/client/credentials, scope/directory/Session and live composer identity, but excludes pure connectivity epoch. Each current metadata attempt includes epoch/raw/policy and gets its own abort controller. An actual POST attempt retains immutable payload/id even if a later catalog query would refuse; preparation alone does not. Known commands preserve their existing fresh invocation semantics, with no new retained command map.

Queued item A retains captured A when the current composer selects B. The actual Page dequeue owner includes queued-item identity/fingerprint plus monotonic edit/delete/reinsert generation, credentials, epoch and policy version. It does not use current composer choice. Ownership capture exposes its generation's AbortSignal; departure installs the new generation/controller before aborting the old one, while an accepted draft-to-created Session handoff preserves its signal. Shared query cancellation never reaches other admission jobs.

Session management publishes a reactive per-Session version only after installing the actual write barrier. New Session admission has a disposable draft policy-query phase BEFORE creation, then a separate Session policy-query phase AFTER the actual ID and required policy acknowledgement. Dispose a phase before a legitimate owned acknowledgement and build a fresh phase afterward; never permanently compose a stale phase's signal into the base ownership signal. External policy SET cancels the active phase. There is no await between disposal of a successful draft phase and calling Session create. Each attempt disposes only its own phases.

TUI CLI raw model intent is saved manual selection first, otherwise raw CLI ref, even if removed, before provisional agent/default candidates. Variant intent uses a NEW persisted variantIntent map (string or null) alongside untouched legacy variant storage. Presence in the new map wins; null is explicit model default and every string including "default" is literal. Legacy-only "default" is conservatively literal until the actual model/variants are known, then an owned effect pins once: literal when that named variant exists, null otherwise. Later removal cannot reinterpret a pinned string. Dialog default and named-variant values have collision-free identities and the default label is Model default. New six UI safety cases exercise this intent/persistence/payload contract under controlled canonical decisions; they do not prove Core execution of a literal default variant. Core's existing sentinel collision was found in cold review and needs its own exact repair plan/gate before E6 closes.
