A URL do authorization server observada por saveDiscoveryState é o issuer; nunca inferir por resource URL, token endpoint ou metadata.issuer. Não implementar cache persistido discoveryState que esconda mudança futura. Comparação equivale ao SDK: URL.href normaliza esquema/host/default port e tolera somente uma barra final; outro path/origin não corresponde. Issuer inválido ou ausente bloqueia somente aquela conexão, sem Bearer/refresh/secret legado em rede nem exclusão das outras entradas cifradas.

Tokens e ClientInfo preservam issuer. ClientInfo novo registra origem dynamic/configured e ID; cliente configurado conserva SOMENTE ID+issuer como metadados, nunca duplica seu secret no auth-file. Pin estático é autoridade separada de tokens e sobrevive a invalidate automático e a fluxos dinâmicos. NENHUMA alteração de config, URL ou simples startAuth apaga esse pin: outro issuer ou outro ID estático exige logout/authRemove explícito já existente, depois Authenticate. Isso evita tomar mudança de config de projeto como aprovação implícita. Logout limpa o pin e avança o fence.

Primitivas internas congeladas: checkout(name,serverUrl), begin(name,serverUrl), readBinding(binding), updateBinding(binding,patch), invalidateBinding(binding,type), consumeState(binding,expectedState), commitBinding(binding,entry), remove(name). Binding imutável contém name/serverUrl/generation. begin e remove retornam previousState opcional para cancelar somente o callback antigo. Patch é fechado a issuer observado, tokens/clientInfo, PKCE/state; callbacks não fornecem generation/serverUrl novos. Leituras all/get/getForUrl continuam diagnósticas, não caminho de entrega automática de credenciais. Remover mutadores sem fence dos callers; eventual adaptação de fixture não cria um segundo caminho de gravação.

checkout captura binding antes da construção do provider/transporte. Cada getter valida geração/URL e identidade atual de configuração: credencial dynamic não vira static, ou vice-versa, só porque um campo mudou. Sem issuer pede needs_auth; primeiro DCR sem credencial antiga pode estabelecer issuer pela descoberta observada. Tombstone após logout impede ABA; não reativar silenciosamente uma conexão encerrada.

begin é AÇÃO explícita de reautenticação: rotaciona geração e limpa tokens/clientInfo/PKCE/state anteriores numa única mutação, preservando apenas o pin de autoridade estática. O manager revoga/releases a conexão atual e a marca needs_auth; cancelar essa tentativa não restaura credenciais antigas. Decisão intencional para não manter duas autoridades enquanto uma substituição está em curso. O novo provider Pending recebe o binding e snapshot não secreto do pin.

Escrita automática não troca URL ou issuer estabelecidos. invalidate(all) limpa credenciais/acoplamentos, preservando autoridade; invalidate(client) também remove tokens dependentes daquele cliente, invalidate(tokens) mantém identidade. Callback antigo não limpa nem ressuscita registro de uma geração nova. SaveTokens valida mesmo quando o SDK engoliu falha anterior de saveClientInformation.

commitBinding somente Pending faz replacement completo CAS, exige issuer observado igual aos stamps de token/cliente, limpa PKCE/state e consome a lease rotacionando geração novamente. Preserva pin estático independente em modo dinâmico; modo configurado só cria/usa pin compatível ou após reset explícito. Providers normais novos fazem checkout da geração publicada; o Pending antigo não pode repetir commit. remove avança geração e deixa tombstone, retornando state anterior antes de qualquer await de cleanup.

Manager guarda objeto flow+binding+state; callback automático captura ESSE objeto. Depois de awaits, status/cleanup/commit só afetam o flow/entry corrente. consumeState compara e limpa atomicamente antes de exchange; cancelPending(name,expectedState) não cancela um fluxo posterior com o mesmo nome. finishAuth público continua apontando ao pending atual sem mudar Protocol. Não prometer cancelar request já enviada legitimamente ao issuer anterior.

### H7 — cold critique resolutions (before tests)

House approved test preparation; Lamport identified the callback reverse-index timeout race. Resolve it by removing the mutable name→state reverse index: pending callback entries are keyed only by random OAuth state and carry their name as metadata. `cancelPending(name, expectedState)` targets that exact entry and checks its name. All manager callers supply captured state; no cancellation/cleanup may discover the current flow merely by name. Duplicate registration of the same state rejects without replacing an existing waiter. A late registration for superseded A cannot replace or erase B; A may receive its own browser response but its persisted `consumeState` CAS must fail before exchange. Timeout, resolve, reject and stop settle their own entries exactly once. Stop is server-wide teardown and intentionally rejects all pending callbacks.

Add deterministic A→B callback registry tests for timeout, cancellation and completion of A after B registration; two managers sharing real Auth storage must prove only B consumes state/exchanges and B's credentials/PKCE/status survive A cleanup. This removes the need to compare an asynchronous registration with a separate name index. No network runs under Auth flock.

House acceptance additions: begin→failure/cancel never restores old credentials; automatic Bearer getter blocks legacy before discovery; the same Pending cannot commit twice; static pin A survives dynamic B commit and changing static ID/issuer still requires logout; AS same origin/different path mismatches; metadata.issuer cannot impersonate the observed AS URL; default-port and one trailing slash normalization stay compatible; auth file never stores configured static secret. Observe resource, registration and token endpoints independently.

The H7 guarantee fences issuer/identity replacement and logout across generations. It does not introduce ordering or single-flight for normal refresh responses within the same valid generation; existing refresh behavior remains subject to the provider's token semantics. Do not claim otherwise in tests or guides.
