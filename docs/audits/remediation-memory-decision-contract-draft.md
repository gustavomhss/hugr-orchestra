## Durable record and identity

One immutable UTF-8 JSON line at `.atlas/project/memory-decisions/<proposal.id>.jsonl`. Private discriminated type:

```ts
type MemoryDecisionReceipt =
  | { readonly version: 1; readonly proposal: ReviewOf<"memory-proposal">; readonly decision: ReviewOf<"memory-decision">; readonly indexed: { readonly record: MemoryRecord; readonly ref: RecordRef; readonly sequence: number } }
  | { readonly version: 1; readonly proposal: ReviewOf<"memory-proposal">; readonly decision: ReviewOf<"memory-decision"> }
```

Runtime rule: indexed field required IFF decision.verdict===indexed, forbidden for discarded. This provisional type should become a proper discriminated exported private union only if expressible without widening existing ReviewOf. No outer kernel hash invented. Entire wrapper and every nested object are CLOSED: no extra fields, including grounding/status/freshness. Proposal keys exactly id/kind/member/rule/scope/at/by; decision keys id/kind/proposalId/verdict/at/by plus optional nonempty rule/scope. Recompute Review IDs through existing actual parseInput+kernel id semantics; equality compares all known field values, not hash alone or property order. Filename equals proposal.id and must match actual valid raw review proposal exactly. Validate hash path format against actual kernel output before path construction; never arbitrary caller path.

Indexed record keys exactly owner/kind/entry; owner equals proposal.member, kind project; entry exactly rule/scope/frecency. Effective rule/scope use existing nonempty override-or-proposal semantics. Frecency===INITIAL_PROJECT_FRECENCY. Actual validate(project,entry), put and versioned([record]) define record and exact ref (contentHash,eventId only), no manual hash/envelope. No optional grounding because this path currently only accepts proposal rule/scope. Indexed.sequence is a positive safe integer captured as max real durable log seq + 1 immediately before staging publication; reconstructed native event retains exact versioned identity and uses sequence only as its existing non-identity ordering hint. Cross-proposal concurrent sequence ties retain existing stable-order behavior; no total causal publication order or tamper-proof sequence claim. Discarded contains no indexed object. No new arbitrary rule/proposal byte limit: preserve existing template/cap behavior, including preexisting duplicate candidate cap counting. This change does not defend against enormous externally edited filesystem input; existing JSONL readers also read whole files.

## Governed preparation and publication

Validate decision verdict/by/at/optional overrides before any candidate work. Invalid input returns existing controlled refusal (template-invalid), no writes. Resolve proposal from fully valid review. Existing valid receipt with same semantic intent returns original decisionId/ref even if new at differs; compare proposal identity, verdict, by and EFFECTIVE rule/scope, not incidental timestamp or presence of redundant overrides. Different intent returns proposal-not-open. Legacy closed proposal keeps old refusal; no invented exact retry receipt.

For indexing use actual createMemoryEmit with actor proposal.member and real durable read, but append into a single candidate-only capture sink. This executes actual template/partition/cap/named scanner and creates exact MemoryRecord without durable activation. Discard does not scan or create Memory. After preparation reread raw+receipt review and revalidate proposal open/identical and state fully known, so scanner-triggered path failure in baseline stops publication. This is not a lock against old binaries or arbitrary external review writers.

Create owned random temp in SAME receipt directory with exclusive creation; write complete validated line, close, read/validate own bytes, publish via linkSync(temp,final) create-only. No rename overwrite. EEXIST validates actual winner against actual raw proposal; same intent reconciles, different refuses, corrupt/unreadable fails closed. Published receipt is sole commit point. After successful link, return original receipt success even if own temp cleanup fails; do not claim rollback/failure after truth committed. Cleanup removes ONLY this invocation's temp, never winner or another temp. On failures before publication no new effective Memory/decision. Temp non-jsonl names are ignored by readers; post-crash cleanup is not part of normal read.

One-process AND multiprocess same-proposal contenders get at most one winner on local supported filesystem. Cross-proposal per-owner cap remains existing bounded concurrency limitation; no NFS/power-loss/old-binary coordination guarantee. Git attributes must override general JSONL union ONLY for receipt subtree in root and modules/atlas: divergent same-proposal receipts are explicit merge conflicts whose marker bytes reader rejects. Update layout/ignore/user docs/invariant to describe receipt decisions alongside legacy append log. Do not claim append-only review file contains every new decision.
