# M13 Main, capture and recovery integration — architectural plan

The private outbox, manager, real Core/SQL bridges and actual Electron SQLite gate are qualified separately. Production wiring is still absent. This plan does not authorize implementation before its exact shared contracts, scaffold and acceptance have independent review.

## Local ownership and placement

Current Live is one Main-owned loop with app-wide settings and logs under app.getPath("userData"). It has no Dock profile identity. Root chooses an explicit app-wide recovery-owner role, desktop-live; do not borrow the active Dock profile or silently change Live when a browser profile changes. Pass the actual userData directory to the existing openLiveOutbox factory and preserve its live-outbox/outbox.sqlite layout. The Store already creates/loads its durable UUID profileID transactionally; use that returned identity. Never pass the role label as profileID, infer one from a path, introduce another identity file or replace the Store's UUID. The role label is not a cryptographic installation identity. Existing database profile validation and exact remote target checks remain required. Document this scope rather than claiming new cross-install isolation.

A single Main owner opens the Store and constructs the manager once. Failure to open or validate storage exposes an unavailable facade and disables new recording before capture or remote meeting creation; do not fall back to the volatile sender. Ordinary app operation remains available. Manager.shutdown already joins jobs and closes the Store; Main must not independently close it again. The owner exposes the private manager to capture and a separate metadata-only public recovery port. Renderer receives no credentials, raw database handles, arbitrary export paths or transcript bodies through snapshot.

## Connection lifetime

Replace the one-shot serverReady closure for Live with a Main-owned connection broker. A connection has the existing manager mode, opaque epoch object and server credentials. Repeated lookups retain the same epoch while the known resource is unchanged. Owned PID spawn/restart, exit and known credential replacement invalidate it. Never create a fresh epoch on every getter, and never reference owned before startOwnedServe assigned it. Initial publication follows the existing initial health check. Restarts reuse the known URL/credentials only after the old capture owner has been stopped and joined; readiness/HTTP failure remains explicit, without pretending the initial health promise covers every restart.

Before rotation or quit begins draining, synchronously close admission to new starts and incompatible mutating recovery actions. Abort pending startup and broker waiters, and join the actual startup promise as well as any late installed handle. LiveLoop.stop currently returns immediately after aborting a pending start; replace that behavior rather than assuming the abort joined it. A new tray/IPC/internal start cannot enter during this window; setAppQuitting alone does not gate Live. Rotation may reopen admission only after the new owner/connection is published; quit never does.

Invalidation pauses publication of a new connection, aborts pending startup and joins capture through LiveLoop.stop. That stop must depend only on local capture/STT/final callback cleanup, never remote ACK or summary delivery, avoiding a broker/stop/network cycle. Broker waiters own their AbortSignal and cleanup. Main tracks asynchronous rotation jobs and joins them during shutdown. Shared external server lifecycle is not observable here; do not claim PID fencing for it. Manager's real target/directory/Session/meeting/time identity verification remains the authority for every delivery/recovery attempt.

## Capture and durable admission

startSenses receives the actual manager; remove production use of the volatile meetingClient sender. Use manager.start with the current pending-attempt signal before opening capture. A late cancelled start must not install a stale senses owner. Every segment calls producer.append synchronously and reports accepted/duplicate/refused truthfully. Keep M11's signal checks, attempt identity and late-handle cleanup.

Normal stop memoizes its promise before invoking callbacks. Persist requestClose first, stop capture, join STT and final callbacks, flush the cutter, then seal only after those resources are joined. A refusal or cleanup failure cannot claim all final segments were saved/sealed; abandon the producer lease when appropriate and leave an interrupted recoverable record. Storage/quota failure immediately stops capture through the producer signal. The UI must say recent audio may be missing after admission failure, even when one unsaved segment remains in memory; accepted segments alone have the durable guarantee. Do not represent unsavedUnavailable=false as proof that every tail segment survived.

The remote stop/delete path remains manager-owned and follows persisted close intent, seal, no active producer, exact ordered ACKs and confirmed ended tuple. Stopping local capture does not await delivery or discard unsent records. Network failure retains pending data and recovery state. Recovery never creates another Session or meeting automatically.

## Completion and Session work

Add an optional private manager completion observer invoked only after successful Store.complete, with localID, Session ID and meeting ID; observer errors cannot undo a committed deletion. LiveLoop subscribes to this signal. Automatic summary requires both locally joined capture closure and confirmed delivery completion for the still-owned foreground meeting, once only. Completion alone or capture stop alone is insufficient. A stale/replaced owner cannot post a summary into the new meeting. Explicit recovery Finish persists local close/seal intent without creating a Session or automatically prompting the live seat. It is not a delivery receipt: the existing private finish action does not restart a paused/blocked campaign. Keep it pending and offer Retry where required; only the actual completion observer confirms remote completion.

Bound Session-client create/prompt/rename requests with request-owned signals/deadlines and join them on replacement/quit. SSE has a bounded header handshake and an owner-cancelled long-lived body; do not impose the short request timeout on an intentionally live stream. Preserve durable admission retry semantics and never claim network timeout retracts an already admitted prompt.

## Public recovery port

Extend the existing pure app-shell live.ts leaf, exported as @orchestra/app/live. Freeze exact DTOs before dispatch: state and metadata items (opaque local ID, title, Session/meeting IDs, times, pending counts/bytes, close/seal/producer/status/reason and unsaved warning). Public failure reasons are stable enums; do not return private target/credential objects. The existing private manager snapshot is not the renderer DTO.

Provide snapshot, Retry, Finish using saved segments, Export and Discard by opaque local ID. Route both new and existing privileged Live IPC registrations through the trusted senderFrame wrapper in ipc.ts; live-ipc.ts currently uses direct ipcMain.handle and does not inherit it automatically. Keep the entire preload/renderer/platform chain typed. Export uses a Main-owned native save chooser and writes only after user selection using an exclusive sibling temporary, closed/synced bytes and atomic rename; no raw database export or renderer path argument. Cancellation is an ordinary result. Discard requires a clear local-data confirmation and does not silently close or delete the remote record.

Expose recovery in the actual Live/Flight chapter and entry card, with current metadata and explicit storage/incomplete warnings. Use the existing Flight copy and language fallback model; avoid bypassing locale parity through new unlocalized app messages. Active recording and pending delivery are distinct user states. Never offer normal capture when durable storage is unavailable.

## Quit and verification

before-quit joins local Live stop, then owner rotation/manager shutdown (including Store close), then sidecars/runtime. Preserve existing window flushing. A failure is observed and cannot be presented as successful durable flush; retain the recovery data and preserve original plus cleanup causes. will-quit remains a fallback rather than the primary unjoined destroy path. No application/server restart is performed by this campaign.

Acceptance precedes source: actual loop/senses with a real Store/manager and real HTTP, controlled capture/STT boundary only; offline append then reopen/retry, quota/refusal stop, cancellation during startup/late handles, final segments before seal, no remote stop before ACK/seal, completion-before/after local stop and stale completion, owned epoch replacement, unavailable storage, trusted/untrusted IPC, export cancellation/failure and local discard, quit ordering with pending requests/readers, concurrent new start versus quit/rotation and join of an aborted startup. Finish accepted locally must not become a completed-delivery UI state. Keep private40/108/3 bridges and real Electron proof as separate qualifications, not substitutes for wiring. Hosted tests and exact-source cold review, serial non-Atlas package types, then final epic and one PR. Root owns architecture, shared contracts, scaffold and integration; four Sol execution packets must have disjoint files.

Cold critique record: owner/broker architecture APPROVE; public/IPC critique FIX-FIRST required an admission fence plus joined startup and accurate Finish-versus-completion vocabulary. Both are now explicit. Exact DTO/API scaffold and acceptance still precede production GO.

## Contract and acceptance wave

Root contract 3ed31aaac4 defines the metadata-only public LiveRecoveryPort, private owner API and compilable unavailable owner scaffold. Two independent critics approved the seam. Admission must also be enforced inside owner.manager.start, not solely through a caller's canStart check. Completion originates only after Store.complete; disappearance after Discard is not completion.

Root UI scaffold c4f0a21f8e defines FlightRecovery({port: LiveRecoveryPort}); its inert body has no production behavior. The eventual surface belongs in both the Flight chapter and Home entry. Platform exposes optional liveSeat.recovery. Snapshot reads are refreshed while mounted and on focus, bounded to one outstanding read, and late results are ignored after disposal. A snapshot/read failure cannot imply delivery or idle. A locally successful Finish refreshes the snapshot without removing the item optimistically. Discard requires explicit confirmation that it removes local recovery data only.

The capture seam is registerLiveLoop's delivery option, a Pick of LiveDeliveryOwner's manager, canStart, connection and onComplete. stop(reason = user), with rotation and quit alternatives, joins local resources only; rotation and quit disable automatic summary before consulting any memoized stop. startSenses uses the actual LiveDeliveryManager, returns localID alongside meetingID, and adds capture/transcriber runtime ports typed from the existing implementations. Those ports control hardware/STT in acceptance; Store, manager and HTTP remain real. Existing unsent stop metadata is not a delivery receipt. Source migration removes the volatile sender and replaces its tests explicitly.

Acceptance ownership: io_recovery owns new owner Node tests and fixtures; desktop_recovery owns new senses/capture Node integration tests and fixtures; ui_recovery owns the new isolated DOM recovery acceptance. memory_recovery first qualifies Atlas evidence and the new Atlas hard-gate finding, then owns IPC/export acceptance. Tests and fixtures have disjoint paths. No production GO has been issued: Root reviews the acceptance coverage and supplies remaining IPC/Main scaffolds before source packets. Implementation integration order is private completion/owner, capture, trusted IPC/preload, then actual chapter/entry. Main shutdown and connection rotation remain Root-owned integration seams. All land in audit-remediation and PR 1463 only.

The IPC/export seam now has type-only LiveIpcOptions {handle,recovery}; registerLiveIpc(loop, options) receives the existing privileged Main handle wrapper instead of importing ipcMain.handle. Main's wrapper calls shared requireTrustedSender(event, rendererDevURL, channel), whose implementation must reuse isRendererOrigin and preserve packaged/development behavior. Every existing and new Live privileged registration uses that wrapper. Five new channels are get-live-recovery, retry-live-recovery, finish-live-recovery, export-live-recovery and discard-live-recovery. Preload API names are getLiveRecoverySnapshot, retryLiveRecovery, finishLiveRecovery, exportLiveRecovery and discardLiveRecovery, mapped to the public LiveRecoveryPort in the renderer. No renderer-supplied export destination or transcript argument is accepted.

exportLiveRecovery(data, {signal,choose}) is the private Main helper; choose is an owned native-dialog closure taking no renderer arguments. Race the uncancellable chooser against abort, observe its late settlement without writing, then serialize the explicit DeliveryExport envelope only after a choice. Admit one owned file operation: exclusive sibling UUID temp, mode0600, write/sync/close, abort check, atomic rename, and cleanup on failure. No raw SQLite dump or directory creation. The owner joins admitted file work on shutdown; dialog cancellation is an ordinary cancelled action. Preserve an existing destination until the rename succeeds. IPC snapshot failures become a stable generic error rather than inventing an empty successful snapshot; action failures use public reasons. The new scaffolds are inert and are not wired into production before acceptance review.
