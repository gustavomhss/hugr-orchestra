# L4: bind replayed rows to the proof they carry

Status: architecture proposal for independent review. No implementation authorization. L4 remains open.

Replay currently re-proves a CAS fact but publishes the log's complete row unchanged. A valid proof therefore does not establish the row's address, claims, governance or auxiliary carriers. Kernel content hashes also exclude grounding/status/freshness recursively. A log hash, seat folder or source commit is not authentication. The deferred signed-commit decision remains unchanged.

The intended boundary is validation before activation, rather than repairing a logged row into a different assertion. A row activates only when its complete semantic payload is justified by actual fact bytes and current production reproof. A mismatch retains the original candidate in staging for ratification; it must not silently drop a claim, relation endpoint, human link or answer reference. Existing trusted/tracked-staging/tracked-provable rules stay fixed. The local projection must not become trusted merely because a new replay journal exists.

First freeze a canonical positive using the actual `composeRuntime().deriveRelations()` path, shared indexed-repository/SCIP fixture and current reverify oracle. Reopen a separate empty destination store, restore the actual logged bytes and verify that the legitimate relation activates at its exact canonical key. Replaying again must be idempotent. This positive must reach the actual publication/readback path; synthetic keys, empty claims or `reproven: () => true` do not qualify it.

Against that same genuinely re-provable fact, adversarial cases must independently alter key, family, claims, scope, tier, primary anchor, family carriers and provenance. Recompute the ordinary public event hash so rejection is attributable to the new binding, rather than the existing torn-line check. Unprovable human/history carriers must remain available as staged evidence and never acquire authority from metadata alone. Cover known-good legacy byte shapes and absent optional fields explicitly before freezing compatibility behavior. Refusing every row is not a valid fix.

The source contract must then specify each supported proven family separately: advisory witness, relation, negation and test-vacuity. Derive address and canonical claims through the existing identity/building rules, including the relation's actual NUL-separated claim, rather than inventing another formula. Scope/tier and per-claim provenance must agree with the actual fact and applicable production gates. Cross-family carriers are not harmless extras. Unsealed and justified transition facts keep their existing staging behavior.

Accumulated claims and provenance require supporting facts, not just the newest CAS object. Supersession, human sameAs/retractions and answer receipts have different authority requirements; a single re-provable fact cannot certify them. Before implementation, inventory these legitimate historical shapes and decide their exact activation/staging rules, with positive controls for the supported shapes. Preserve original bytes and report held rows; do not relabel staging as data deletion or historical cleanup. `derivedAt` must be produced by local verified publication, never refreshed from a forged log timestamp.

Independent planning review approved this direction with five required decisions before a source contract: (1) `sameRow` currently skips reproof for already-present rows, and equality cannot certify a formerly replayed assertion; (2) staging currently deduplicates primarily by content hash, which cannot preserve different claims/carriers naming the same CAS object; (3) actor authorization must use the validated semantic scope; (4) every accumulated claim needs its own actual support, with explicit missing-support behavior; (5) optional-field presence and local derivations need closed per-family rules. These remain open design items, not delegated implementation choices.

The family inventory also found an important compatibility case: the specialized negation write request currently omits the row seal even when its promoted CAS fact retains `seal: proven`. Requiring unconditional row/fact seal equality would reject genuine existing output. Other proven-family requests carry the seal. Preserve this distinction in positives before deciding whether a future format change is necessary. The shared SCIP fixture is controlled serialized protobuf, not an invocation of a real indexer; test reports must describe it accurately.

Tests and any required bundling run only on hosted CI. Production changes and boundary-generated outputs require separate source approval, serial package typecheck, exact snapshot proof and official generation/recovery. Full Atlas Vitest/Own qualification belongs to the final single-PR gate. L5 causal publication ordering is a separate design: its future durable metadata may establish sequencing but cannot authenticate a human assertion or replace L4 reproof.
