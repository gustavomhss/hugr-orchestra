# L9 Session transfer preserves source files

Root decision: carrying changes copies the captured scoped patch to the destination and moves the Session, while retaining source files and index. Remove the automatic post-publication Git discard. No new input field, destructive command or implicit cleanup is added. The previous plan's compare-before-delete cannot fence an external writer or an already open file descriptor on the supported platforms; it is not sufficient for the required source-safety guarantee.

This intentionally changes the documented moveChanges=true behavior. Source and destination may both remain dirty. The destination receives the captured patch, not a promise of the source's latest concurrent contents. There is no atomic multi-file snapshot or transaction spanning apply and Session publication. Same-project checks, capture/apply failures, same-checkout handling and omitted/false transfer remain intact. The move itself must perform no source cleanup, including when there is no competing writer.

Cold architecture review accepts retention and identified required consistency work: public Protocol description, specific TUI carry dialog wording, server comment/legacy reset failure and exact source-retention tests. Keep the shared destructive workspace-deletion dialog unchanged. Update the user guide. Retain the exported ResetSourceChangesError as a documented legacy compatibility type unless a separate removal is justified; the move no longer emits it. Public HttpApi metadata change requires the official hosted Client generator again, never hand-edited generated output.

Acceptance first: update only the old reset/removal assertions to deliberate exact retention, preserving destination bytes, moved Session projection, staged index, nested scope and unrelated-file assertions. Add a real independent writer using AppProcess/Omni and an owned constant actor. It opens its descriptor before the move and waits for a file acknowledgement. An additional typed EventV2 projector for this Session's Moved event releases the writer after capture/apply and joins its ACK and natural exit inside the actual durable transaction before returning. commitDurableEvent awaits these projectors before publication returns, placing acknowledged writes before the old cleanup. It appends to the existing projector list and does not replace SessionProjector; the writer performs only filesystem work, without SQL reentry. Cover tracked replacement, captured untracked contents, a new untracked file, rename replacement and an already-open descriptor. Assert every acknowledged source byte survives and captured destination bytes remain exact. Keep the default/false path controls and a serial retention control. No copied Git algorithm, global mock, probabilistic sleep or fake success containment.
