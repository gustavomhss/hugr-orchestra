# M13: actual Electron storage capability

The private Store and Manager pass their Node gates, but Desktop pins Electron 42.11.16, whose embedded Node must be measured separately. Before wiring the new SQLite store into Main/Senses, qualify the actual store module inside a real Electron main process. This is a capability gate, not full application or packaging qualification.

Add one Desktop Bun native test and one narrow Electron fixture. Reuse the existing response-download native test's executable discovery and Linux Xvfb launch pattern. Declare `expectSpawn` and start every child through the real AppProcess/Omni services. Resolve the validated installer using existing `electronInstallScript`; invoke it through bounded `AppProcess.run`, rather than reusing the helper's grandfathered raw exec. No new spawn allowlist entry, workflow, dependency or production source change is authorized.

Build the fixture only on the hosted runner with `Bun.build`, target Node/CJS, importing the actual `openLiveOutbox` source. Electron and Node builtins stay external; do not replace `node:sqlite` with a fake. Use actual Electron main with `ELECTRON_RUN_AS_NODE` absent, an isolated existing userData directory and no renderer or production app startup. Linux uses the existing `xvfb-run`/`--no-sandbox` pattern; missing native prerequisites fail setup rather than skip. Never start or restart the owner's local app.

The fixture reports actual `process.type`, Electron/Node/SQLite versions and PID, requires main/browser process identity and matches the pinned Electron version. In its owned profile, open the real outbox, create one valid target/meeting and append one exact segment ID. Close it, reopen a fresh store and require the same profile ID, record, pending count, segment content and native batch IDs. Inspect SQLite integrity after closing the store and require `integrity_check` success. No network peer or delivery-policy reimplementation is needed for this gate. Always close handles and exit the actual Electron process on success or failure.

Parent assertions require the actual proof record, natural exit0, nontruncated bounded stdout/stderr and joined child/reader/temporary-profile cleanup. Record build/source hashes and measured runtimes without dumping the environment. Bound installer execution to 180 seconds and Electron execution to 45 seconds; a 240-second test budget contains setup and cleanup and never certifies success by expiry. Test execution and fixture build are hosted only, through a scoped BOTH-OS `test:ci` request after full Root/independent review, typecheck and a pushed checkpoint.

This does not establish packaged ASAR/fuse behavior, UI, microphone permissions, Capture/STT lifetime, Manager wiring, close intent delivery or quit behavior. Packaged runAsNode is disabled, which is why this gate must use an actual Electron main process. Subsequent M13/M11 contracts and gates remain required.
