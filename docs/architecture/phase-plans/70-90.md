### 4.3 Guard rules (`script/check-module-boundaries.ts`)

**Scope.**
- Files: `git ls-files -co --exclude-standard -z`, extensions ts/tsx/mts/cts/js/jsx/mjs/cjs, under a registered package path.
- Excluded: `node_modules/`, `dist/`, and `modules/atlas/**` except `modules/atlas/boundary/`.
- Anti-vacuity: fail if fewer than 4,000 files are parsed or fewer than 2,000 cross-package edges are found (about 4.9k files at baseline).

**Parsing.**
- Specifiers come from `ImportDeclaration`, `ExportDeclaration`, `ImportEqualsDeclaration`, `import()`, `require()`, `ImportTypeNode` and `import.meta.glob(str|str[])`.
- `typeOnly` is tracked; type-only edges still count for R1.
- Workspace specifiers are resolved **only** through the registry path plus that package's `package.json` `exports`, read from the working tree. Relative specifiers use the stem candidates `[s, s.ts, s.tsx, s/index.ts]`, with `@/` for orchestra and app-shell. **Never through `node_modules`** (Risk 7).

**Test predicate.** `isTestFile` is exported and shared with the tools:

```
/(^|\/)(test|tests|e2e|test-browser|fixture|fixtures|__tests__|\.storybook|script|scripts|campaign|example|examples|benchmark)\/|\.(test|spec|stories|fixture|suite|test-helper)\.[cm]?[jt]sx?$/
```

| default (strict) | Fails on new violations and on stale entries. | CI, lead |
| `--no-stale` | Ignores stale entries. | cards |
| `--scope <path-prefix>...` | Parses only the scoped files. Runs R0/R6a/R8 globally (no parse). Reports stale only for entries whose file is in scope. | cards |
| `--json` | `{ new: [...], stale: [...], counts: {rule: n} }` | cards, lead |
| `--prune` | Removes stale entries, never adds. Exits 1 on any new violation. | lead |
| `--seed` | Writes the ledger only if it is absent. | lead, once |

**Cost contract.**
- AST only: one `createSourceFile` per file, walked then dropped, with no AST retained.
- No `child_process`: use `Bun.spawnSync` for git, because the spawn-import gate scans root `script/`.
- P4 measures `/usr/bin/time -l bun run check:boundaries`. Budget: full ≤ 20 s and ≤ 1 GB max RSS; `--scope` ≤ 3 s.
- Cards always use `--scope`. If the full run misses its budget it still runs in CI, but the lead records the numbers.

### 4.4 Tools (`script/`, sharing `script/module-architecture.ts`)

`script/module-architecture.ts` is the shared library, ≤ 250 LOC. It contains:
- registry decode (effect `Schema`)
- `isTestFile`
- `resolveExport(exportsMap, subpath)`: Node rules. `*` matches across `/`; precedence is an exact key, then the longest prefix before `*`, then the longest key.
- `ownerOf(file, domains)`
- `listFiles()`
- `renderReadmeBlock(alias)`

The guard (≤ 500 non-blank LOC) imports it.

**`explicit-exports.ts <alias> [--write|--check|--count|--verify-resolution <baseRef>]`** (80-90 §3.3 algorithm):
1. Assert the manifest is canonical, i.e. `JSON.stringify(pkg,null,2)+"\n"`. Otherwise exit `EXPORTS_MANIFEST_NOT_CANONICAL`.
2. Split the old map into explicit `E`, asset wildcards `A` and code wildcards `C`.
3. Demanded literals: `git grep -hoE` of quoted `<name>/<sub>` over tracked files, excluding `*.md`, `specs/`, `docs/` and `bun.lock`, plus `entries`. Keep a literal only if it resolves through `C` to a tracked file. This drops service-tag strings: core 7, server 4, relay 5.
4. For `full`, also add the inverse key of every non-test, non-story file under `C`.
5. New map `N = E ∪ A ∪ sorted(derived)`.
6. Invariant: every kept literal resolves to the same file under `N` and the old map. Otherwise exit `EXPORTS_RESOLUTION_CHANGED:<s>`.
7. `--verify-resolution <baseRef>` reads the old map from `git show <baseRef>:<path>/package.json`, re-scans literals, and prints `checked=<n> same=<n> changed=<n> lost=<n> ignored=<n>`. Here `lost` means it resolved before and does not now. It exits 1 if `changed + lost > 0`.
8. `--count` prints the key count of `N`.

**`compat-facade.ts <alias> <prefix>... [--write|--check]`**:
- Visit non-test source files under the prefixes, skipping `src/compat/`.
- For each string-literal specifier in `ImportDeclaration`, `ExportDeclaration` and `ImportTypeNode` that is mapped by the registry `legacy` specifiers (§4.5), replace only the literal text, keeping the quote. Edit from the end of the file to the start.
- Write `@/compat/<f>` in app-shell. Elsewhere write a POSIX relative path without extension.
- Errors: `FACADE_MISSING`, and `FACADE_UNSUPPORTED_IMPORT_FORM` on a default or namespace import (verified: 0 exist).
- Prints the changed-file count. `--check` exits 1 if anything would change.

**`module-readme.ts <alias>... [--write|--check]`**:
- Renders the block below. It replaces an existing block, or appends one after one blank line.
- It never creates a README: RN cards create the file first.
- core and orchestra also get `### Domains` (one line per domain: `id` — kind — patterns — target).

## 10. Risks and traps specific to this repo

1. **omni-expect-guard is a path reader.** `packages/core/test/omni-expect-guard.test.ts:61-70` maps `@orchestra/core/<sub>` to stem files and silently drops anything it cannot resolve. Any future move or rename of a core file reachable by package specifier weakens it without a failure. This is why there are no moves (D12) and why X1/M1' need a guard change first. Closing `exports` does not affect it, because it ignores `exports`.
2. **Path-keyed ledgers:** `script/rename-ledger.ts`, `godfile-waivers.json` (74 waivers, 65 in app-shell), `script/spawn-allowlist.json` (76 sites), `script/archive-scopes.json`. No card moves or renames a file. FAC edits change only a specifier on the same line, so godfile line counts are unchanged.
3. **Hash- or shape-pinned workflows.** `distribution-bundle-workflow.test.ts:209-212` pins the static job's steps, so the gate goes only in `test.yml` (no test pins its steps; verified). `lean-candidate.yml` is hash-pinned and untouched, but its cache key hashes `package.json` files, so the EXP cards cold-start that cache once. Core test inputs hash `test-ci.yml`, `distribution-bundle.yml` and `setup-bun`; P4 asserts they are unchanged.
4. **Plugin exports are runtime data** (`core/src/plugin/sdk-package.ts:33-43`). Never edit `packages/plugin/package.json` `exports`. The plugin compat files are safe: the shim re-exports through the virtual `orchestra-plugin-sdk:` specifier, not through file lists.
5. **The rename guard scans every tracked file and path.** Places that need care:
   - The ledger carries vendored specifiers (R3 rows) and the registry names the tarball, so P1 must land before P2/P4 commit them.
   - The guard source and its fixtures must use registry-sourced or fake vendored names.
   - Facade files are named `vendored-client*`.
   - READMEs carry no token.
6. **Specialist-name guard** (`apps/orchestra/test/agent/specialist-name-guard.test.ts`): `owner` fields and READMEs use roles and ids only.
7. **The node_modules symlink trap.** Card and integration worktrees symlink another checkout's `node_modules`. With Bun's isolated linker, `node_modules/@orchestra/*` points into **that** checkout, so `Bun.resolveSync`, `import()` or tsgo from a card worktree would read the other tree's `package.json` `exports` and prove nothing. The guard and tools therefore resolve workspace specifiers only from the working tree (registry plus `exports`). Only `typescript` comes from `node_modules`. Real Bun, Vite and Electron resolution is proven by T2, T3 and the epic CI.
8. **Effect service-tag strings look like specifiers** (`"@orchestra/core/tools"`, `"@orchestra/relay/ArmStore"`, `"@orchestra/server/CatalogAvailability"`; core 7, server 4, relay 5). The generator keeps only literals that resolve to tracked files. The guard reads AST import positions only.
9. **Node `*` semantics.** `*` matches across `/` and the longest prefix wins. `./v2/styles/*` beats `./v2/*.css`, and `./v2/*.css` beats `./v2/*`. CSS consumers (`packages/app-shell/src/index.css`, `settings-v2.css`) use explicit keys or asset wildcards. The generator's literal scan covers `.css`.
10. **Typecheck is not a complete exports oracle:** ui and session-ui exclude stories, app-shell checks only `src`, and desktop excludes its tests. The generator invariant plus R6b over all files are the real check.
11. **Self-references.** Core imports itself by package name (237 subpaths in tests). Never trim keys that are "only used by tests".
12. **Dead aspirational file.** `apps/orchestra/specs/v2/api.ts` (`// @ts-nocheck`) imports `@orchestra/core` and `@orchestra/core/tools`. That gives 2 R6b rows, and the generator excludes `specs/`.
13. **Relay docs guard.** `modules/relay/bin/check-docs.py` validates markdown links in `modules/relay/README.md`, so the block has no links. The review-record hash of that README (`docs/reviews/runtime-fixes.json`) is historical: it is already ≠ the current file and is not checked by any test.
14. **Turbo caching.** `@orchestra/script#test.inputs` must list the four new root files, or cached passes survive edits. Do not edit `module-registry.json` (a global dependency).
15. **Nix.** `nix/scripts/dependency_measurement.py` fingerprints every blob under `packages/`, `modules/` and `assets/`, so every card changes it; requalify only at 90-A. `nix/scripts/workspace-paths.json` maps `@orchestra/core/*` → `src/*.ts`, bypassing `exports`.
16. **Spawn gate.** `check:spawn-imports` scans root `script/`, so the new scripts use `Bun.spawnSync`, never `child_process`.
17. **Godfile.** The guard must stay ≤ 500 non-blank LOC (hard limit 750), so split it via `script/module-architecture.ts`. JSON files are not counted.
18. **Two packages are named `orchestra`** (the root and `apps/orchestra`). The registry keys by alias; R4 must not treat the root as a workspace dependency.
19. **Windows CI.** POSIX paths from `git ls-files -z`, CRLF-tolerant parsing, and ledger keys normalized to `/`.
20. **Mac load.** 20 agents run no tsgo and no install; the guard's `--scope` ≤ 3 s. Never stop or restart the Orchestra desktop app or its local server.
21. **Baseline drift.** #738 and #755 may change counts. Receipts from the P5 rehearsal, not this file's numbers, are the expected values in the briefs.
