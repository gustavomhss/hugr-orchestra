Reviewing AI and agent artifacts: how should a reviewer judge changes to prompts, agent skills, playbooks, tool definitions, model routing, evals and LLM-calling code? This matters because Orchestra itself is mostly made of such artifacts. Use primary sources (Anthropic and OpenAI prompt and agent guidance, Agent Skills docs, OWASP Top 10 for LLM Applications and Agentic AI threats, MCP security guidance, papers on prompt regression, eval methodology and LLM nondeterminism).
Subquestions: (1) prompt and skill review: clarity, contradiction and ambiguity detection, instruction hierarchy, prompt bloat and context budget, progressive disclosure, rules that belong in host-enforced tools instead of prose, and how to detect behavior regressions from a prompt diff; (2) agent safety review: prompt injection and indirect injection paths, tool permission scope, least privilege, confused deputy, data exfiltration channels, human-approval gates, MCP server trust; (3) eval review: whether a change ships with evals, eval contamination and overfitting, statistical significance with nondeterministic outputs, LLM-as-judge validity, golden sets and regression suites; (4) LLM-calling code: retries and timeouts, streaming and cancellation, token and cost budgets, caching, structured output validation, model version pinning, provider fallbacks, billing and terms constraints; (5) what this repository already has (seat prompts in modules/maestro/coordination/src/seats/prompt, playbooks, seat skills, script/seat-skills.ts, prompt tests and hash pins, the claude-code host gate, ToolSafety sandbox) and which review checks it lacks.
