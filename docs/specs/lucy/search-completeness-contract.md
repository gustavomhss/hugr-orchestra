## 1. Explicit semantic change

Today `coverage.complete` ignores `binariesSkipped` entirely. An early binary
match can already produce `binariesSkipped: 1` together with `complete: true`.
This proposal deliberately changes that meaning: a result is not complete
when a matching file was only partially searched because of binary detection.
It also corrects the count for a binary file that emitted a primary match
before detection, and prevents an incomplete secondary probe from certifying
completeness. This is more than a counter repair.

Preserve returned matches, clipping, context, mode/case/glob selection, stable
ordering and offset/limit pagination. `next` and `bounds.truncated` continue
to describe pagination only. Binary incompleteness does not invent a next
page or claim that a result page was cut by its limit. A final offset page may
still be complete if no other incompleteness remains. Preserve the named
`pattern_invalid` error for an actual invalid regex and existing typed process
failure behavior. Research and Review use the same corrected semantics.

## 2. What the binary count means

Define sets from the actual native calls, before applying the requested page:

- **M**: canonical paths with at least one actual primary JSON `match` event.
- **B**: canonical paths whose primary JSON `end` has a valid non-null
  `binary_offset`. Zero is a present offset.
- **P**: canonical matching paths from a successful, complete secondary
  `--files-with-matches --binary` probe of the same pattern and selected scope.

When the secondary probe certifies P, the unresolved matching binary set is
**`(B ∩ M) ∪ (P − M)`**. `binariesSkipped` is the unique size of that set.
It counts unresolved
matching files, not every file containing NUL and not names containing the
pattern. It remains a query-relative count, not a repository binary inventory.

A file with NUL but no pattern match belongs to neither M nor P and does not
make the result incomplete. Even if an end event for a no-match file were
present, intersecting B with M prevents its inclusion. With the inspected
15.2.0 command, the JSON printer additionally uses `always_begin_end(false)`:
an end is emitted only after a begin generated by a match/context, and normal
context comes from matches. The contract does not rely solely on that output
optimization. A real no-match binary control is required.

Require complete primary output, no next page, a complete successful probe,
and an empty unresolved binary set for `complete: true`.

If the secondary capture is truncated, P is unknown. Do not parse or use its
partial filename stream. Return **`|B ∩ M|` as a lower bound** for
`binariesSkipped`, with `complete:false` and the exact diagnostic below. A
reported zero in that situation means zero proven unresolved matching files,
not proof that no matching file was skipped. A secondary process/exit/framing
failure instead returns the named error below, so there is no result counter
to interpret. No new public counter or optional certainty field is added.

## 3. Probe integrity and scope

Keep the two existing native passes and their capture budgets. Make the
secondary filename stream NUL-framed, with strict UTF-8 decoding. Normalize
complete paths exactly as the primary result does; do not add a new path
allowlist. Empty output with exit 0 or 1 is valid. A nonempty stream must end
in NUL, and every framed filename before that final delimiter must be
nonempty. Deduplicate complete normalized names.

Apply this precedence, without falling through to a more permissive branch:

1. An AppProcess typed failure stays `CodeSearch.Failure` with reason
   `search_failed` and the existing underlying error message. Interruption
   and unexpected defects propagate unchanged.
2. A returned secondary exit code other than **0 or 1**, including 2, is a
   `CodeSearch.Failure` with reason **`search_failed`**, not a partial result.
   Its message is exactly `ripgrep binary coverage probe exited <code>` plus
   `: <trimmed stderr>` when that bounded stderr is nonempty. Exit failure
   takes precedence even if output is also truncated. The primary pass's
   existing invalid-regex recognition remains `pattern_invalid`.
3. With exit 0/1, any `stdoutTruncated`, `stderrTruncated` or
   `outputTruncated` flag makes the probe uncertified. Do not attempt to parse
   its possibly malformed suffix/prefix. Preserve valid primary matches,
   return `complete:false` and the lower-bound counter, and append exactly:

   ```json
   { "path": ".", "reason": "ripgrep binary coverage output ceiling reached" }
   ```

4. Only a normal, untruncated exit reaches decoding. Invalid UTF-8, missing
   final NUL or an empty framed filename returns `CodeSearch.Failure` with
   reason **`search_failed`** and the exact message
   **`ripgrep binary coverage probe returned invalid NUL-framed UTF-8 paths`**.
   It must not become a clean zero, a partial success or an unexpected parser
   defect. A complete valid list certifies P and permits the set calculation.

Existing primary read-error/output-cap diagnostics remain in their original
order; the secondary truncation diagnostic is appended without erasing them.
It does not set `next` or `bounds.truncated`.

No new public option, observation callback, download, subprocess backend or
binary-as-text result mode is needed. Preserve the caller's signal, Review's
no-download resolver and scoped child cleanup. General repair of truncated
primary JSON is outside this slice; its current failure does not certify a
complete result and must not be silently relabeled by this change.

## 4. Four real native acceptance cases

Use genuine temporary files, the resolved ripgrep, and AppProcess. An
observational forwarding wrapper may record the actual native outputs; it
must return them unchanged. Positive witnesses run before negative assertions.

| Case | Real prerequisite and assertions | Predecessor classification |
| --- | --- | --- |
| Text plus nonmatching binary | Two regular text matches; `needle-name.bin` contains NUL but no `needle` in its bytes. Observe the complete secondary result and prove that file is absent from its matching paths. Require the two text matches, binary count zero, no next page and `complete:true`. A clean zero query remains complete too. | **Positive control**, expected green. The pattern in the filename makes the byte-based distinction explicit. |
| Early matching binary | A regular text seed and a small `needle\0...` file. Actual primary output omits the binary match; the actual secondary probe includes the file. Assert the existing binary count is one before checking completeness. | **Expected RED at complete:false**: baseline already counts one, but reports complete:true. |
| Late binary after a primary match | A separate regular seed and a file with a matching first line, at least 256 KiB of short nonmatching padding lines, then NUL and a later matching line. Observe the actual primary early match, positive `end.binary_offset`, absence of the later match, and the actual secondary filename. | **Expected RED at binary count one / complete:false**: baseline subtracts the already-matched file, yields count zero and complete:true. Preserve the valid early match. |
| Native secondary capture truncation | First prove the unmodified search/probe complete. For a second call, a forwarding AppProcess decorator changes only the actual secondary stdout capture ceiling to a tiny positive bound, preserving the native command, remaining options and returned result. Assert its real truncation flag before evaluating the CodeSearch result. | **Expected RED at complete:false**: baseline ignores the real secondary truncation. Require the exact section 3 diagnostic and lower-bound count; primary matches and page fields remain unchanged. |

The fourth case qualifies propagation of native truncation, not exhaustion of
the production 8 MiB default. It does not fabricate exit codes, byte streams,
timeouts or output flags. This distinction must remain in the qualification
record. No new skips or swallowed missing-runtime prerequisites are accepted.

The late-binary fixture searches directory root `.` as production does.
Ripgrep's automatic mmap selection chooses mmap only when every explicit
path is a file; this directory search uses the streaming reader. The upstream
binary tests establish late-NUL behavior for that reader, but the fixture must
still observe the real witnesses on each host before its RED qualifies.

## 7. Frozen native-exit qualification addendum


Add one fifth native case before the first hosted baseline: a valid normal
search first, followed by the same actual CodeSearch entry with a valid text
pattern and `paths: ["[z-a]"]`. This is a descending character range, not an
invalid regex. Ripgrep 15.2.0's globset parser rejects it explicitly, including
the upstream `err_range1` test. Do not use an unclosed `[` as the fixture:
glob construction can allow an unclosed class to become a literal.

The forwarding observer must prove both genuine calls received that glob,
the primary and secondary returned exit 2, and the secondary stderr was
nonempty. Return every native result unchanged. The target is a typed
`CodeSearch.Failure`, reason `search_failed`, with exactly
`ripgrep binary coverage probe exited 2: <trimmed secondary stderr>`.
The predecessor currently returns an empty partial result: primary exit 2
without the regex-error marker is allowed, and the secondary exit is ignored.
This is a causal assertion RED for the new secondary-exit check, not a
fabricated process failure. A different resolved binary must establish the
same real witnesses before the result qualifies.

The source chain for that fixture is:

- [Globset parser and its exact `[z-a]` rejection test](https://github.com/BurntSushi/ripgrep/blob/15.2.0/crates/globset/src/glob.rs): `parse_class` rejects a descending range; `err_range1` fixes this input.
- [Ignore glob construction](https://github.com/BurntSushi/ripgrep/blob/15.2.0/crates/ignore/src/gitignore.rs): `GlobBuilder::build` failure becomes `Error::Glob`.
- [Override builder](https://github.com/BurntSushi/ripgrep/blob/15.2.0/crates/ignore/src/overrides.rs) and [argument conversion](https://github.com/BurntSushi/ripgrep/blob/15.2.0/crates/core/flags/hiargs.rs): `add_line` and `builder.add(glob)?` propagate the failure.
- [Ripgrep entry point](https://github.com/BurntSushi/ripgrep/blob/15.2.0/crates/core/main.rs): a non-broken-pipe argument error is printed and returns exit 2.

The cap fixture remains viable without changing precedence. Hugr Orchestra's
`AppProcess.collectStream` keeps draining after the retained-output ceiling,
marks truncation, and does not terminate the process or close its output pipe.
The capped CodeSearch path uses that streaming collector. Therefore a tiny
capture ceiling does not itself cause a signal exit; the test must still
observe the real normal exit 0/1 rather than assume it. Source inspection is
not a substitute for that hosted witness.

The qualification boundary is deliberately narrow:

| Case or branch | What can be qualified by these native cases |
| --- | --- |
| Case 1: text and nonmatching NUL bytes | Positive preservation control for byte-based membership, no-match completeness and ordinary successful native output. It is not an expected RED. |
| Case 2: early binary | The changed meaning of `complete` when the already-correct binary count is nonzero. |
| Case 3: late binary | The `B ∩ M` contribution, unique count and incomplete result while preserving valid primary matches. |
| Case 4: capped secondary stdout | Real stdout-truncation propagation, the exact diagnostic, preserved primary/page data, and refusal to decode a partial filename stream. It does not qualify production 8 MiB exhaustion or separately induce stderr-only truncation. |
| Case 5: invalid glob | The actual secondary exit-2 refusal and exact named error, after a valid ordinary search control. It does not independently exercise every other nonzero exit or exit-plus-truncation combination. |
| Untruncated malformed UTF-8/NUL output | **Not independently qualified.** A genuine functioning ripgrep emits the requested NUL framing; none of these cases manufactures corrupt native stdout. The defensive decoder/refusal in section 3 remains source-reviewed protection, not a native RED claim. Reuse the existing strict filename-decoding policy narrowly; this slice does not authorize a broader parser project. |
| Unusual filename fidelity | Ordinary paths exercise successful framing on the candidate. They do not independently prove newline-containing POSIX filenames; Windows cannot provide the equivalent native fixture. No cross-platform claim is made for that untested filename boundary. |

No new parser fixture, fake byte stream, altered process result or production
scope is introduced by this addendum. The fifth case uses the same proposed
acceptance file. Existing pagination and invalid-regex controls remain exact.
