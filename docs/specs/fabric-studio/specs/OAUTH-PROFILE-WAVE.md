# R02 — perfil e admissão de callback

**WP IDP01, solo.** Próximo recorte depois de MSQ01; não é OAuth completo nem tentativa durável. Referências S02, MSAL-QUALIFICATION e C01/C07. Nenhuma rota/listener, rede, token, chave ou cache do operador é ativado.

## Contrato e limites

- `FabricIdentityProfile.admit(unknown)` só é chamado pelo composition root com configuração do host. Resultado discriminado ok/profile ou erro genérico `invalid-input`. Perfil runtime imutável e não serializável como licença: callback aceita somente a identidade de objeto emitida nessa instância de módulo, nunca cópia/JSON. Isto **não** substitui ServerOperator, ContextGuard, state durável de uso único ou autorização Microsoft.
- Desktop inicial: cliente público UUID canônico, redirect explícito `http://localhost:<porta>/api/fabric/oauth/callback`, porta válida não default, sem userinfo/query/fragment. Não admitir IP/IPv6 de loopback por suposição; 127.0.0.1 tem registro separado ainda não qualificado. Porta real/listener/registro Entra serão comprovados na fatia de tentativa. Server: cliente confidencial UUID, origin HTTPS host-owned sem path/query/fragment/userinfo, redirect HTTPS na mesma origem e no path fixo. Não aceitar clientSecret/certificado nesse descritor: credenciais pertencem ao futuro host de exchange.
- `callback(profile,{url,expectedState})` valida bytes UTF-8 (16 KiB), origem/path/fragment/userinfo, unicidade de parâmetros fechados OAuth, state esperado e recebido com comparação timing-safe. State host-owned, base64url de 32–256 caracteres; não é nova Authority. Code não vazio até 8 KiB e sem caracteres de controle. Code e erro simultâneos recusados. Erro remoto vira somente outcome denied, sem descrição/URI sensível nem fetch. Nenhum redirect posterior/returnTo livre é admitido.
- Parâmetros permitidos: state/code/session_state/iss/error/error_description/error_uri. `iss` não é validado como identidade por este parser e não concede confiança: exchange/ID token precisa provar assinatura/issuer/audience/nonce/tenant/conta separadamente. Callback sintático válido não consome state, não produz conexão e não autoriza token. O code retornado é somente para o futuro host interno de exchange, nunca DTO/log/modelo.

## Ownership, prova e continuidade

Somente novo `modules/fabric/src/identity-profile.ts`, export de módulo e teste `identity-profile.test.ts`; sem nova Schema pública/wire/HttpApi/migração ou dependência. Aceitação: perfis desktop/server distintos; URLs/credentials/origens erradas; cópia de perfil; state/code duplicados/trocados; limites UTF-8; erro sanitizado; nenhum callback inválido entrega code. RED compilável antes da implementação, CI focado, contraprova do vínculo de origem/state e restauração. Não reexecutar C07/PR02/MSQ01 sem delta relevante. Encerrar este WP não encerra a campanha: seguir para state durável, integração de cache/MSAL e obrigações R13 ainda abertas; registro/budget/tenant reais continuam bloqueando qualificação remota, não autoria local.
