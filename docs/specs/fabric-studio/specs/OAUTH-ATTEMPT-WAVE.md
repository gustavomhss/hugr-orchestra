## Contrato congelado

- `FabricIdentityAttempts.make({operators, root, profile, maxAttempts? , now?})` usa Database/Project existentes e perfil runtime realmente emitido por IDP01. Cópia/JSON de perfil é recusada. Limite hard de 1024 rows de tentativa no store, configurável apenas para menos; todos os estados contam, sem apagar tombstones para liberar quota. `now` é instrumento do host, nunca request.
- `begin({context, scopes}) -> FabricIdentityAttempt.Ref`; `inspect({context, attempt}) -> Info`; `cancel({context, attempt}) -> Ref`. Schemas canônicos no pacote Schema; nenhum novo HttpApi/Client/evento/ferramenta. O primeiro conjunto de scopes é deliberadamente só `https://api.fabric.microsoft.com/Workspace.Read.All`, singleton; ainda não promete outras superfícies, execução remota ou consentimento real. Extensão de scopes terá qualificação própria, não string livre de manifesto.
- Ref é ID aleatório de 256 bits emitido no servidor e revisão inteira positiva; não concede acesso. Begin admite estado interno `preparing`, prazo fixo de dez minutos do relógio host e metadados de contexto/store/principal/Location/projeto/perfil/scopes. Não há state/nonce/verifier/code/token no record nem no recibo. `preparing` não é tentativa pronta para callback. `pending/exchanging` e conclusão serão outra fatia, sem fingir que já existem.
- Toda chamada exige invocação real do operador **e Location.Service atual**, comparada exatamente a `FabricContexts.resolve`: directory, ausência/presença de workspaceID, project.id e project.directory. Mesmo Project global não equipara contextos. Falta de Location falha tipada; JSON não preenche Location nem Authority. Construção do serviço não captura Location de um request anterior.
- Resolução de diretório/projeto fica fora de SQL; ambient transaction é recusada antes dessa observação. Dentro do writer imediato, revalidar binding atual e row de contexto (store/principal/generation/estado/root/directory/projeto). Nenhum filesystem, MSAL, cifra ou rede no callback SQL. Não extrair/mudar o guard de C07 nesta fatia.
- Begin/cancel usam `CapabilityRequest` para recibo idempotente SQL-only, retorno **somente Ref**, mesma chave/exato payload reconcilia; reutilização conflitante falha. Checagens de dono/contexto/perfil e autoridade também nas repetições. Cancel usa CAS de revisão e é terminal; concorrência não produz duas transições. Inspect não muda row/TTL; expiração projetada recusa novos cancelamentos. Falha/relógio regressivo/corrupção não limpam rows nem recomeçam login automaticamente.
- Info contém somente Ref, estado `preparing/cancelled/expired` e deadline; sem material OAuth, principal, caminho, scopes, perfil ou JSON armazenado. Futura preparação precisa de seam interna fresca e explicitamente autorizada; **callback público nunca reconstruirá Authority de owner/state no SQL**. Receber callback, reivindicar uma vez, verificar JWT/conta e publicar cache são WPs separados ainda não congelados.
