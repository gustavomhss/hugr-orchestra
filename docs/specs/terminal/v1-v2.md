# Terminal do agente: V1 e V2

2026-10-25. Nota para quem for aposentar o V1.

## O fato

O Orchestra tem dois motores de sessão:

| Motor | Onde | Ferramenta de shell | Quem usa hoje |
|---|---|---|---|
| V1 | `apps/orchestra` (`SessionPrompt`) | `apps/orchestra/src/tool/shell.ts` | **o chat do app** |
| V2 | `packages/core` (`SessionV2`, `SessionRunner`) | `packages/core/src/tool/bash.ts` | testes e o caminho novo; o chat ainda não |

O terminal do agente (PR #894, flag `ORCHESTRA_AGENT_TERMINAL`) roda cada comando do agente num PTY próprio, numa aba `agent: <comando>` que o dono vê e pode digitar. Ele está ligado **só no `bash` do V2**, por decisão do dono ("Mantém só o V2"). O e2e (`packages/core/test/agent-terminal-e2e.test.ts`) prova o caminho sessão V2 → modelo roteirizado → bash → PTY.

## Consequência hoje

No chat do app, mesmo com a flag ligada, os comandos do agente **não aparecem em aba**: o V1 roda como antes. O resto do épico do terminal (terminal do usuário, cwd herdado via OSC 7, estado e notificação das abas) já vale no app.

## O que falta, e onde

- **O V1 tem que deixar de existir** (dono, 2026-10-25). A migração do chat para o V2 é a campanha do PR #873 (`v2-maestro-parity`, U0-U17), não o épico do terminal. Em 2026-10-24 nenhum commit do #873 passava no typecheck; o plano era refazê-lo a partir do `dev`.
- **Nada a fazer no terminal quando o chat for para o V2**: a aba do agente aparece sozinha. Não ligar `AgentTerminal.run` no `shell.ts` do V1; seria código que morre com ele.
- Ao remover o V1, conferir que o chat do app chama o `bash` do V2 com `Pty.node` no grafo (já declarado em `bash.ts`) e rodar `agent-terminal-e2e.test.ts` e `tool-bash.test.ts` pelo `test:ci`.

Referências: `docs/specs/terminal/status.md` (seção de escopo V2), `AGENTS.md` (Terminal and PTY), `.orchestra/skills/terminal-maintenance/SKILL.md`.
