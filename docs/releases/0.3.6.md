# Release 0.3.6

Freeze reviewed `dev` on `release-0.3.6` after the release infrastructure lands. Dispatch `release-cli.yml` and `release-desktop.yml` with version `0.3.6`, `sign=false`, `publish=false`; dispatch `test.yml` and `distribution-bundle.yml` on that same frozen commit. Preserve all four successful run IDs.

Download `release-assembled`, all `desktop-*` installer artifacts, and `release-desktop-feed` into separate `cli`, `desktop`, and `feed` directories. Validate the downloaded Mac Intel desktop and CLI in an isolated profile. Do not use the existing installation as evidence for this cut.

Create `VALIDATION.json` with `schemaVersion: 1`, `version`, `sourceSha`, numeric `cliRunId`, `desktopRunId`, `qualificationRunId`, `fullRunId`, and `validation: { result: "pass", appVersion: "0.3.6", cliVersion: "0.3.6" }`. Record actual runtime checks and every published file's relative `path`, byte `size`, and lowercase `sha256` in `files`. Keep raw validation evidence with the cut. Attach the receipt to a draft `release-candidate-v0.3.6` release targeting the frozen source.

Run `release-promote.yml` on `release-0.3.6`, supplying the four run IDs and receipt SHA256, first with `publish=false`. Only after all checks pass, use `publish=true` with identical inputs. Promotion downloads and verifies the existing artifacts; it never rebuilds them. If the release environment only permits `dev`, temporarily allow this exact frozen branch and remove only that additional policy after publication.

Verify annotated source tags, npm integrity, release asset digests, and the desktop update feed against the receipt. Never move a published tag or overwrite published versioned release assets. A partial publish can be retried with the same receipt and runs; different existing bytes fail closed. These binaries are unsigned; this procedure does not claim signing or notarization.

The inherited update feed uses fixed installer filenames. Promotion backs up the old assets and restores payloads before metadata on upload or digest failure. A brief metadata/payload mismatch remains possible during the update; versioned release assets remain immutable.
