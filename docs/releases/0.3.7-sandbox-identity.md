# Sandbox parent identity investigation for release 0.3.7

The old rollback ownership check could treat a replacement directory as the directory it had created, then remove that replacement. Distinct native file IDs became equal JavaScript `Number` values; in the observed failures, device and creation time also matched. The production fix shipped in 0.3.7 compares exact `BigInt` identities and rejects zero file IDs.

The release source is [`197dc302f77ea8d4da27425e0774e1298568fecb`](https://github.com/gustavomhss/hugr-orchestra/commit/197dc302f77ea8d4da27425e0774e1298568fecb). The historical source is [`2c0f005490dde198f1e4777b5da8dacb98f57ba2`](https://github.com/gustavomhss/hugr-orchestra/commit/2c0f005490dde198f1e4777b5da8dacb98f57ba2). Investigation date: 2026-11-12.

## Ownership failure

[`sandbox-parents.ts` at the historical source](https://github.com/gustavomhss/hugr-orchestra/blob/2c0f005490dde198f1e4777b5da8dacb98f57ba2/packages/core/src/sandbox-parents.ts) records `dev`, `ino` and `birthtimeMs` after exclusive directory creation. On preparation failure, it compares those numeric fields before nonrecursive removal. Number equality cannot distinguish every integer file ID above its exact-integer range.

The fixture renames the created `owned` directory to `moved`, creates a new `owned`, and makes the original deliberate absent-control lookup fail. Rollback must preserve the replacement. The latest native observation captured:

| Field | Original directory, now `moved` | Replacement `owned` |
| --- | --- | --- |
| Native file ID | `18014398509791294` | `18014398509791295` |
| ID converted to Number | `18014398509791296` | `18014398509791296` |
| Device | `1422631540` | `1422631540` |
| Creation time in nanoseconds | `1794496843290857900` | `1794496843290857900` |

The fixture recorded completed rename and replacement creation. After preparation returned the expected placement denial, verification failed at the actual `stat(owned)` with `NotFound` / `ENOENT`. Its pre-teardown snapshot found `owned` absent and the original identity still present at `moved`.

An [earlier instrumented native replay](https://github.com/gustavomhss/hugr-orchestra/actions/runs/43220072766) directly recorded successful cleanup removal after a numeric identity collision. The latest replay observes the alias and disappearance through the corrected fixture; it does not add a direct `rmdirSync` trace.

## Maintained failure reporting

[PR #1523](https://github.com/gustavomhss/hugr-orchestra/pull/1523) added bounded, pre-teardown state and the captured identity regression. [PR #1530](https://github.com/gustavomhss/hugr-orchestra/pull/1530) then addressed two masking paths in that fixture:

- Typed rename/mkdir setup failures could become the expected placement denial. Setup now preserves the original error as an Effect defect.
- `isDir` could turn a stat error into `false`. Verification now uses uncaught `stat` and records the verification phase.

All three new error-channel regressions failed [before the change](https://github.com/gustavomhss/hugr-orchestra/actions/runs/43240581300) and passed [after it](https://github.com/gustavomhss/hugr-orchestra/actions/runs/43241032384) on Linux and Windows. The identical reviewed test also passed [against complete published production source](https://github.com/gustavomhss/hugr-orchestra/actions/runs/43241223284). The 128-case loop belongs to the isolated forensic workflow; the maintained test suite retains the focused regressions.

## Original event boundary

The [first isolated failure](https://github.com/gustavomhss/hugr-orchestra/actions/runs/43176744279) records an expected placement denial followed by `isDir(owned) === false`. It does not record setup completion, identity operands, cleanup action or the original stat error. Its JUnit contains two attempted assertions and an empty AssertionError.

Controlled fault probes demonstrated that a failed rename followed by legitimate own-directory rollback can produce those observations. A typed stat failure can also make the actual `isDir` helper return false while the directory remains present. Those synthetic controls are separate from the native observations above.

The retained original attempt, full 96-member log archive, artifact inventory, failed-shard JUnit, annotations, linked PR records and exact saved Turbo cache provide no discriminator. The cache contains successful prerequisite builds only. The ownership defect and its fix are experimentally established; the individual cause of that first event remains indeterminate.
