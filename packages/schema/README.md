# @orchestra/schema

Browser-safe, serializable wire and storage contracts shared across Orchestra: shapes, codecs and stable identity schemas. Domain packages own services and runtime behavior; this package owns only the definitions.

Dependencies run Schema -> Core and Protocol -> Server. The only runtime dependency is `effect`; do not add Core, Protocol, Server, filesystem or host-runtime imports.

## Who uses it

Almost everything: `packages/core`, `packages/app-shell`, `modules/maestro`, `modules/relay`, `packages/protocol`, `packages/server`, `packages/session-ui`, `packages/client`, `packages/sdk-next` and `packages/plugin`.

## Entry points

- `@orchestra/schema` (`src/index.ts`): canonical domain namespaces and the helpers from `src/schema.ts`, including `MaestroEvent` and `ResearchEvent`.
- Specialized entrypoints are direct subpaths listed in `package.json`, for example `@orchestra/schema/session-event`, `.../workspace-event`, `.../lsp-event`.
- `event-manifest` and `durable-event-manifest` are infrastructure subpaths, not root exports.

## Rules

- Define each contract and ID once. Facades re-export the exact schema value and brand; they never create a second identity.
- Names are unversioned (`Session`, `Permission`, `Question`). Old stored rows are decoded privately by the package that reads them.
- Keep contracts portable to browser and generated-client consumers.

After a change that reaches the public Protocol or Server `HttpApi`, run `bun run generate` in `packages/client`; never edit its generated files. Contributor rules are in the [Schema guide](./AGENTS.md).

## Commands

From this directory: `bun typecheck`. Tests run on CI from the repository root: `bun run test:ci schema [files...]`.
