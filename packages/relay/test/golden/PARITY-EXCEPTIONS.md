# Parity exceptions

Every place the TS engine diverges from a golden, with its reason and the test that pins the TS behaviour. A golden
mismatch that is not listed here fails. The owner reviews this file before the Python Relay is retired.

| ID | Golden or exit path | Divergence | Reason | Test |
|---|---|---|---|---|
| J1 | judge: HTTP redirect | urllib follows a 301, 302 or 303 as a GET and raises on a 307 or 308. The TS judge follows none and returns `api error: HTTP Error <code>: <phrase>`. | Following a redirect would send the judge key to a location the config did not name. | `test/judge.test.ts`: a redirect is an HTTP error and is never followed |
| J2 | judge: no API key and no base URL; backend choice | Python fell back to `ANTHROPIC_API_KEY`, chose the `api` backend when it was set, and named it in `api: ANTHROPIC_API_KEY not set`. TS reads only `JudgeConfig.Config` and returns `api: judge API key not set`. | Owner decision: no provider credential ever reaches the judge. Naming a provider variable would point the operator at a setting the judge never reads. | `test/judge.test.ts`: no provider or legacy judge variable is read, sent or obeyed |
| J3 | judge: transport failures other than an HTTP status | A connection failure, a timeout or a body that is not JSON carries Bun's message after `api error: `, not CPython's (`<urlopen error [Errno 61] Connection refused>`, `Expecting value: line 1 column 1 (char 0)`). The 60 s timeout covers the whole exchange rather than each socket operation. The verdict, the backend tag and the abort are unchanged. | Those texts are specific to CPython and the OS (the errno differs between macOS and Linux), and the reason never reaches the ledger. | `test/judge.test.ts`: a body that is not JSON is an api error; a reply that never comes is an api error after 60 seconds |
| WP1-1 | `relay_chain_append` tail (`jq -r '.seq // -1'`, `jq -r '.h // empty'`) | A last line whose `seq` is not an integer, null, false or absent, or whose `h` is a float, array or object, refuses the append with `write` and releases the lock. | Bash feeds such a `seq` to `$((seq + 1))`, where a string is read as a variable and `set -u` kills the writer while it holds `.chain.lock`; it prints such an `h` as raw JSON into `prev`. Neither is a chain worth extending. | `ledger.test.ts` "a tail whose seq or h bash could not use refuses the append and releases the lock" |
| WP1-2 | `relay_chain_append` body and tail, read by jq | Text jq accepts but strict JSON does not (`NaN`, `Infinity`, `nan`) is a refused body (`body`) and an unreadable tail (the next entry links from GENESIS). | One grammar for every reader. The verifier rejects such a line anyway, so jq's acceptance only produced a ledger that cannot verify. | "a malformed body or a top-level h appends nothing and leaves no lock; nested h is data", "the tail is read as `tail -1 \| jq` reads it" |
| WP1-3 | `relay_chain_lock` | A missing ledger directory fails the lock at once instead of after 200 tries (about 10 s). Every other mkdir failure is retried like the bash loop. | Waiting cannot create the directory, and the outcome is the same: `lock`, nothing appended. | "a missing ledger directory fails the lock at once" |
| WP1-4 | `strict_json_loads` | Nesting deeper than 1000 levels is a decode error, "maximum nesting depth exceeded", which verify reports as a BROKEN line. | CPython raises RecursionError there, which verify_ledger.py does not catch (a traceback, exit 1, empty stdout); JS would overflow its stack instead. | "nesting deeper than 1000 levels is refused instead of exhausting the stack", "a deep nesting is a BROKEN line, not a crash" |
| WP1-5 | `RELAY_GEN` (`jq -r '.gen // 0'`, then the digits check) | A digit-only `gen` beyond 2^53 − 1 resolves to 0. | The oracle stamps those digits, but `AppendInput.gen` is a JS number. No sprint reaches such a generation. | "generation is what `jq -r '.gen // 0'` prints when that is all digits" |
| WP1-6 | `json/numbers.json`, column `computed` | `RelayJson.compact` refuses a JS number that is not a safe integer instead of printing jq's computed form (`1e+17`, `1.5`). | R1: ledger numbers are integers. Parsed literals keep exact parity through `compactNode` (column `literal`), which is the path every appended body takes. | "number table: literals print in jq's canonical form; compact writes safe integers only" |
| WP3-1 | `check/check-hook-variables-visible`, `arm/parity-hook-variables-visible`; E2, E4, K1, K2: command environment and `${name}` | The Python check `eval`s inside the hook, so a command sees the hook's shell variables and functions (`i`, `SPRINT`, `RUN_DIR`, `LEDGER`, `ledger_item`, …) and its whole environment, and `$0` is the hook script; `${name}` in context and scope paths expands from the same. TS runs a fresh `bash -c` with PATH, HOME, RELAY_* and the run's params only (`$0` is `bash`), and `expandParams` reads params only. | Hook internals are not a contract, and the hook environment can carry secrets (R2, R7). | `test/gate.test.ts` "WP3-1" |
| WP3-2 | `arm/parity-judge-paths-glob-from-cwd`; E3, E4: judge `paths` | bash word-splits the scope and also pathname-expands each word against the hook's cwd (the workdir in the goldens), for both the artifact digest and the diff pathspec, so `*.md` digested `a.md` and `b.md`. TS word-splits only; a glob word stays literal, which equals bash whenever nothing in that cwd matches. | The hook's cwd is incidental to the control. | `test/gate.test.ts` "WP3-2" |
| WP3-3 | E2, K1, K2: a command that cannot run | Python has no timeout and assumes bash: a hung command hangs the hook, and a vanished workdir makes `cd` fail as a `deterministic` fail. TS records `unavailable(missing\|timeout\|spawn)`, verdict fail, failing, with the command's oracle sha. | A check that did not run is not a deterministic verdict; WP10 kills it after 60 s. | `test/gate.test.ts` "WP3-3" |
| WP3-4 | `arm/e4-judge-responses`; E4: judge transport | judge.py is a process: a criterion starting with `-` makes argparse exit 2 (`judge:unavailable(exit-2)`), `RELAY_JUDGE` can substitute the program, and any nonzero exit is `unavailable(exit-N)`. TS calls the judge service in process: there is no argv and no exit status, so the golden's `exit-7` replies grade as the pass they printed. Its response is still validated: a verdict other than pass/fail or a non-string or NUL backend is `judge:unavailable(invalid-response)`. | No CLI backend or child process (module map, spec §1). | `test/gate.test.ts` "WP3-4", "judge response" |
| WP3-5 | E3, E4: judge context that is not UTF-8 | judge.py reads context files and the diff in strict UTF-8 text mode; undecodable bytes crash it (UnicodeDecodeError, exit 1, `judge:unavailable(exit-1)`), unless the stub is forced and reads nothing. TS gives such a context file no text (the stub fails it as unmarked, the API judge sees `(file not found)`) and treats such a diff as `judge:unavailable(no-diff)`. | Same fail-closed outcome without a crashing transport. | `test/gate.test.ts` "WP3-5" |
| WP3-6 | K4, K8: malformed counter | For a negative counter the CLI grades `work_packages[-1]` (jq indexes from the end) and reports `i: -1`. TS refuses any counter that is not a nonnegative integer with `PlanError`, as the CLI already does for every other non-integer. | `CheckOutcome.i` is a nonnegative integer; the arm never writes a negative counter. | `test/gate.test.ts` "WP3-6" |
| WP3-7 | E3, E4: `\u`/`\U` in a scope path | The artifact digest runs the accumulated lines through `printf '%b'`. TS encodes `\u` and `\U` escapes as UTF-8, surrogates included, as bash 5 does in a UTF-8 locale. bash in the C locale (the golden generator's) prints an unencodable surrogate as a literal `\uD800` instead. | Locale-dependent output cannot be byte-pinned; every other `%b` escape matches bash 5.3 in both locales. | `test/gate.test.ts` "WP3-7" |
| WP3-8 | `arm/e5-host-check` | The Python gate has no host checks: a control with only `host_check` has neither a command nor a criterion and records `judge:unavailable(invalid-criterion)`. `GateControl.run` records nothing for it; the arm grades it with its registered host check (WP6), and a dry `GateCheck.check` fails it unrecorded. | `host_check` is TS-only and additive (§6). | `test/gate.test.ts` "host_check controls are left to the arm", "a dry check fails host checks closed" |
| W7-1 | authoring hook compile; the hook node catalog | TS accepts and lists the additive `relay.hook.v1` vocabulary that Python refuses ("Hooks accept an event, conditions and hook actions…", "Invalid output port for this action", "Choose the event operation and timing"): the `relay.hookAllow` node with an optional note, a second Verify output (Pass, Fail), and the `tool`, `session-start` (after), `prompt` (before) and `session-idle` (after) operations. | Owner decisions 2 and 5 (2026-10-06), frozen in `RelayHook`. | `authoring.test.ts` "W7-1", and golden `node-types` compared as the Python catalog plus these additions |
| W7-2 | authoring hook compile | A hook carrying a field `relay.hook.v1` does not define (an extra node key or parameter, a non-numeric `typeVersion`) is refused with "The hook holds fields that relay.hook.v1 does not define"; Python exports it. | Installs decode the snapshot strictly, so the export is refused before publish instead of at install. | `authoring.test.ts` "W7-2" |
| W7-3 | authoring workflow compile | A compiled plan that `RelaySprint.Sprint` cannot decode (a retained `self_check` that is not a list of text, a non-boolean `blocking`, …) is refused with "The retained plan holds fields a Relay sprint cannot carry"; Python compiles it. | The compiled sprint is what the arm loads, and the TS arm decodes it strictly. | `authoring.test.ts` "W7-3" |
| W7-4 | lint findings | A WP `id` that is not text is reported in `wp` as Python's `str()` of it (`5` becomes `"5"`); Python copies the raw value. | `Finding.wp` is text; only an undecodable plan has such an ID. | `authoring.test.ts` "W7-4" |
| W8-1 | `document_checksum`; store row bodies (`json.dumps`) | A JS number carries no int/float split: a safe integer is written as a Python int and any other number in Python's float repr. A float that is a safe integer (`240.0`) hashes and stores as `240`; an int beyond 2^53 − 1 as a float (`9007199254740992.0`). Every golden checksum, fixture checksum and fixture row matches. | Documents reach the store as plain JS values (JSON.parse, the HttpApi decode), where `240.0` and `240` are one value. The checksum only has to agree between the TS store and its clients, which compute it the same way. | `store.test.ts` "W8-1: a safe integer hashes as a Python int, any other number as a Python float" |
| W8-2 | `save_scope` duplicate check (`str.casefold()`) | Names compare after lower, upper, lower casing (the dotless ı kept apart, as casefold keeps it). That equals casefold equality under the runtime's Unicode tables, which are Bun's (Unicode 15.1), where CPython 3.14 has 16.0: a case pair added in Unicode 16 (U+A7CB and U+0264) is not a duplicate in TS. | JS has no casefold. Checked over every code point against CPython 3.14: the only differences are the 54 code points whose case mappings Unicode 16 added. | `store.test.ts` "W8-2: case pairs newer than the runtime's Unicode tables are not duplicates" |
| W8-3 | `seed_profiles` | Each seeded profile document carries `meta.relay.profile` (its file name); Python seeds the bare projection. Run admission (`AuthoringStore.runnable`) refuses a profile other than tdd_feature and wp-execute with 409 `profile-tools-missing`, and reads an unmarked `relay-<profile>` ID the same way, so a store Python seeded is covered. | Owner decision R8 (2026-10-06): planning, design, research-v2 and spec-decompose call Relay tool programs that are not ported, so they are imported but refuse to run. | `store.test.ts` "seeds each profile once, as Python projects it, marked with its profile", "only tdd_feature and wp-execute run; the other profiles refuse with profile-tools-missing" |
