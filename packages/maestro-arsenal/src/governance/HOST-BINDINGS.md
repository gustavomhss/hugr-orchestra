## Native integration

- Import `governanceToolDescriptors` from `governance/descriptors.ts` for all five authoritative descriptors. `governanceToolDescriptor` is also exported from `tools/governance.ts`. Descriptor module contains pure data and pure schema dependencies; catalog loading does not load filesystem/process handlers. Register the canonical `governance` name as required, not optional/absent. Legacy `root`, raw shell Relay checklists and provenance-free ledger schemas are incompatible with this port.
- `ArsenalContext`/`ToolDef` come from the shared A-owned contract. Authorization paths/commands are readonly arrays; D never defines a divergent context shape. `GovernanceContext` is only a shared type reference. Host placement supplies directory/stateDirectory/projectID. State directory must already exist, outside source repository; each project gets a canonical ID subtree. Assembled workspace compiles against the actual shared contract, without temporary declarations or path overrides.
- Host must acquire immutable check/usage/action records from real Session events or executed named checks. Schema provenance establishes identity and validates shape; it does **not** authenticate caller prose. E/F must reject model-supplied observations and bind actual records at invocation. Host owns completeness of each observation window.
- F imports `readPreferences(context)` / `readPreferencesSnapshot(context)` from `tools/profile.ts`. Missing preferences return null; reads never create/default-write state. Snapshot includes exact managed path and SHA-256 of source bytes. F supplies E's same `stateDirectory`; D does not derive/import the Core data root. Actual path is `<stateDirectory>/<projectID>/profile/preferences.json`.
- `relay-arm` persists normalized completion contracts. F imports `readCompletionContract` and `runCompletion` from `governance/completion.ts`. Call `runCompletion(context, token, actualSessionID, compiledCheckRegistry, expectedGitRevision?)` at the real completion boundary. Registry defaults empty and fails named unbound checks; callbacks execute in gate/check order, stop on red/skip/acquisition error, and return actual immutable records. Session/name/revision mismatch fails. No callback functions can enter through model JSON. Pure/public `completion-check` results are explicitly non-authoritative; only the compiled host callback path can certify execution. No Claude hook is installed or presumed.
- Host enforces tool-before/tool-after controls for custom/MCP/native tools and V2 Location placement. Policy/sandbox outputs are proposals, not permissions or proof of OS confinement. Instruction/config protection, secret-output handling and output/context bounds remain native F responsibilities.
- Static operation effects conservatively list possible effects. Each real I/O boundary additionally awaits exact path/command authorization. Pure scheduling and observation computations execute no commands.

## Evidence semantics

- Acceptance uses complete, nonempty actual result captures. `red-green` proves new behavior; explicit `preserve-source-green` proves preserved source behavior. Missing baseline/final, skips, acquisition errors, contradictory exits, duplicate names and loss of previously green checks cannot pass.
- Usage preserves exact provider/model identity and all four token buckets. Pricing is caller-supplied USD/million tokens with source/asOf. Unknown pricing or missing usage produces named HOLD, never zero spend. `cost-estimate` returns its pure estimate report with `isError: true` for `OVER_ESTIMATE` or `HOLD` (unknown pricing or missing budget); only `WITHIN_ESTIMATE` succeeds. The existing native wrapper translates `isError` into tool failure. This estimate-check boundary adapts source `cost-governor.py`, not live provider spending enforcement. Comparison uses raw finite USD values: equality succeeds, any excess fails. This is explicitly stricter than the source's four-decimal rounding; $3.000003 exceeds $3 even though the source rounds it to $3.0000. Handler/schema cases and refusal mutation: `test/cost-estimate.governance.test.ts`.
- Usage `input` is uncached input; `cacheRead`/`cacheWrite` are separate buckets. Host must use the actual provider's counter semantics rather than double-counting cached input. Prices use the same four buckets, exact provider/model key, USD per million tokens, actual pricing source and effective date/time or contracted rate-version identity. No default prices are supplied.
- E may use `validateHostSnapshot(context, actualSessionID, capturedFacts)` to validate and freeze actual captures. Provenance `eventID` is a bounded opaque actual identity, not a filename. Git/source revisions accept actual 40- or 64-hex IDs. `revisionKind: "event"` labels a real event-version identity; it is never compared as Git HEAD. When historical source revision is unavailable, omit revision and supply `revisionUnavailable: "not-captured" | "not-applicable"`. Normal audit/usage/status still return facts plus named `SOURCE_REVISION_UNAVAILABLE` diagnostics. No current HEAD is attached retroactively. Preflight/release checks requiring Git identity fail explicitly when it is absent or not Git provenance.
- Audit digests only supplied bounded observations (`persisted:false`, `integrityClaim:"digest-of-supplied-observations-only"`). Native audit/status separately attach host-only `integrity` from `EventV2.Service.verifySealWindow`: the global durable owner seals existing Event rows inside its transaction before publication. `ArsenalObservations.read` resolves actual SessionStore project/Location before and after acquisition, binds aggregate to that Session, freezes trusted optional `auditWindow`, and defaults to its actual high-water's latest interval of at most 2,048 rows. Verification reads all event types in one consistent window; usage completeness stays independent.
- Integrity scope is `event-window-only`, with `observationsVerified:false`: separately folded actions, predecessor bodies and prefix/tail outside the interval are not certified. Empty/legacy/compacted history is UNKNOWN; edited or missing sealed rows are BROKEN where compaction does not explain gaps. Neither means PASS or full-history coverage. Typed acquisition errors attach `UNKNOWN/HOLD` diagnostics without fabricating a window. Model integrity/project/Session/aggregate/window overrides are denied; supplied observation source prose cannot replace host records. No second log, original-remote attestation, external notary or coherent database/chain-replacement protection is claimed. Actual native tests: `packages/opencode/test/maestro/arsenal-integrity.test.ts` and `arsenal-integrity-report.test.ts`; placement-removal and model-integrity-substitution mutations fail these tests.
- Metrics read explicit bounded paths and state exact coverage. Metrics reports do not certify correctness. Scoped CI receives actual Git changes plus operator-bound groups/universal checks; unmatched/config/harness paths select FULL. Release checks require actual full-suite names and exact HEAD evidence.
- Plan paths remain `changelog-propose`, `release-propose`, `ruleset-propose`. Explicit `changelog-write`, `release-run`, `ruleset-run` consume operator request data (`requestID`, exact action, expected actual HEAD) and await actual native write/process authority. Request fields/user approval booleans cannot grant authority. `changelog-write` performs atomic scoped insertion with source digest/rechecks and refuses reopening an existing version. `release-run` acquires the actual committed repository release recipe, binds its SHA-256 source digest, checks clean tree/branch/tag freshness, invokes it only after authorization, then verifies a real annotated tag targeting expected HEAD. The recipe owns repo-specific full verification/publication policy; external publication remains unknown without its actual receipts. `ruleset-run` invokes real `gh api` only after authorization and validates actual API scope/rules/ID. No automatic cloud calls, retries, tag pushing or global rollback are added.

## State and recovery

- JSON state capped at 512 KiB; wave ledger capped at 256 retained records. Overflow rejects. Explicit compaction returns removed count, digest and totals and records cumulative loss; host persists compaction receipt if historical retention is needed. Read never presents compacted history as complete.
- Same-process state writers serialize with bounded queue; exclusive lock prevents cross-process lost updates. Busy/stale lock returns named `STATE_LOCK_FAILED`; library never steals locks. Writes use exclusive temp file, fsync and rename. Private host state root must not be writable by untrusted concurrent actors; lexical/physical checks reject existing symlinks.
- Recovery begins only for explicit clean committed regular files. Prepare captures committed baseline, current HEAD, tracked/index dirt digest and owned bytes/existence. Restore acquires native edit/process authority, reads exact committed blob bytes and rechecks before writes. Text and binary files restore byte-for-byte within acquisition bounds; symlinks fail. Deleted owned files can be re-created from their exact committed blobs. HEAD and index stay untouched. No reset/clean, wave-wide atomicity or reversal of external side effects is claimed.
- Recovery uses optimistic checks; host must serialize native edits during restoration for exclusive ownership. A mid-operation failure may leave a prefix restored, so re-acquire evidence before retry. Replay recommends only checks lacking actual green records; it never dispatches workers.

## Verification boundary

Focused Bun tests use actual files, SHA-1/SHA-256 Git repositories, compiled check callbacks, real local annotated tags, permission denial and failure captures. Remote ruleset tests deny the real invocation before spawn; no fake `gh` success or live external mutation is reported. Pure API-receipt validation is separate from live API verification. Host end-to-end execution/interception and actual GitHub API results belong to E/F integration tests. Policy/sandbox proposals still require F/E's real native binding and do not claim kernel enforcement.
