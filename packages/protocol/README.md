# @orchestra/protocol

The public Effect `HttpApi` contract for Orchestra's instance routes under `/api`: route schemas, errors, middleware requirements and API composition. It declares routes; it does not implement them.

Dependencies run Schema -> Core and Protocol -> Server. Protocol depends on `@orchestra/schema` and `effect`.

## Who uses it

`packages/server` builds the API and implements the handlers. `packages/client` generates typed client code from it. `packages/sdk-next`, `packages/plugin` and `packages/app-shell` import types from it.

## Entry points

There is no bare `@orchestra/protocol` export; every subpath is an explicit key in `package.json`.

```ts
import { makeApi, makeDefaultApi } from "@orchestra/protocol/api"
import { InvalidRequestError } from "@orchestra/protocol/errors"
import { MessageGroup } from "@orchestra/protocol/groups/message"
```

- `src/api.ts` composes the public API from the endpoint groups in `src/groups/` (one file per group: session, message, model, provider, permission, fs, pty, relay, actions and others). `makeApi` takes event definitions; `makeDefaultApi` uses the default event group.
- Most groups require Location middleware; Session-scoped groups use Session Location middleware. Authorization and schema-error middleware apply to the whole API. Server supplies the runtime layers for all of them.

## Changing the contract

After changing the public Protocol or Server `HttpApi`, regenerate client outputs from `packages/client` with `bun run generate`. Do not hand-edit `packages/client/src/generated` or `packages/client/src/generated-effect`.

## Commands

From this directory: `bun typecheck`. Tests run on CI from the repository root: `bun run test:ci protocol`.

## Limits

Client runtime code may depend on Schema and Protocol, never Core or Server.
