# sqlc generated queries

## Applicability

Calling Go code that sqlc `1.31.1` generated for PostgreSQL with `sql_package: pgx/v5`, running on pgx `v5.8.0`. This card covers using the output: `Queries`, `WithTx`, parameter and row structs, and `pgtype` nullable fields. Read [pgx](pgx.md) for handles, transactions and errors.

## Non-trigger

- Output generated for `database/sql` or `pgx/v4`: the `DBTX` interface and the method signatures differ. Check `sql_package` in `sqlc.yaml` or `sqlc.json` first.
- Editing generated files (`db.go`, `models.go`, `*.sql.go`). They start with `// Code generated by sqlc. DO NOT EDIT.`; change the SQL and regenerate.
- Changing `overrides`, `emit_*` options or the output package. That configuration is supplied by the packet.

## Inputs

- The sqlc config, the query files and the generated package path.
- The `go_type` overrides in force, and whether `emit_pointers_for_null_types`, `emit_empty_slices` or `emit_interface` is set.
- The packet's generation command, when query files change.

## Steps

1. Construct the queries on a handle: `q := dbgen.New(pool)`. `New` takes the generated `DBTX` interface, which `*pgxpool.Pool`, `*pgx.Conn` and `pgx.Tx` all satisfy.
2. Inside a transaction, bind a copy with `qtx := q.WithTx(tx)` and send every participating query through `qtx`. The original `q` still runs on the pool; one call through it escapes the transaction and still compiles.
3. Read the generated signature before calling. Several parameters arrive as a `<Query>Params` struct; a single parameter is passed directly. `:one` returns one row struct or scalar, `:many` a slice, `:exec` only an error, `:execrows` the affected-row count as `int64`, `:execresult` a `pgconn.CommandTag`.
4. Handle absence. A `:one` query with no row returns `pgx.ErrNoRows`; match it with `errors.Is`. A `:many` query with no rows returns a nil slice unless `emit_empty_slices` is set, so encode an empty JSON array explicitly when the contract needs `[]`.
5. Map nullable columns. Without overrides, a nullable column becomes a `pgtype` value: `pgtype.Text{String, Valid}`, `pgtype.Int4{Int32, Valid}`, `pgtype.Int8{Int64, Valid}`, `pgtype.Timestamptz{Time, Valid}`. `Valid: false` is SQL `NULL`, and the zero struct is `NULL`, not `""` or `0`. With `emit_pointers_for_null_types: true` the field is a pointer instead. `uuid` maps to `pgtype.UUID` unless an override says otherwise.
6. In SQL you author, name parameters with `@name` or `sqlc.arg(name)`; `sqlc.narg(name)` makes one nullable. A PostgreSQL list filter is `= ANY(@ids::bigint[])`, which takes a Go slice.
7. After a query file changes, run the packet's generation command and read the generated diff before calling new signatures.

## Tools and outputs

- Generated and owned by sqlc: `db.go` (`DBTX`, `New`, `WithTx`), `models.go`, one `<file>.sql.go` per query file, and `querier.go` with the `Querier` interface when `emit_interface` is set.
- Handwritten and yours: the SQL text, the repository wrapper, the mapping from row structs to the contract's DTOs, and tests.
- The generated header lists `sqlc v1.31.1` under `versions:`. Any other version there means the project pins another generator: report it and never regenerate with a different version.

## Limits and checks

- Generation and compilation prove only that the SQL fits the schema sqlc read. They prove neither tenant predicates, atomicity nor the deployed schema.
- Never return generated row structs as API responses; map them to the contract's DTO so field names, `NULL` handling and types match it.
- A `Queries` value bound with `WithTx` is dead once its transaction ends; build a new one for the next transaction.
- Checks run the generated methods against the supplied real PostgreSQL, including a `NULL` column case and the no-row case of each `:one` query the change calls.
