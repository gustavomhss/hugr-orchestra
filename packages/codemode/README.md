# @orchestra/codemode

Confined code execution over explicit, schema-described tools. A model writes a small JavaScript program that can call only the tools the host supplies; it can sequence calls, branch, loop and run calls in parallel, with no ambient filesystem, process, network or module access. It interprets a bounded JavaScript subset without `eval`.

## Who uses it

No package in the workspace imports it today (a grep for `@orchestra/codemode` outside this folder finds nothing). It is a self-contained library.

## Entry points

`src/index.ts` exports `CodeMode`, `Tool`, `OpenAPI`, `ToolError` and `toolError`.

```ts
import { CodeMode, Tool } from "@orchestra/codemode"
import { Effect, Schema } from "effect"

const lookupOrder = Tool.make({
  description: "Look up an order by ID",
  input: Schema.Struct({ id: Schema.String }),
  output: Schema.Struct({ id: Schema.String, status: Schema.String }),
  run: ({ id }) => Effect.succeed({ id, status: "open" }),
})

const runtime = CodeMode.make({ tools: { orders: { lookup: lookupOrder } }, limits: { maxToolCalls: 10 } })
const result = yield* runtime.execute(`return await tools.orders.lookup({ id: "order_42" })`)
```

- `CodeMode.execute({ tools, code, limits })` runs once; `CodeMode.make(options)` returns a reusable runtime with `execute(code)`, `catalog()` and `instructions()` (the model-facing syntax and tool guide).
- `Tool.make` takes an Effect Schema (validating) or a JSON Schema (signature only) for `input` and `output`. Input is decoded before `run`; output is decoded and copied to plain data before the program sees it.
- `OpenAPI.fromSpec({ spec, auth })` turns an OpenAPI 3.x document into a tool subtree and a `skipped` list. Auth is resolved host-side and never model-visible; generated tools need an `HttpClient` in the environment. Unsupported features are listed in `src/openapi/TODO.md`.
- `$codemode.search` is always registered. The instructions list tools within a catalog budget (default 2,000 estimated tokens, `discovery.catalogBudget`) and advertise search when the list is partial.

## Results and limits

`runtime.execute` always yields a `CodeMode.Result`: `{ ok, value | error, logs?, truncated?, toolCalls }`. Program, validation, limit and tool failures come back as diagnostics (`ParseError`, `UnsupportedSyntax`, `UnknownTool`, `InvalidToolInput`, `InvalidToolOutput`, `InvalidDataValue`, `ToolCallLimitExceeded`, `TimeoutExceeded`, `ToolFailure`, `ExecutionFailure`); host interruption stays interruption. Unknown host failures are sanitized; fail with `toolError("message")` to return a safe message.

Three optional limits, none set by default (the host decides): `timeoutMs`, `maxToolCalls`, `maxOutputBytes`. Output over `maxOutputBytes` is truncated and marked, never failed.

The supported language is documented in the runtime `instructions()`; [`codemode.md`](./codemode.md) holds the design notes. It excludes `eval`, modules, classes, generators, timers, `new Promise` and `.then` chaining.

## Authority

CodeMode confines programs to the supplied tools; it does not authorize what those tools do. The host owns authentication, authorization, credentials, persistence, approval and logging. Do not expose a broad tool and rely on the prompt to restrict it. Rules for changing the package are in [AGENTS.md](./AGENTS.md).
