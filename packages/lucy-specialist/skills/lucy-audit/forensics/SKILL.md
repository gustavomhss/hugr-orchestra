# Repository forensics

Use the actual revision and available repository history to examine changed-area hotspots, prior reverts, contributor concentration and potential knowledge concentration. State the time window, paths and data source for each observation. A hotspot is a clue for targeted inspection, not proof of a defect. Contributor or truck-factor figures are estimates, not measures of an individual's value or performance; never rate developers.

When authorized evidence includes machine-readable delivery records, compare changes, approvals and outcomes to the stated control. Read source records rather than the author's narrative. Distinguish a missing record, an inaccessible source and a confirmed exception; document incomplete history, retention and unavailable CI data as coverage limitations. Do not contact live systems or use network access unless the host already supplies authorized evidence; no tool capability is granted by this skill.

Escalate a concrete defect only with its rule, location, trigger and labelled evidence. Otherwise return a question or observation, with the facts that would settle it.
