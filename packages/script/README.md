# @orchestra/script

Build, CI and repository tooling library.

## Purpose and ownership

- `src/index.ts` computes the release channel, version and team list (`Script`) for the build scripts in `apps/cli` and `apps/desktop`.
- `src/workspace-paths.ts`, `src/module-catalog.ts` and `src/module-resolver.ts` find the repository root and resolve workspace modules from `script/module-registry.json`.
- `src/omni.ts` and `src/tree-sitter-prebuilds.ts` hold the shared native-binary steps of the CLI and desktop builds. `src/spawn-imports.ts` is the scanner behind `script/check-spawn-imports.ts`.

## Public entry points and consumers

- Export keys `.`, `./module-resolver`, `./module-catalog`, `./workspace-paths`, `./spawn-imports`, `./omni`, `./tree-sitter-prebuilds`.
- Consumers: `apps/cli`, `apps/desktop`, `script/test-ci-package.ts` and `script/check-spawn-imports.ts`.
- The root tools `script/check-module-boundaries.ts`, `script/explicit-exports.ts`, `script/compat-facade.ts` and `script/module-readme.ts` share `script/module-architecture.ts`, not this package.
- Nix resolves `@orchestra/script/*` through `nix/scripts/workspace-paths.json`.

## Dependencies and boundaries

- Layer `tooling`.
- Depends on `@orchestra/schema`, `semver` and `typescript`.

## Assets, schemas and generated files

- Reads `script/module-registry.json` (`src/workspace-paths.ts`) and `.github/TEAM_MEMBERS` (`src/index.ts`). The architecture registry and the boundary ledger are read by the root tools in `script/`.

## Persistence, identity and lifetime

- None. Importing `src/index.ts` runs it: it checks the Bun version and prints the resolved `Script` values.

## Commands

- `bun typecheck` from `packages/script`.
- `bun run test:ci script <files>`
- `bun run check:boundaries`

## Contracts and verification limits

- `packages/script/src/tree-sitter-prebuilds.ts` is listed in `script/spawn-allowlist.json`.
- Tests exercise the resolvers on fixtures; they do not run a real release build.
