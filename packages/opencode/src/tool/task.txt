Launch a new agent to handle complex, multistep tasks autonomously.

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When not to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for a specific class definition like "class Foo", use the Grep tool instead, to find the match more quickly
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead of the Task tool, to find the match more quickly
- If no available agent is a good fit for the task, use other tools directly


Usage notes:
1. Launch several agents in one message only when their work is independent.
2. Pick the subagent's model per call with the `model` parameter as 'providerID/modelID' (e.g. 'openrouter/deepseek/deepseek-chat', 'groq/llama-3.3-70b-versatile', 'anthropic/claude-opus-4-6'). Without it, the subagent uses its configured model, else the parent session model.
3. The provider part selects credentials: OAuth subscriptions (Claude Max, ChatGPT) and API keys resolve per providerID when the subagent runs. For a second key on the same backend, define a provider alias in opencode.json with its own options.apiKey (e.g. provider "groq-work" with baseURL https://api.groq.com/openai/v1) and call model 'groq-work/llama-3.3-70b-versatile'.
4. Sessions can scope which models subagents may use with permission rules like { permission: "task", pattern: "openrouter/*", action: "allow" } plus { permission: "task", pattern: "*/*", action: "deny" }. When such rules exist, the resolved model is added to the permission prompt; a denied model fails with the session's allowed list so you can retry with a listed one. Without model-scoped rules nothing changes.
5. Once you have delegated work to an agent, do not duplicate that work yourself. Continue with non-overlapping tasks, or wait for the result. For background tasks, you will be notified automatically when the result is ready.
6. A new agent knows only your prompt and the repository's instruction files, so the prompt is its whole brief: the outcome and why, the constraints, the exact paths, what done looks like and the check to run, whether to write code or only research, and what to send back.
7. Agents share your working tree, so give each set of files a single writer.
8. The agent ends with one message, which the user does not see; tell the user what matters in it. That message is a report to check: verify the claims you rely on, such as the diff or the test output, before you build on them or relay them.
9. Each call starts a fresh agent. To continue an earlier one with its context, pass the exact task_id it returned; an unknown id fails.
10. If an agent's description says to use it proactively, use it without waiting for the user to ask.
