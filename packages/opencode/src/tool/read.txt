Read a file, or list a directory.

- Output is `<path>`, `<type>`, then `<content>` with each line as `N: text`. The `N: ` prefix is not part of the file; never copy it into an edit or a patch.
- A read returns at most 2000 lines and 50 KB, and cuts lines longer than 2000 characters. The content ends with `(End of file…)` when nothing remains, or with `(PARTIAL view… Use offset=N to continue.)` when more does.
- To continue, pass that offset with a `limit` no larger than the page you got: an explicit `offset` or `limit` whose slice exceeds 50 KB fails instead of truncating.
- `offset` is the first line, counted from 1; 0 is invalid. A negative offset returns the last lines, such as `-200` for the end of a log.
- Prefer one large window to many small slices. Each call reads one path; read several files with parallel calls.
- A directory lists one level, including hidden and ignored entries; subdirectories end in `/`. `offset` and `limit` page the entries.
- JPEG, PNG, GIF, WebP and PDF files up to 20 MB come back whole as attachments. Archives, Office files and other binaries are refused.
- The first time you read a file under a directory with its own AGENTS.md, CLAUDE.md or CONTEXT.md, its rules follow `</content>` in a `<system-reminder>`; follow them. Shell reads, searches and directory listings never load these rules.
- Nothing is cached, and edits and writes do not check what you have read.
