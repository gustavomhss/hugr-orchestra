# @orchestra/session-ui

Solid components that render Sessions: messages, parts, diffs and review.

## Purpose and ownership

- Components for transcript rendering (`packages/session-ui/src/components`: message parts, markdown, files, diffs, session review, line comments), their shared context (`packages/session-ui/src/context`) and the transcript model (`packages/session-ui/src/transcript-model.ts`).
- The v2 components, including the prompt input, live in `packages/session-ui/src/v2/components`.
- Primitives such as buttons and dialogs come from `@orchestra/ui`.

## Public entry points and consumers

- Explicit `exports` keys (for example `./message-part`, `./session-review`, `./transcript-model`, `./v2/prompt-input`) plus the asset wildcard `./v2/*.css`.
- Consumers: `packages/app-shell` (the bulk of the imports) and `apps/storybook`.
- The CSS entry `@orchestra/session-ui/styles` is imported by `packages/app-shell/src/index.css`.

## Dependencies and boundaries

- Layer `ui`: may use the ui, schema, client and contract layers, and only the `browserSafe` core helpers.
- The legacy SDK and the vendored upstream client tarball are not reached from this package.

## Assets, schemas and generated files

- Styles in `packages/session-ui/src/styles` and `packages/session-ui/src/v2/components`. Nothing is generated.

## Persistence, identity and lifetime

- UI state only; nothing is written to disk.

## Commands

- `bun typecheck` from `packages/session-ui`.
- `bun run test:ci session-ui <files>`
- Stories for these components run in `apps/storybook`.

## Contracts and verification limits

- Keep `packages/session-ui/AGENTS.md`: it requires every visible string to go through an i18n key.
- Tests cover pure logic (markdown, tool metrics, patches, comments); rendering is checked in Storybook, not by tests.
