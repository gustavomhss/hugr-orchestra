# Codex reviews of ADR-0001/0002 (S1) and ADR-0003 (S2)

Independent, read-only reviews by Codex CLI of the spike ADRs and the spike code that produced their evidence
(2026-10-02). Both returned `reject` as a product baseline; the lead's response is ADR-0005 (supervisor).

## ADR-0001 + ADR-0002 (process model, host exit)

**Verdict:** `reject` — Neither ADR is safe to adopt unchanged as a product baseline. Windows jobs and avoiding native signal chaining are well supported. Unix supervision needs checked initialization, atomic spawn ownership, and identity safety that survives foreign reapers and host death; an exec'd supervisor is the safer foundation. Windows console attachment must leave the embedding host untouched. Review covered source and platform documentation; quoted CI logs could not be independently retrieved, and no files were modified.

| Decision | Supported | Evidence |
|---|---|---|
| ADR-0001 §1: suspended Windows spawn, job assignment, then NtResumeProcess | partly | Q1 has useful controls: late assignment exposes escaped grandchildren, and simulated preemption defeats naive assignment. Suspension therefore has strong support. However, win.rs:26 statically imports NtResumeProcess; win.rs:157 ignores its return status. Runtime resolution and fallback are proposed, not tested. JOB_LIST achieves comparable measured performance through a documented interface. |
| ADR-0001 §2: Windows graceful stop through CTRL_BREAK, including temporary host console attachment | partly | Q3 demonstrates delivery from sequential Rust fixtures and honestly exposes batch continuation. It does not establish safety inside an embedded runtime. AttachConsole and FreeConsole reset the calling process's control-handler table, contradicting ADR-0002's unchanged-host guarantee. [Microsoft documentation](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler) |
| ADR-0001 §3: direct posix_spawn with SETSID on Unix | partly | SETSID is a sound choice on supported systems, but Q4's containment and terminal tests use pre_exec, not the proposed spawn implementation. The raw path in unix.rs:717 benchmarks only an absolute-path noop, ignores attribute-setting errors, and never verifies session identity. PATH, cwd, file actions, signal resets, and PTY setup remain unproved. |
| ADR-0001 §4: Unix process-group signaling, without host subreaping or process scans | yes | Q4 tests group membership, killing grandchildren after root exit, and a surviving setsid escapee. The subreaper experiment supports avoiding a process-wide reaping obligation. This supports signaling group members, not unconditional tree containment or a deadline for termination. |
| ADR-0001 §5: retain an unreaped root to prevent signaling recycled process-group IDs | partly | Q7 supports the argument when the library exclusively controls reaping. Its own SIGCHLD=SIG_IGN and foreign-waitpid experiments invalidate that premise in the advertised hostile hosts. Event notification does not preserve a zombie or reserve the numeric PGID after another component reaps it. |
| ADR-0001 §6: pidfd/kqueue exit reactors, with blocking-wait fallback | partly | Latency and concurrency experiments support event-based observation. They do not prove registration safety against an immediately exiting, automatically reaped child, and some registration failures are counted as successful observations. P_PIDFD waiting requires Linux 5.4, whereas pidfd_open arrived in 5.3. [Linux wait documentation](https://man7.org/linux/man-pages/man2/waitpid.2.html) |
| ADR-0002 §1: Windows KILL_ON_JOB_CLOSE for host-death cleanup | yes | Q5 includes no-job controls, checks both generations, and isolates host-directed CTRL_BREAK from the child's group. The last-handle-close mechanism is documented. This is a sound product foundation provided job creation succeeds, breakaway remains disabled, and no other process retains a job handle. [Microsoft job documentation](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) |
| ADR-0002 §2: one forked-without-exec Unix watchdog using pidfd/kqueue | partly | Q5/Q6 demonstrate cleanup of already registered, cooperative fixtures on recent Linux/macOS and minimal Node/CPython hosts. They support a separate supervisor and process-based death detection over EOF alone. They do not establish post-fork safety, atomic registration, identity safety after host death, or robust operation under resource failures. |
| ADR-0002 §3: bindings install no cleanup signal handlers or exit hooks | yes | Q6 has meaningful controls demonstrating handler replacement, broken chaining, caught KeyboardInterrupt, and exit-hook limitations. Avoiding handler chaining is well supported. The stronger claim that host behavior remains unchanged is nevertheless contradicted by the Windows console-attachment decision. |
| ADR-0002 §4: host-death grace equals the largest live-tree grace, capped at five seconds | no | watchdog.rs uses a fixed grace supplied at startup; all exercised watchdogs use 200 ms. Its four-byte messages carry only signed PGIDs, not grace values. There is no test of different tree graces, removal of the maximum, the cap, or a descendant surviving SIGTERM until forced escalation. |

| Severity | Topic | Problem | Proposal |
|---|---|---|---|
| must_fix | Post-fork safety requires a complete argument; prefer an exec'd helper | ADR-0002:166 treats 'only async-signal-safe calls' as established. After fork from a multithreaded host, locks and allocator state can belong to vanished threads; every reachable operation must remain safe until exec, including inherited signal handlers. The fixed arrays avoid obvious heap allocation, but watchdog.rs does not reset inherited handlers/masks and provides no platform audit of Darwin kqueue/kevent or the Rust/libc call paths. nanosleep lacks a portable POSIX async-safety guarantee, although glibc documents its implementation as AS-safe. Successful minimal-host runs cannot prove absence of rare deadlocks. Fork without exec is not categorically forbidden, but this implementation has not established its required conditions. [POSIX fork requirements](https://pubs.opengroup.org/onlinepubs/009695399/functions/fork.html), [signal-safety list](https://man7.org/linux/man-pages/man7/signal-safety.7.html), [glibc nanosleep safety](https://sourceware.org/glibc/manual/2.42/html_node/Sleeping.html) | Ship a small versioned helper and start it through posix_spawn where supported, with explicit signal defaults/mask and descriptor actions. Exec gives the helper fresh runtime and allocator state. If retaining no-exec operation, require a platform-specific audit of its complete call graph, signal sanitization, startup races, and error paths; allocation/lock contention tests supplement that audit. |
| must_fix | Hostile reapers defeat the advertised Unix identity guarantee | ADR-0001:259 promises zombie pinning while ADR-0001:315 supports SIGCHLD=SIG_IGN and foreign waitpid(-1). Explicit SIG_IGN, SA_NOCLDWAIT, or a competing reaper can remove the zombie regardless of WNOWAIT. A pidfd identifies its original process but does not preserve a zombie or make a later numeric killpg safe; kqueue is also an observer. A SIGCHLD handler that waits only for its own children is compatible, whereas a catch-all reaper is not. [pidfd_open prerequisites](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) | Either require exclusive child-reaping ownership and explicitly narrow supported-host guarantees, or make an independent helper the actual parent of managed roots, with its own SIGCHLD policy. Do not continue numeric group signaling after ownership is lost. Add tests combining foreign reaping, retained Child handles, group disappearance, and PID/PGID reuse. |
| must_fix | Zombie pinning ends at host death | The watchdog is the root's sibling, not its parent. When the host dies, retained zombies can be reparented and reaped. After watchdog SIGTERM, the group can disappear and its number become reusable before the delayed SIGKILL at watchdog.rs:142. An unrelated group could then receive SIGKILL. Untracking before normal reaping does not protect this host-death path. | Have the surviving supervisor own and retain root zombies through its final group signal, or use a verified stable containment identity. Exercise host death after root exit and group disappearance during grace, with an unrelated-process sentinel. Exec alone does not solve this ownership problem. |
| must_fix | Spawn-to-watchdog registration gap | ADR-0002:205 requires tracking after the group exists. Abrupt host death between posix_spawn and the track write leaves a running tree unknown to the watchdog. unix.rs:466 spawns before tracking, and all Q5/Q6 death tests wait until registration has completed. An acknowledgment after tracking alone cannot close the earlier gap. | Use a supervisor-owned spawn transaction, or another mechanism that prevents target execution before durable supervision is established. Inject host death at each startup boundary. Until then, describe cleanup as applying only to successfully registered trees. |
| must_fix | Watchdog liveness is insufficient; IPC and initialization are unchecked | watchdog.rs:26 does not handle fork failure; death-handle creation and registration errors are ignored. Track writes are blocking, unchecked writes despite the non-blocking contract. Full pipes can stall the host, failed writes lose supervision, and a broken pipe can invoke SIGPIPE behavior. The 256-entry table silently drops additional groups. Descriptor cleanup closes only descriptors below 1024, and mapping /dev/null onto standard descriptors can overwrite the pipe if it occupied descriptor 0, 1, or 2. A living but stopped, wedged, or improperly armed watchdog provides no cleanup. | Specify a checked startup handshake, explicit capacity/backpressure policy, protected IPC descriptors, complete descriptor cleanup, and failure behavior for every syscall. Define T2 in terms of a successfully armed, responsive supervisor. Test exhausted descriptors, failed process creation, denied pidfd/kqueue operations, full IPC, dead/stopped helpers, and more than 256 trees. |
| must_fix | Console attachment mutates the embedding Windows host | ADR-0001:249 proposes a process-wide library lock around AttachConsole/send/FreeConsole. That lock cannot coordinate Node/libuv, other addons, or application calls. Attachment and detachment reset host control handlers; console-associated standard-handle state can also change. Q3 runs sequential Rust hosts and does not check handler preservation or concurrent host activity. [Microsoft control-handler documentation](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler) | Perform console attachment in a separate signaling helper. Otherwise report graceful signaling unavailable for console-less embedding hosts and retain job termination as the forced path. Validate existing handlers, standard handles, simultaneous stop requests, and host console changes. |
| must_fix | Windows resume failures and documented production alternative | The spike supports suspended-before-assignment containment, but win.rs:158 ignores NTSTATUS and resume_toolhelp ignores ResumeThread failure. The ADR's dynamic lookup and automatic fallback are absent. An unchecked resume failure can return a permanently suspended child. The evidence gives no performance reason to prefer undocumented NtResumeProcess over JOB_LIST. JOB_LIST requires Windows 10/Server 2016, unlike the current Windows 8 minimum. [JOB_LIST requirements](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) | Prefer CreateProcessW plus JOB_LIST on supported Windows versions, porting std's quoting/resolution/environment code with upstream tracking and differential security tests. If Windows 8 support is required, retain the primary thread handle and use documented suspension/assignment/ResumeThread. Any NtResumeProcess option must check status, exercise lookup/fallback failures, and terminate/wait/close on failure. |
| must_fix | Unix platform minimums and fallback behavior | The SETSID minimum is glibc 2.26, macOS 10.15, and musl 1.1.17. Older macOS may silently ignore the flag, so a successful spawn is not a sufficient capability test. The promised cwd functionality normally needs glibc 2.29's spawn chdir actions, exceeding the ADR's glibc minimum. Linux 5.3 supports pidfd_open but not P_PIDFD waiting until 5.4. Kernel versions also do not establish availability under seccomp. [glibc SETSID addition](https://sourceware.org/pipermail/glibc-cvs/2017q2/061954.html), [libuv macOS detection](https://github.com/libuv/libuv/blob/v1.x/src/unix/process.c), [musl release announcement](https://www.openwall.com/lists/musl/2017/10/19/1), [glibc cwd support](https://sourceware.org/ml/libc-alpha/2019-01/msg00723.html), [P_PIDFD minimum](https://man7.org/linux/man-pages/man2/waitpid.2.html) | Publish a complete capability matrix and test actual session creation, cwd, signals, and descriptor actions at supported minimums, including musl. Reject unsupported containment explicitly or use a checked exec-helper/audited fork-exec fallback. Do not silently substitute setpgid or drop SETSID. Distinguish Linux 5.3 observation from 5.4 status retrieval and capability failures from version checks. |
| must_fix | Printed success counts are not acceptance gates | Q1, Q4, Q5, and much of Q7 print failed outcomes without failing the executable. The workflow merely collects RESULT lines; nightly steps additionally allow failure. Thus 'all green' does not establish the quoted architectural outcomes. Q1's late-assignment/preemption controls and Q5's no-mechanism controls are valuable, but Q7's ESRCH row does not exercise ID reuse, and no control validates escalation against a SIGTERM-resistant tree. | Assert each expected outcome and its counterexample, including intentionally failing controls, and make discrepancies fail CI. Add registration-race, forced-escalation, and identity-reuse scenarios. Preserve raw results with source SHA and platform versions; characterize 100/100 as observed trials rather than a proof of correctness. |
| must_fix | Several observation errors can be reported as success | unix.rs:922 counts every event-registration error as an observed exit. exit_watch_wait accepts any returned event without validating NOTE_EXIT, EV_ERROR, or poll event flags. The raw spawn benchmark ignores posix_spawnattr_setflags's result and never checks SID/PGID. On macOS, is_zombie at unix.rs:63 treats any proc_pidinfo failure plus successful kill(pid,0) as a zombie, potentially classifying a live but unobservable process as dead. | Separate verified exit, unavailable status, registration failure, and unknown liveness. Validate event identity/flags and all setup return values. Add delayed-live controls and injected observation failures; use a reliable secondary liveness oracle instead of equating inspection failure with death. |
| should_fix | Grace policy has no supporting experiment or protocol | ADR-0002:178 introduces max-live-tree grace and a five-second cap, while the spike stores one startup grace and transmits no per-tree grace. Its fixtures terminate on SIGTERM, so reported sub-millisecond cleanup does not exercise the delayed forced phase. nanosleep interruption is also ignored. | Identify this as an unvalidated policy choice, define how grace values reach the supervisor, and test mixed graces, untracking the maximum, capping, interrupted waits, and descendants that ignore SIGTERM. Use monotonic deadlines for escalation. |
| must_fix | GUARANTEES exceed their mechanisms | T1 correctly distinguishes kernel enforcement from T2, and Unix escape exclusions are useful. However, T2 currently requires more than a living watchdog: successful registration, responsiveness, valid group identity, and permission to signal all relevant members. Unix graceful delivery is best effort too. Group membership alone does not overcome changed credentials. Forced termination should not imply immediate resource reclamation or a strict exit deadline. Windows process groups also are not console isolation: children can re-enable Ctrl-C, and CTRL_BREAK reaches only group members sharing the sender's console. [Windows console semantics](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent), [handler behavior](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler), [asynchronous termination](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess) | Separate containment scope, graceful delivery, forced-termination request, exit observation, and bounded completion. State each tier's prerequisites and failure/degradation behavior. Remove unconditional host-behavior and terminal-signal claims until the console design and supervisor ownership are fixed. |
| should_fix | Normal PTY job control exceeds one process group | ADR-0001:253 includes PTY children, but interactive shells normally create additional process groups for foreground/background jobs. Those jobs escape root killpg without malicious daemonization. The Q4 terminal test checks inherited-terminal reads, not an interactive shell running a pipeline or background job under the proposed PTY setup. | Exercise shell job control and scope/host cleanup of foreground and background jobs. Make the practical PTY limitation explicit or provide a stronger containment tier. Specify how the direct spawn path establishes the controlling terminal; TIOCSCTTY is not a standard spawn file action. |
| should_fix | Zombie and job-handle ownership need a product lifecycle contract | ADR-0001:327 acknowledges that retained Child handles retain zombie roots indefinitely. This consumes process-table resources and conflicts with hostile-host support. ADR-0002 ties job lifetime to Child lifetime while PLAN.md:155 forbids GC from killing live processes; binding finalization therefore cannot simply release the last job handle. | Define who owns containment and supervision independently of language-wrapper reachability, when signaling becomes permanently unavailable, and how explicit disposal, GC, completed-but-retained handles, and leaks affect resources. Bound zombie retention to a documented cleanup lifecycle and validate repeated completed commands. |
| should_fix | Benchmark and compatibility conclusions are broader than the experiment | Q8 compares a raw Unix spawn with empty environment, inherited stdio, and no file actions against std's inherited environment and null/piped stdio. It omits supervision, registration, reactors, and the product's full setup. The Windows variants also differ in setup. Q2 covers several outer-job flags but not documented nested-job restrictions such as UI limits. Bun/Deno and actual napi-rs/PyO3 integration remain untested. | Keep Q8 as a mechanism microbenchmark, not a demonstrated product K4 result. Compare equivalent argv/env/cwd/stdio and full lifecycle costs with interleaved measurements. Test nested-job failure cleanup and the intended embedding runtimes before extending product guarantees. [Nested-job restrictions](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs) |

## ADR-0003 (PTY)

**Verdict:** `reject` — The spike supports atomic CLOEXEC opening, basic ConPTY pipe ownership, explicit standard handles, resizing and JOB_LIST containment. The ADR is unsafe to freeze because deadline enforcement, host-global Ctrl+C changes, Unix containment and output guarantees exceed the evidence. Source and read-only checker counterexamples were inspected; hosted run logs could not be independently retrieved, and the full spike was not rerun.

| Decision | Supported | Evidence |
|---|---|---|
| Build an owned PTY layer instead of using portable-pty 0.9.0. | yes | The cached 0.9.0 source confirms hard-coded cursor inheritance, a single PSEUDOCONSOLE attribute without JOB_LIST, and Unix close_random_fds() inside pre_exec. The DSR reply and missing-interpreter comparisons are meaningful controls. This supports rejecting that release for this contract; it does not establish production readiness of the replacement. |
| Unix: open both PTY ends atomically with O_CLOEXEC, establish a controlling session, and drop parent slave copies. | partly | The openpty and openpty-plus-fcntl controls demonstrate the inheritance race; the size, foreground-group and EOF probes support setsid/TIOCSCTTY and slave ownership. However, own_unix.rs uses thread-unsafe ptsname(), retains unrelated inherited descriptors, and proves only the fork/pre_exec spawning path. |
| Windows: flags=0, close PTY-side pipe ends, use explicit null standard handles, and disable ordinary handle inheritance. | yes | The DSR, retained-pipe-end and Unset/Invalid/Null comparisons directly support these choices on 20348 and 26100. [Microsoft's walkthrough](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session) supports separate communication servicing and releasing redundant pipe handles, although its documented release point is after CreateProcess. |
| EOF: close ConPTY at root exit, drain concurrently, and kill the tree at graceMs if EOF has not arrived. | partly | The basic EOF sequence has useful controls and narrow burst evidence. The deadline sequence is untested: main.rs:399-408 kills before ClosePseudoConsole in stubborn-kill. The synchronous close in own_win.rs:205-212 can prevent the deadline from being enforced on older Windows. [Microsoft documents the blocking behavior](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole). |
| Windows tree containment through PSEUDOCONSOLE and JOB_LIST in the same CreateProcess call. | yes | The probes inspect root and grandchild membership and wait for grandchild termination. Atomic creation removes the post-assignment race by construction. The ADR correctly admits that its racy control never demonstrated an escape. Host-crash cleanup and Job setup failures remain unproved. |
| Unix tree kill through process-group kill plus session sweep. | partly | The interactive-shell experiment demonstrates that killpg alone misses background jobs and that a sweep removes the observed survivors. A session snapshot is not process-tree containment: setsid escapes, concurrent forks and PID reuse remain. The generic UPty::kill_tree implementation still performs only killpg. |
| Clear the inherited ignore-Ctrl+C flag in the embedding host. | no | The Windows 0/20 versus 20/20 comparisons establish effectiveness for the helper, not safety for Node/Bun/Deno or Python. [SetConsoleCtrlHandler documentation](https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler) confirms that NULL/FALSE changes the calling process's inheritable behavior. Neither host behavior preservation nor concurrent spawning was tested. |
| write("\x03") interrupts the foreground program. | partly | The helper receives SIGINT/CTRL_C_EVENT under the tested terminal modes and Windows flag configuration. Applications can disable ISIG or ENABLE_PROCESSED_INPUT, change VINTR, or ignore the signal. The unconditional guarantee exceeds normal terminal semantics. |
| Initial dimensions and subsequent resizing reach the child. | yes | The helper queries native dimensions and each resize requests a distinct value, making stale output insufficient to pass. This supports the tested dimensions and configurations, without a latency guarantee or proof of rendering correctness during resize. |
| Use the VT normalizer as the normative cross-platform output comparator; never compare bytes. | no | stream.rs discards meaningful controls and whitespace and does not implement terminal screen semantics. Read-only counterexamples confirmed identical normalized results for missing final newlines, removed trailing spaces, removed blank lines, and A\rB versus AB. main.rs:155 additionally accepts reordered and duplicated burst lines. |
| Support Windows 1809 onward, declare a per-session leak below 26100, and defer bundled ConPTY. | partly | 1809 is an API availability floor. Only 20348 and 26100 were exercised. The reported handle growth supports a problem on 20348.5622, without identifying its handle type or proving all earlier builds leak. No bundled backend was tested, so it is a candidate remedy rather than an established fix. |

| must_fix | ConPTY close blocks enforcement of graceMs | ADR Q2's sketch calls ClosePseudoConsole and joins before its timeout branch. own_win.rs implements synchronous close, including in Drop. Before 26100, close waits for pseudoconsole exit, so a stubborn client can consume roughly five seconds even with a two-second grace, and an actual hang can prevent escalation indefinitely. | must_fix | Concurrent PTY creation through ptsname | own_unix.rs:64-68 obtains a pointer from ptsname() and then opens it. | must_fix | Normalizer hides user-visible differences | stream.rs:105-161 discards CR, backspace, erase operations, cursor columns, styling, titles, hyperlinks and terminal modes; it also trims whitespace and invents a final newline.
