# Codex review of the S5 supervisor spike

**Verdict:** `accept_with_changes` — The supervisor architecture is credible, and S5 contains meaningful assertions and controls. It does not establish every evidence claim or justify a product freeze: reader readiness, overlapping Stop requests, scan failures, pidfd absence, and T4 false passes need correction. Review was read-only and static; historical CI results were not independently reproduced.

| Claim | Supported | Evidence |
|---|---|---|
| T1: spawn, descriptor isolation, and pipe/PTY round trips | partly | s5.rs:422–485 asserts exact pipe argv, selected environment values, cwd, stdin, stderr, exit status, Unix fd inventory, and PTY terminal/size/session facts. The in-host spawn control genuinely detects the planted leak; Windows also validates its supervisor-handle probe. However, s5fx.rs:215–226 inspects only five signal dispositions and three blocked signals, excluding SIGPIPE; it does not prove 'all signals default, nothing blocked'. PTY mode does not repeat the argv/env/cwd/leak assertions. Unix supervisor inspection can produce non-failing NOTRUN and lacks a planted positive control. |
| T2: exits, output preservation, exit/EOF separation, and typed failures | partly | s5.rs:523–607 compares exit codes and Unix signals with std::process and explicitly requires Exited more than one second before descendant-held EOF. Those are meaningful assertions. The 300 KB check verifies length and suffix, permitting same-length corruption; the PTY check accepts only 200 complete pattern occurrences from 20 KB, permitting substantial loss. NOT_EXECUTABLE also accepts NOT_FOUND. The std comparisons are useful independent references, but there is no failing control for output loss or exit/EOF coupling. |
| T3: one deadline, resistant tree cleanup, polite stop, and stop after root exit | yes | s5.rs:613–680 requires fixture readiness and three logged processes, independently checks survivors by PID and name, enforces wall time <=1500 ms, and distinguishes forced resistant cleanup from polite cleanup. The resistant tree must remain alive without stop; rootexit requires surviving descendants before stop and unchanged cached exit status afterward. These checks would fail for missing escalation, root-only termination, per-level grace accumulation, or premature Stopped. Scope is one small tree per request. |
| T4: each named host-death mode, bounded cleanup, and creation during host death | partly | s5.rs:684–757 checks six initial fixture processes, zero survivors by PID/name, and supervisor termination; the unsupervised orphan control is useful. However, if the host fails to exit within 15 seconds, the harness kills it and can still PASS. It does not assert the requested exit mechanism or status. Cleanup may take approximately 5.3 seconds before failing, rather than the reported ~1.3 seconds. Full-frame midspawn requires only the original six processes, so the additional spawn can be ignored without failing; neither creation nor its ordering after host death is asserted. |
| T5: isolation from SIGCHLD=SIG_IGN and a foreign reaper | partly | s5host.rs:192–250 creates the hostile conditions; s5.rs:817–848 asserts exits 42/7, forced tree cleanup, and an unrelated survivor. The host-child control must lose at least one status, which distinguishes the hostile host from the supervisor. It does not require all five losses or any positive reaped_by_foreign count, and it does not enforce a stop deadline. Coverage is the Rust host, as the result rows indicate. |
| T6: stale identity safety and retention while descendants live | partly | s5.rs:911–960 has a strong Unix recycled-group test: exact PID reuse, GONE acknowledgements, immediate Stop, a surviving sentinel, then a naive killpg control that kills it. However, recycling failures become non-failing NOTRUN. The live-descendant arm never calls Release and cannot validate 'Release notwithstanding'. Windows checks 150 distinct live sentinels while retaining the process handle, but its post-release test can PASS without observing reuse, and has no destructive comparison control. |
| T7: supervisor death, failed waits, platform cleanup, and restart | partly | s5.rs:1123–1171 requires two pending waits to fail with IO promptly and requires zero Windows survivors. Unix survivor counts are observations: the assertion accepts any outcome. Restart explicitly calls Sup::start again instead of exercising facade::sup's automatic replacement, so a broken lazy restart could pass. Pending spawn, stop, resize, and signal requests are not tested. |
| T8: PTY interaction, host state, close deadlines, and fast-exit output | partly | s5.rs:1175–1243 asserts prompt response, interrupt delivery, resize markers, stubborn-writer liveness/cleanup, and deadlines. Disabling TIOCSCTTY or retaining Windows' ignore flag provides useful interrupt controls; synchronous ClosePseudoConsole is a meaningful deadline control on pre-26100 Windows only. Unix host_sig_state checks five handlers/flags and merely counts blocked signals 1..31, omitting sigaction masks and full mask identity. The resize control checks absence of only one unexpected size. ptyloss_run checks only the PTYREPORT substring and ignores wait/EOF success; its macOS failure control is probabilistic. No test delays reader startup to expose the Go race. |
| T9: latency comparison and K4 | yes | s5.rs:1272–1375 implements rotated, same-job arms, 50 warm-ups, 500 measurements, and actual p50 <=1.25 assertions for the default and alternative paths. FAIL propagates to process exit and the workflow has no continue-on-error. This supports the reported benchmark methodology, not independent verification of the historical numbers. First-spawn timing is explicitly observational because its verdict is unconditional true. Only Rust, null stdio, and trivial pipe-mode programs are benchmarked; PTY and binding latency remain unmeasured. |
| T10: cross-host coverage | partly | T10 is the documented aggregation of T1/T3/T4, not a separate harness command. hosts_for selects Rust/Node/Python for T3/T4 and adds Bun/Deno for T1; the workflow supplies all five. This genuinely exercises the bindings, subject to those tests' weaknesses. It does not establish concurrent host-thread operation or extend T2/T5/T6/T7/T8/T9 to every runtime. |
| Contradiction 1: fork latency violates K4; posix_spawn/vfork-style creation helps | partly | The benchmark fairly compares creation alternatives inside the same supervisor. It can establish runner-specific fork overhead and K4 failures, but does not isolate a universally constant IPC cost or prove either alternative meets K4 across targets. sup_unix.rs:712 uses clone-vfork only when !hold: the current PTY Go protocol therefore falls back to fork. A clone child waiting for host Go would suspend the supervisor needed to send Go. Shared-memory child setup also needs a separate safety audit. [Linux clone semantics](https://man7.org/linux/man-pages/man2/clone.2.html). |
| Contradiction 2: reap-on-release is unsafe; retain cleanup ownership and the identity pin | partly | sup_unix.rs:365–374, 546–579 correctly separates released from gone and retains the zombie until its session appears empty. The conservative fix is sound provided emptiness is trustworthy. T6 never exercises Release with live descendants. The causal wording is too absolute: reaping alone does not immediately make a live session's identifier reusable on Linux; kernel PID bookkeeping retains identifiers used by process groups/sessions. The actual danger is dropping cleanup ownership or retaining an identity after its lifetime ends. [Linux PID bookkeeping](https://github.com/torvalds/linux/blob/master/kernel/pid.c). |
| Contradiction 3: the session is the cleanup unit for pipe children too | partly | Every Unix root calls setsid, and sup_unix.rs:492–525 combines root-group signalling with session-member signalling. That is appropriate for descendants using job-control groups. However, the fixtures never move descendants into another process group, so group-only cleanup would pass the existing lifecycle tests. Sessions are not kernel containment boundaries, and scanning is not an atomic emptiness oracle. Ordinary setpgid cannot move a process outside its session; setsid can. [setpgid semantics](https://www.man7.org/linux/man-pages/man2/setpgid.2.html). |
| Contradiction 4: Stop/Stopped, Ready, and acknowledgement messages | partly | The protocol is a sound way to centralize escalation and confirm termination; T3 exercises that behavior. Signal-only messaging is not intrinsically incapable of implementing stop, but would require additional host state and termination confirmation. The built protocol remains incomplete: both platforms store only one StopSt.req, so overlapping Stop calls silently lose later replies. Blocking owner-thread operations can also defeat the supposedly independent deadline. |
| Contradiction 5: macOS PTY output loss and the Go fix | partly | The no-hold control can demonstrate the reported fast-exit loss, and macOS session-leader exit does drain/revoke its controlling terminal. However, client.rs:465–467 calls Pump::start and immediately sends Go; Pump::start provides no reader-start acknowledgement. Therefore 'until the reader runs' is not implemented. The extra scheduling opportunity can reduce loss without eliminating the race. The proposed sequencing is reasonable, but its implementation and losslessness guarantee need stronger evidence. [XNU session-leader exit](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_exit.c). |

| Severity | Topic | Problem | Proposal |
|---|---|---|---|
| must_fix | PTY Go handshake and held-child cleanup | client.rs:465–467 releases the child before proving reader readiness. In addition, sup_unix.rs:698–724 leaves the Go pipe's write end inherited in the child until after its blocking read; closing the supervisor's write end therefore cannot produce the promised EOF. Existing tests do not cover host death before Go. | Implement explicit reader readiness before Go and test a deliberately delayed reader with complete output comparison. Verify whether readiness suffices under delayed draining; preserve the session leader through a drain acknowledgement or narrow the guarantee if necessary. Close unused Go/error-pipe ends in the child before waiting, and test cancellation, pre-Go host death, setup failure, and missing Go. |
| must_fix | Process inventory must distinguish unknown from empty | procs.rs returns empty inventories on enumeration failure and skips failed stat/getsid reads. sup_unix.rs:545–549 then interprets missing members as an empty session, reaps the pin, and declares gone. The harness shares these inventory helpers, so some observation failures can affect both implementation and oracle. alive also returns false for some EPERM-plus-stat-failure cases despite its conservative comment. | Return complete/partial/error inventory status and alive/dead/unknown liveness. Never reap or emit successful Stopped from an incomplete scan. Use dynamically sized macOS inventories, robust process identity checks, and independently validated test oracles. Inject enumeration, permission, parsing, and truncation failures while descendants remain alive. |
| must_fix | Kernels or policies without pidfd | sup_unix.rs:147 falls back for host monitoring, but signal_member:801–803 silently skips members whenever pidfd_open fails. Descendants in other groups survive on older kernels, under syscall filtering, or under descriptor exhaustion. The ADR's fallback description covers only host detection. [pidfd availability](https://man7.org/linux/man-pages/man2/pidfd_open.2.html). | Feature-detect host monitoring and member signalling separately. Either require and enforce supported pidfd syscalls or define a weaker fallback with explicit PID-reuse limitations; do not silently claim session cleanup. Test ENOSYS, EPERM, EMFILE, and pidfd_send_signal failure with a resistant descendant in a separate group. |
| must_fix | Full channels and backpressure | uds::send_all and Windows Sup::send perform blocking writes on the lifecycle owner. Unix exec_result also blocks that owner, and read_chan drains all decoded requests before returning to deadline work. Windows uses an unbounded internal event queue. A stalled reader, request flood, or stopped setup child can prevent host-death handling and escalation; the ConPTY close worker alone does not make deadlines independent. | Use nonblocking or asynchronous control transport with bounded queues, admission limits, reserved cleanup capacity, and fair processing budgets. Monitor exec-error pipes asynchronously and prioritize host death/deadlines. Define bounded completion or explicit failure for stalled supervisors. Test both channel directions full, partial frames, request floods, SIGSTOP, and children stalled before exec while another tree is stopping. |
| must_fix | Concurrent requests and host threads | sup_unix.rs:422–430 and sup_win.rs:342–349 retain only the first Stop request ID, leaving later callers blocked forever. Host write locks prevent frame interleaving but do not solve Stop/Release/Go races, startup failure races, or inherited mutex state after host fork. | Specify operation linearization and cancellation rules, preserve the earliest escalation deadline, and reply to every waiter. Make supervisor replacement and tree IDs generation-safe. Reject or reinitialize forked-host clients before acquiring inherited locks. Test simultaneous startup/spawn/stop/release, overlapping Stop deadlines, and supervisor death during those operations across real host threads. |
| must_fix | Descriptor and handle exhaustion | Many startup and Windows partial-allocation paths use raw handles without complete rollback. Received ancillary fds can remain queued after errors. Unix Inner.sock is forgotten and shutdown only calls shutdown, with no close; Windows proc_h has no corresponding ownership cleanup. Release does not remove cached exits. Repeated operation can consume resources until cleanup itself fails. | Use RAII for every local and transferred resource, explicit transfer ownership, rollback for incomplete spawns, bounded pending state, and cleanup of released exit records and dead supervisor generations. Reserve resources needed for emergency cleanup. Inject failures at every pipe/socket/PTY/job/dup/thread allocation and verify recovery plus stable fd/handle counts, including high-numbered fds beyond the current close-loop caps. |
| must_fix | Channel authentication and inherited endpoints | The Unix channel authorizes whoever holds its host endpoint; CLOEXEC does not prevent fork-without-exec inheritance. Neither peer identity nor command authority is checked. Windows raw handle values in Spawn also require strict ownership validation. A startup token alone cannot distinguish a fork that inherited both endpoint and token. | Define the trust boundary explicitly. Bind bootstrap and command authorization to the original host using OS-authenticated identity where available, and prevent inherited clients from issuing commands or keeping authorization alive. Where the platform cannot enforce this, state the inherited-capability limitation. Validate all message states, descriptor counts, and transferred-handle ownership; test an inherited endpoint attempting Spawn/Stop/Release and malformed ancillary traffic. |
| must_fix | Windows supervisor-start inheritance race | client.rs:528–594 creates temporarily inheritable channel ends and a host process handle. HANDLE_LIST restricts this supervisor's inheritance but cannot prevent another host thread's unrestricted CreateProcess from inheriting them. A module-local mutex cannot coordinate unrelated native code. [Microsoft's explanation](https://devblogs.microsoft.com/oldnewthing/20200306-00/?p=103538). | Bootstrap without inheritable host handles, for example through a private authenticated rendezvous with bInheritHandles=FALSE and subsequent non-inheritable DuplicateHandle transfers. Arm host-death monitoring before accepting managed spawns. Test concurrent unrestricted process creation throughout startup, including startup failure and host death, and verify no unintended process retains channel endpoints or host handles. |
| must_fix | musl and libc compatibility | sup_unix.rs:1046–1100 unconditionally references nonstandard spawn actions for Linux. CI builds only the runner's GNU target; libc/API availability, static linking, old glibc compatibility, and child setup under musl are unproved. | Declare supported libc/version floors, gate optional spawn implementations by actual availability, and retain a tested fallback. Build and execute musl targets, including static configurations and oldest supported environments. Run lifecycle, descriptor isolation, PTY, failure, and latency tests on each creation backend before selecting it. |
| should_fix | Scanning cost with many trees | A tick uses one shared process scan, approximately O(system processes + tracked trees), rather than one scan per tree. Nevertheless, members scans are repeated by each begin_stop; host death invokes begin_stop for every tree, making stop-all potentially O(trees × system processes). check_exits traverses all trees, gone unreleased entries remain, and scan duration itself can exceed the 10 ms target. | Share one inventory and one absolute deadline across stop-all, bound command/scan work, retire completed state, and schedule deadline work independently of expensive enumeration. Use event-driven exit/membership support where sound. Benchmark thousands of trees against large unrelated process populations, measuring CPU, admission latency, scan duration, and worst-case cleanup latency. |
| must_fix | T4 false passes and mid-spawn coverage | s5.rs:709–725 permits cleanup success after the harness substitutes a forced host kill for the requested death mode. Midspawn can pass with no additional tree created, and the claimed ~1.3-second bound is printed rather than enforced. | Require the host to exit through the requested mechanism; mark timeout as FAIL before cleanup. Measure cleanup from observed host death against an explicit bound. Add deterministic barriers around accepted Spawn, OS creation, registration, and Go, asserting expected extra creation for full frames and no creation for incomplete frames. Cover initial supervisor bootstrap separately. |
| must_fix | Release ownership and job-control coverage | The evidence attributes Release-independent pinning to T6, but that test never releases its live-descendant tree. No fixture changes process group, so session sweeping is untested and group-only implementations can pass T3/T4/T6. | Release a root-exited tree with resistant descendants in separate process groups, then kill the host and require complete cleanup. Add a group-only control that leaves those descendants alive, plus explicit zombie-pin observation. Require PID-reuse coverage on designated CI targets instead of silently accepting NOTRUN. |
| should_fix | Output, signal state, and restart assertions | T1 overstates its sampled signal checks; T2 does not compare complete output and accepts NOT_FOUND for a non-executable; T7 tests manual startup instead of automatic recovery. T8's marker-only fast-exit check and partial host-state snapshot leave failures undetected. | Compare exact expected pipe bytes and complete normalized PTY output; require successful wait and EOF. Use a minimal fixture that observes signal state before runtime changes and seed ignored/blocked signals in the host. Assert exact platform error classifications. Kill a facade-owned supervisor with pending operations and verify automatic restart through the same public API. |
| must_fix | Product output backpressure and resource bounds | Pump::start appends every byte to an unbounded Vec and treats all read errors as EOF. The spike's permanently draining threads avoid real consumer backpressure and can exhaust memory. Closing or slowing a product consumer also affects macOS loss guarantees and pre-26100 ConPTY shutdown. | Implement the product's bounded output policy, ordered loss/error reporting, cancellation, and continued draining during cleanup. Distinguish expected PTY EOF errors from real I/O failures. Test slow and abandoned consumers, output limits, and stubborn writers on both Windows build families. [ClosePseudoConsole requirements](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole). |
| must_fix | Creation-backend safety and PTY latency | T9 exercises alternatives only with trivial null-stdio children, so performance results do not establish equivalent behavior. CLONE_VM shares supervisor memory and CLONE_VFORK suspends its owner; a blocked setup child stalls all lifecycle work. The present Go hold disables that backend for PTYs, whose extra round trip is unmeasured. | Run the complete behavioral suite per backend and audit shared-memory child code, signal delivery, stack/TLS use, error paths, and blocked setup behavior. Keep Go-held PTYs off a suspending creation path unless the handshake is redesigned. Measure PID latency and spawn-to-exit separately for pipe and PTY modes; explicitly resolve K4 rather than treating an alternative benchmark as its fix. |
| should_fix | ADR acceptance and guarantee precision | The original Decision still permits reap-on-release, describes pipe containment by group, and retains an unmet K4 requirement. 'Everything else held' exceeds the tested scope. Ordinary setpgid within the existing session is covered by the intended session sweep and should not be described as an escape outside that session. | Integrate accepted refinements into the normative decision, identify observations and NOTRUN rows, and state session scanning and supervisor-death limits precisely. Keep product freeze conditional on the strengthened tests and an explicit performance decision. |
