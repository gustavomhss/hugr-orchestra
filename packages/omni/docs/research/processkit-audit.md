# processkit v3.3.4 — independent source audit (Codex)

Static review of the source and tests at tag v3.3.4 (commit ba1a6fe) by Codex CLI, read-only, without
relying on the README. Nothing was built or executed here; the hands-on evaluation is `processkit-eval.md` (E1).

**Verdict:** `build_on_it_with_fixes`

The inspected source supports race-free Windows startup containment and conditional Linux cgroup containment, backed by meaningful real-process tests. A production TypeScript package needs PTY fd and input-validation fixes, bounded ConPTY drainage, explicit incomplete-capture reporting, bounded output handling, and honest containment/host-death capabilities. Universal cross-platform no-orphans guarantees do not hold. Assessment is static at ba1a6fe/v3.3.4; nothing was built or executed.

## Areas

| Area | Status | Evidence |
|---|---|---|
| 1. Windows tree kill and batch quoting | concerns | Startup containment is sound in the inspected paths: CREATE_SUSPENDED precedes AssignProcessToJobObject and resume (src/sys/windows.rs:636, :682, :696); ConPTY follows the same order (src/sys/pty/windows.rs:850, :944; src/sys/windows.rs:733, :741). Startup grandchildren therefore inherit membership. KILL_ON_JOB_CLOSE is installed on an unnamed, non-inheritable Job handle (src/sys/windows.rs:475, :491). No breakaway permission is enabled; rejected nested assignment returns an error and the suspended-child guard attempts termination (:683, :1636). Abrupt host death between creation and assignment can still leave a suspended orphan (:112). Ordinary batch launches delegate to std through cmd.spawn() (:655); the repository's batch test supplies no hostile arguments (tests/integration/capture.rs:459, :499), so BatBadBut resistance is not independently established. ConPTY uses its own MSVCRT quoting and raw CreateProcessW, without batch dispatch (src/sys/pty/windows.rs:379, :878). |
| 2. Linux and macOS tree kill | broken | The unconditional whole-tree promise fails on the process-group backends. Linux locates cgroup v2 at two fixed mount paths, derives the parent from /proc/self/cgroup, and creates a private directory (src/sys/linux.rs:907, :924, :1443, :1483). Creation errors fall back to process groups unless resource limits were requested (:118); the degradation warning exists only with tracing (:91). Successful cgroup launches join through a pre_exec write before executable code runs (:205), so setsid alone cannot escape membership. A membership-write failure fails spawn rather than starting an uncontained child (:210, :2939). Teardown uses cgroup.kill, with a bounded freezer/pidfd sweep when that write fails (:2225, :2281). Without delegation, containers commonly reach the weaker process-group path. Both that path and macOS create a child process group and signal its group ID (src/sys/pgroup.rs:1162, :947; src/sys/unix.rs:66). Descendants that call setsid or move into another process group escape; inherited group membership alone remains covered. |
| 3. Drop, host panic, and host exit | broken | Dropping an owned group triggers containment cleanup: Windows closes the Job handle (src/sys/windows.rs:2283); Linux attempts cgroup kill and bounded drain while swallowing Drop errors (src/sys/linux.rs:849, :863); process groups issue best-effort SIGKILL (src/sys/pgroup.rs:1625). Non-escalating shutdown deliberately disables this backstop (src/sys/windows.rs:2247; src/sys/pgroup.rs:1627). RunningProcess drop aborts its pumps and watchdogs; a shared-group handle does not own the group's teardown (src/running/mod.rs:3281, :3391, :726). Unwinding an owning scope runs Drop; panic=abort, process::exit, and default fatal host signals do not. No host SIGINT/SIGTERM cleanup handler was found in src. Linux's optional PDEATHSIG kills only the direct child and is tied to spawning-thread death (src/sys/linux.rs:178, :2902, :2919); grandchildren survive, explicitly asserted by tests/integration/parent_death.rs:383. macOS provides no abrupt-death cleanup, and its test asserts both descendants survive (:391). Windows kernel handle closure covers already-assigned members even on abrupt host termination, with the creation-to-assignment exception above. |
| 4. PTY lifecycle and EOF | concerns | ConPTY bridges start before the child is assigned and resumed (src/sys/pty/windows.rs:928, :937, :944). Process waiting holds the handle through Arc ownership (:224). After exit, wait releases the input keepalive, waits for 100 ms of output silence, and then calls ClosePseudoConsole synchronously (:103, :124, :246, :262). This is a silence heuristic, not proof that rendering finished, and its loop has no overall bound. The reader bridge remains available during normal close but uses a bounded channel (:1047). Drop calls ClosePseudoConsole without the quiescence wait (:349); RunningProcess aborts pumps before backend field destruction (src/running/mod.rs:3300). Unix correctly wires slave stdin/stdout/stderr, creates a session, and acquires the controlling terminal with TIOCSCTTY (src/sys/pty/unix.rs:455, :469, :485). The Unix raw-fd inheritance defect is described in area 6. ConPTY stdin EOF is a Ctrl-Z/CR gesture, not closing the console input pipe (src/sys/pty/windows.rs:1095, :1170). |
| 5. Output pumping and memory | concerns | A newly started RunningProcess has no output pumps (src/running/mod.rs:864, :867; PTY :926, :929). Capture, readiness, streaming, or wait operations install them later (:1385, :2144, :2216). Holding a handle without such an operation can therefore block a chatty child. Once running, ordinary pumps do not depend on the consumer popping lines, but callbacks run synchronously and tee writes are awaited, so either can stall drainage (src/pump.rs:1482, :1485). Default retention is unbounded; bounded(max_lines) does not bound individual line length (src/buffer.rs:355, :364, :433). max_bytes also constrains unfinished-line assembly, with chunk and allocation overhead (src/pump.rs:1607, :1722). Normal EOF flushes the final unterminated line (:1757); pump joins instead abort after five seconds and do not report incomplete drainage (src/running/mod.rs:47, :3791). UTF decoding is incremental, lossy, and removes the leading BOM (src/pump.rs:1608, :1652); raw stdout capture preserves bytes (src/running/mod.rs:3741). |
| 6. Unsafe code and signal/async safety | concerns | The sampled fork-to-exec hooks prepare allocations in the parent and use stack formatting and syscall-style operations in the child: cgroup join uses open/write/close (src/sys/linux.rs:2939), PDEATHSIG uses prctl/getppid/_exit (:2919), and terminal setup uses setsid/ioctl (src/sys/pty/unix.rs:469, :485). No allocator/lock call between fork and exec, definite UB, or double close was established in these sampled paths. Windows handle transfer clears the previous owner's handle before constructing File (src/sys/pty/windows.rs:1002), and detached waits retain process ownership through Arc (:224). However, Unix openpty descriptors are wrapped without setting FD_CLOEXEC (src/sys/pty/unix.rs:185, :198). The later fcntl changes only O_NONBLOCK (:214, :219), and the pre_exec hooks do not close the original master. On implementations returning inheritable openpty fds, the executed child and unrelated concurrent launches inherit unintended terminal descriptors. An exec-time fd inventory test would establish the precise platform impact. |
| 7. Error handling and public-path panics | concerns | Public-path implementations contain poisoned-mutex expects, including SharedLines and raw capture (src/pump.rs:686; src/running/mod.rs:1692), and ConPTY reader/writer state (src/sys/pty/windows.rs:1265, :1522). Several ownership expects appear protected by internal invariants; no ordinary-input violation of those invariants was established. Line-handler panics are caught and disable that handler (src/pump.rs:188); a panicking stdin source has a real error-propagation test (tests/integration/capture.rs:968). Actual pump read errors are recorded and surfaced (src/pump.rs:1815; src/running/mod.rs:2201). Pump task panics and drain timeouts are nevertheless swallowed as run errors (src/running/mod.rs:3798), tee write failures disable the tee, and tee flush errors are ignored (src/pump.rs:1454, :1493, :1802). Drop cleanup is best-effort and cannot report failure. Raw ConPTY launch also bypasses std's normal spawn-time input validation. |
| 8. Tests and platform proof | concerns | These are not merely mocks. Actual tree tests include windows_grandchild_is_contained (tests/integration/groups.rs:133), windows_nested_job_assign_and_kill_all (:950), windows_nested_job_outer_close_reaps_tree (:1020), unix_setsid_child_forks_grandchild_still_contained (:230), and unix_fork_storm_is_swept_by_group_broadcast (tests/integration/process_control.rs:134). The Unix setsid test covers a direct child intentionally starting a session; its grandchild does not independently escape. A real Linux setsid-escapee cgroup test exists (src/sys/linux.rs:6007), but returns successfully when delegation is unavailable (:5670, :6008). CI runs ignored tests on Linux, Windows, and macOS (.github/workflows/ci.yml:105, :130); no mandatory delegated-cgroup setup was found. pty_finish_sends_console_eof_without_closing_the_session proves ConPTY input EOF (tests/integration/pty.rs:454). concurrent_pty_sessions_stay_correct_at_scale checks output markers and completion (tests/stress/main.rs:422, :465), and is scheduled on all three OSes (.github/workflows/stress.yml:40). Neither distinguishes actual output EOF from the five-second pump-abort fallback; no test directly proves prompt ClosePseudoConsole output EOF, complete final-frame drainage, or PTY startup-grandchild containment. Windows abrupt-owner-death coverage is also absent from the Unix-gated parent-death suite (tests/integration/main.rs:28). No tests were executed during this audit. |
| 9. Maintainability, churn, and API stability | concerns | Measured src contains 86,342 lines across 58 Rust files; 28 exceed 650 lines. This includes substantial comments and inline tests, not 86k production statements. Large lifecycle modules include src/command.rs:101 (6,586 total lines), src/running/mod.rs:839 (6,403), src/sys/linux.rs:107 (6,331), and src/pump.rs:1414 (5,258). HEAD ba1a6fe identifies v3.3.4 (Cargo.toml:3). Its history contains 1,108 commits from 2026-05-31 through 2026-08-22, including 102 dated 2026-07-08. Major lines arrived rapidly: v1.0.0 on June 16 (73a812c), v2.1.0 on July 6 (66c8c66), and v3.0.0 on July 25 (c4c537c). Source-changing commits demonstrate genuine breakage: field/API renames (d7c5f61), alias removal (d19c631), Error boxing (a40dff9; current src/error.rs:1350), and OutputEvent-to-ProcessEvent rename (9cb59aa; current src/running/stream.rs:1023). Two author identities belonging to Anton account for 868 commits; another 201 use Test <test@test.com>. Bus factor is uncertain but visibly concentrated; those anonymous commits cannot establish independent maintainers. |

## Findings

| Sev | Location | Claim | Reality |
|---|---|---|---|
| P0 | `src/sys/linux.rs:118` | Whole-tree kill-on-drop provides an unconditional no-orphans guarantee. | Linux silently accepts process-group fallback without tracing when cgroup creation fails. Descendants that change process groups survive cleanup; macOS always has this boundary. A TypeScript API must expose the weaker capability or refuse launches requiring stronger containment. |
| P0 | `src/sys/linux.rs:2919` | Host termination reliably cleans up the process tree. | Default Unix SIGINT/SIGTERM, SIGKILL, abort, and process::exit bypass Drop. Optional Linux PDEATHSIG reaches only the direct child; the real test explicitly expects grandchildren to survive. macOS has no abrupt-death cleanup. Host signal handlers can improve graceful termination, but cannot supply universal SIGKILL cleanup. |
| P1 | `src/sys/pty/unix.rs:198` | Unix PTY descriptors remain confined to their intended owners. | The original openpty master and slave are never marked close-on-exec, and no pre_exec hook closes the master. Inheritable descriptors leak into executed children and potentially concurrent launches. Set close-on-exec before launch and verify inherited fd inventories on Linux and macOS. |
| P1 | `src/sys/pty/windows.rs:431` | ConPTY preserves the normal process-launch input validation boundary. | The raw environment builder copies embedded NULs and invalid names directly. For example, a value containing "ok\u0000INJECTED=yes" becomes two environment entries. Command-line construction likewise permits NUL truncation. Building a tokio Command does not perform the spawn-time validation because this path calls CreateProcessW directly. Reject invalid inputs before serialization and add Windows regression tests. |
| P1 | `src/sys/pty/windows.rs:124` | Waiting for the ConPTY child reaches output EOF promptly after that child exits. | Quiescence restarts indefinitely while output arrives. A surviving descendant that continually renders can keep wait pending after the direct child exits. Conversely, 100 ms of silence does not establish that every delayed final frame arrived. Add an overall drain bound and tests for both continuous descendant output and delayed final rendering. |
| P1 | `src/sys/pty/windows.rs:878` | PTY launch supports the same Windows executable and batch commands as ordinary launch. | Ordinary launch reaches std's batch handling; ConPTY directly submits a .bat/.cmd path to CreateProcessW with only MSVCRT argument quoting. There is no equivalent batch dispatch or hostile-argument test. Reject batch PTY launches explicitly or implement and test an appropriate safe launch path. |
| P1 | `src/running/mod.rs:3791` | Successful capture accurately reports whether output was completely drained. | Pump panics are ignored, and five-second drain timeouts abort pumps without returning a capture error. Text truncation is computed only from buffer-policy drops at line 1578. A successful result can therefore contain incomplete output with truncated=false; an unfinished text tail can also be lost. Report pump completion and preserve partial tails. |
| P1 | `src/running/mod.rs:867` | Starting a process protects an unattended caller from output blockage and uncontrolled memory growth. | Pumps are initially absent, so an unattended handle can leave OS pipes full. After pumps start, default capture grows without bound, and a line-count limit alone permits an arbitrarily large unfinished line. A TypeScript wrapper needs deliberate eager drainage, byte limits, and callback/tee backpressure semantics. |
| P1 | `src/sys/linux.rs:5677` | The platform test matrix establishes the strongest containment and ConPTY EOF claims. | Real cgroup tests can return success without exercising cgroups, and CI does not require delegation. Existing ConPTY completion tests can pass through pump-abort fallback. Require a delegated Linux test lane and a Windows output-EOF assertion that cannot pass after aborting the reader. |
| P2 | `src/command.rs:101` | The crate is a small, stable substrate with distributed maintenance ownership. | The source spans 86,342 lines, lifecycle responsibilities occupy several multi-thousand-line modules, and three major API lines appeared within weeks. Commit authorship is concentrated, with a substantial anonymous Test identity. Pin the Rust version and isolate its evolving API behind a narrow binding contract. |
