# Native Atlas context and continuity

Read for every task, whether or not a Memory write is needed. Use only actual native bound tools; do not invoke an Atlas CLI, write `.atlas/` or invent a storage root.

## Header is always native

The host supplies shared Awareness/Orientation and this owner's bounded project Rules on actual provider turns, independent of skill loading. Owner is stable `jimmy`, not the display label. Do not manufacture a header, inject another member's Rules, or use task/PR archives or the orchestrator logbook as running context.

Complete-empty, partial and unavailable are different states. Missing Orientation fields remain missing. Previously loaded context is not fresh during an outage. Report the affected operation and continue only work whose evidence does not depend on it. Header availability is a host fact, not a claim inferred from this document.

## Read verified Own selectively

Use `atlas_context`'s exposed `catalog` action to identify exact verified units/territories, then its `unit` action for the selected identity using the live closed schema. Do not guess unimplemented argument names, select a nearest-name unit or supply project/root/owner. Read required context and continuation before claiming its coverage.

Preserve returned source identity, worktree/revision binding, grounding/currentness and coverage. Dirty blob drift, ambiguous identity, incompatible ancestry, stale cache and missing required coverage are holds; return them verbatim without a bypass. A preview does not certify omitted required context. A verified source binding does not automatically ratify the research inference drawn from it.

## Recall only the named own unit

`atlas_memory_recall` accepts exactly `{ kind: "task", taskId }` or `{ kind: "pr", prId }`. Use actual task/PR identity from the mission/native context. The host binds owner, project and storage. Do not request another owner, project Rules or logbook through recall. Partial/unavailable stores do not establish that no checkpoint exists.

On authorized logical resume, recover the exact admitted checkpoint supplied by native selection and reopen its retained corpus/source references. Memory text is not the archive. The host owns once-per-logical-resume admission and compaction restore; do not select a newer checkpoint under an old admission or repeat its fold each turn.

The canonical closing fold is reduced continuity text, not the complete task entry. If its evidence pointer is absent, recall the named own unit and match the full record to the admitted record reference before using its optional `ref`. Decode only the actual returned pointer and reopen it through `research_view`; a Memory reference never grants arbitrary file access. Missing source bytes remain unavailable even when the checkpoint text survives.

## Emit only truthful continuity or experience

`atlas_memory_emit` accepts `{ entry }`. Supported entry keys are exactly:

- Task: `taskId`, `attempted[]`, `failedWith[]`, `stoppedAt`, `lesson`, optional `ref`.
- PR: `prId`, `decisions[]`, `reviewOutcomes[]`, `knowledgeDelta[]`, optional `ref`.
- Project: `rule`, `scope`, optional `grounding`.

Describe only this role's actual research attempts/outcomes. `ref` can point to retained native evidence using the exposed template's representation. Do not add `findings`, owner/provenance/status, scores, `frecency`, custom partitions or logbook entries. Do not fabricate lessons, implementation decisions, review outcomes or knowledge changes. A simple fact need not emit Memory. If a required template field lacks a truthful value, preserve the corpus and report the limitation.

Reconcile-before-write is native. After uncertainty, resubmit only the identical entry when permitted; do not vary it to force another append. Preserve `admitted`, `refused`, `unavailable`, `uncertain` and reconciled status. Only a real receipt establishes admission; scanner refusal is returned verbatim.

Research findings are not Memory Knowledge writes. Candidate reusable facts stay in the corpus unless the existing admission owner/door supplies a real Knowledge receipt. Handoff to that owner is a recommendation, not self-ratification. Complete warranted Memory operations before [final closure](closure.md).
