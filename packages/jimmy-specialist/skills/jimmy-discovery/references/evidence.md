# Evidence and applicability

Read for every discovery or research task. Use these distinctions before acquiring, interpreting or citing material; read [corpus](corpus.md) when the analytical state needs durable links or revisions.

## Follow the evidence chain

A source origin identifies where material came from. A host capture identifies retained bytes under a declared representation. A locator identifies the passage. A proposition explains what that passage supports under stated conditions. None alone establishes truth, currentness, causal effect or independent verification.

Use original code, contracts, official versioned documentation, supplied observations and primary studies where applicable. A generated overview or vendor claim can orient search, but does not replace the underlying clause. When only secondary material is available, attribute it as such and retain that limitation. Read enough context to include the exception that changes the answer.

Distinguish:

- **Extraction:** what the source states; attribution is not endorsement.
- **Observation:** what an admitted observation actually shows, for its inputs/environment/window.
- **Inference:** what follows from sources and assumptions; explain the bridge.
- **Hypothesis:** an unresolved possible explanation or value claim; name its discriminator.
- **Proposed action:** what someone should do next; never relabel it an observation.

Static source can establish a branch or registration. It cannot establish activation, production causality or an experiment's result. A test definition is not its execution; an execution receipt is not universal correctness.

## Preserve source state

Requested, acquired, transformed, parsed and used are separate stages. An HTTP success can retain an error page. Conversion can omit a table. A preview can stop before an exclusion clause. Record actual failures, partial coverage and inaccessible material instead of silently dropping them.

Bind evidence to the applicable version, scenario and representation. A lockfile does not prove the loaded binary; `latest` documentation does not establish fork behavior. Dirty file bytes need their actual capture identity. Same URL can change; identical mirrors share an origin and do not corroborate each other independently.

Use only returned `SourceRef` values and locators over their exact retained representation. Do not invent artifact IDs, revision numbers or hashes. A host digest identifies content, not meaning. Preserve historical evidence when current content differs; reanchoring creates a new candidate/currentness assessment, not replacement history.

## Confront the claim

For each decisive claim ask: what would make this false, narrower, stale or irrelevant? Read the material alternative, boundary condition or contrary source. Explain disagreement through version, definitions, sample, environment or method where evidence permits. Preserve unresolved conflict in the finding and final synthesis.

A valid citation map only establishes reference resolution. Check whether each cited passage supports its associated clause. Separate multi-source inference from quotation, and paraphrase from exact quotation.

## Bound negatives

Before “none”, “all”, “only” or “no references”, define the examined universe, detector operation, revision/config, exclusions and failures. Demonstrate a known positive witness of the same kind in that universe. Failure to retrieve the witness makes the negative inconclusive. Success demonstrates sensitivity for that control, not completeness everywhere.

Top-K results, an empty LSP result, missing trace spans and failed fetches do not establish absence. Say what was not found in the examined scope and what remains unexamined. Stop rather than manufacturing confidence percentages or source quotas; [closure](closure.md) defines truthful sufficiency.
