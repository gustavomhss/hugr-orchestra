# @orchestra/tui

Terminal UI used by the CLI.

## Purpose and ownership

- The terminal app (OpenTUI and Solid): `packages/tui/src/app.tsx`, routes, prompt, dialogs, keymap, themes, and the feature plugins and plugin slots under `packages/tui/src/feature-plugins` and `packages/tui/src/plugin`.
- `apps/cli` starts it with `run` from `@orchestra/tui`.

## Public entry points and consumers

- Explicit `exports` keys: `.` (`run`), `./config`, `./builtins`, `./runtime`, `./keymap`, the `./context/*` providers and `./plugin/*`.
- Consumers: `apps/cli`.

## Dependencies and boundaries

- Layer `terminal-ui`: may use core (it runs in the backend process), plugin, schema, ui and client.
- The TUI speaks only V2: Sessions, messages and events come from `@orchestra/client` and the types in `packages/tui/src/types.ts`.

## Assets, schemas and generated files

- None.

## Persistence, identity and lifetime

- The KV and persistence contexts write under the core `Global` paths (state directory).

## Language policy

The TUI is English-only for now. Strings are written in place and there is no i18n layer. Do not add ad hoc translation dictionaries; a localization layer needs its own design, as the web and desktop apps have one in `packages/app-shell`.

## Commands

- `bun typecheck` from `packages/tui`.
- `bun run test:ci tui <files>`

## Contracts and verification limits

- `packages/tui/src/clipboard.ts` and `packages/tui/src/editor.ts` are listed in `script/spawn-allowlist.json`.
- Tests do not drive a real terminal; screen output is checked by hand.
