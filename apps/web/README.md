# Web entry

The browser entry and Vite build of the Orchestra interface. It is a thin shell: `src/entry.tsx` builds the web
`Platform` (browser draft store, notifications, external links, default server URL kept in `localStorage`), optional
Sentry setup and the initial locale, then renders `AppInterface` from `@orchestra/app` (`packages/app-shell`), the same
shared UI that Desktop hosts. All UI, contexts, platform contracts and public assets live in `packages/app-shell`.

## Who uses it

- `orchestra web` and `orchestra serve` in `apps/cli` serve the built output. They look for it in
  `ORCHESTRA_WEB_UI_DIR`, then a `web` folder beside the executable, then `apps/web/dist`.
- Developers, through the Vite dev server.

## How it connects

The page talks to an Orchestra server. In dev, or when `VITE_ORCHESTRA_SERVER_HOST` or `VITE_ORCHESTRA_SERVER_PORT` is
set, it targets `http://<host>:<port>` (default `localhost:4096`); otherwise it uses the page origin. A saved default
server URL wins over both. An `auth_token` query parameter is read once for sign-in and removed from the address bar.
Sentry starts only when `VITE_SENTRY_DSN` is set.

## Commands

From the repository root:

```sh
bun --cwd apps/web dev     # Vite dev server on port 3000, all interfaces
bun --cwd apps/web build   # production build into apps/web/dist
bun --cwd apps/web serve   # preview the build
```

`bun typecheck` from this directory. UI unit, browser and E2E harnesses live in `packages/app-shell`; the dev server
also serves its fixtures at `/e2e/`. See [packages/app-shell/AGENTS.md](../../packages/app-shell/AGENTS.md) for the UI
and localization rules.

## Limits

- The dev server listens on `0.0.0.0` and allows any host, so use it only on a trusted network.
- There is no `public/` here: the config points `publicDir` at `packages/app-shell/public`.
- Source maps are uploaded and removed only when the `SENTRY_*` variables are set.
