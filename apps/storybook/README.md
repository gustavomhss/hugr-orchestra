# @orchestra/storybook

Storybook workbench for the ui, session-ui and app components.

## Purpose and ownership

- Loads the `*.stories.*` files that live beside the components in `packages/ui`, `packages/session-ui` and `packages/app-shell`; this app holds no stories of its own.
- `apps/storybook/.storybook/main.ts` lists the story globs and aliases app-shell's `@/context/*` modules to mocks, so app components render without a server.

## Public entry points and consumers

- Application only, no library exports. Developers run it locally; the `storybook build` job in `.github/workflows/storybook.yml` builds it on the `epic` label or by manual dispatch.
- Configuration in `apps/storybook/.storybook` (`main.ts`, `preview.tsx`, `manager.ts`, `theme-tool.ts`, `playground-css-plugin.ts`) and mocks in `apps/storybook/.storybook/mocks`.

## Dependencies and boundaries

- Layer `app`.
- Dev dependencies `@orchestra/ui` and `@orchestra/session-ui`; stories in `packages/app-shell` are reached by path.

## Assets, schemas and generated files

- Mocks under `apps/storybook/.storybook/mocks/app` stand in for app-shell contexts, hooks and two components.
- The Storybook build output is not checked in.

## Persistence, identity and lifetime

- None.

## Commands

- `bun run storybook` serves on port 6006 (`storybook dev -p 6006`).
- `bun run build` writes the static site.
- There is no typecheck script.

## Contracts and verification limits

- Mocks declare the small wire types they need locally; they import no SDK package.
- A mock can drift from the real app-shell context it replaces; the build does not detect that.
