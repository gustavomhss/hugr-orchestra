## Execution rules

- One GUI owner and one heavyweight process at a time. Maximum two lightweight, independent readonly review tasks after their source slice freezes; no discovery fan-out or new worker fleet.
- Fast feedback uses the actual production module and real provider, narrowed to the failing path. A focused pass is diagnostic evidence, not a replacement for full acceptance.
- Every hypothesis has a predicted observable, one bounded probe and a saved receipt. After two unproductive probes, revisit the mechanism using their evidence rather than launching the full suite.
- Run the full registered-tool suite only after the local failure and affected regression controls pass. Re-run a passing broader gate only for a new source change in its reach, a failure or an unresolved concern.
- Keep request budgets, scope/focus guards, unknown outcomes, mutation controls, required-case manifests and independent effect oracles intact. No hidden skips, normalization, deadline widening or synthetic ACK success.
- Keep the existing pinned image and owned HOME. Recreate only a stopped testbed's session volume when stale sockets prevent a fresh supervisor launch. Re-read process/session identities after every boot.
- Use a persistent private evidence directory outside any Git checkout for registered-tool receipts: `/Users/gustavoschneiter/.local/share/orchestra/recovery/dock-accessibility-20261002`. This preserves the harness's existing output-location guard. Temporary storage is not the resume anchor.
- Recreate only the minimal resolver/dependencies the chosen command requires. No repository-wide install or cleanup loop.
- Update this dashboard when a gate changes; one short outcome/blocker/next-step card. Read source and receipts on demand, not entire historical transcripts.
