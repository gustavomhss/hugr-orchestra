## Minimal packaging, offline operation, update and rollback

- Add ordinary toolkit package with versioned platform payloads: `native/`, `js/`, `python/`, `jvm/`, `licenses/`, build inventory and conventional npm/Python/Cargo locks. Inventory records engine/source/version, target+ABI, URL/package coordinate, verified content integrity, runtime closure, license texts and qualified recipe. It is release metadata, not new runtime catalog protocol.
- CI obtains pinned upstream archives/npm packages/wheels/JARs, builds ogen/SQLx, assembles complete target tree. Standard npm platform `optionalDependencies` + `os/cpu/libc`, npm pack and tar/zip reuse existing mechanisms. User-facing normal install selects complete target payload once; all advertised channels call same readiness contract. Prefer publishing assembled payload over resolving upstream tools on user machines.
- Bundle must live on real filesystem for subprocesses. Bun virtual filesystem embedding alone does not make native helpers executable. Package beside host or at immutable versioned prefix; resolver returns exact executable/argv/environment and version to existing shell/native adapters. Direct and Maestro use same paths. Do not substitute ambient `node`, `python`, `java`, `dotnet` or unpinned engine.
- Ordinary setup checks full inventory and local representative operations before declaring READY. Rust/DB-dependent acceptance runs in release qualification with provisioned project fixture; end-user install can check SQLx SQLite DB/migration operation without requiring user Rust project. Project-required tool version takes precedence only through explicit compatible recipe; mismatch is reported, not replaced with latest default.
- **Offline install:** distribute complete target archive or completely mirrored package closure; no-network empty-cache installation must work from that input. Online normal installation may fetch package payloads before READY. **Offline/warm invocation:** local schemas/refs/imports, preinstalled runtimes/plugins and zero first-use package resolution; new tasks must not need earlier tasks to populate a tool cache.
- Disable engine updater/telemetry network paths in managed invocation. Kiota source supports `KIOTA_OFFLINE_ENABLED=true` for update check and `KIOTA_CLI_TELEMETRY_OPTOUT=true`; supply local OpenAPI input. Use direct OAG JAR rather than updater wrapper. Offline tests deny network rather than trusting flags. Project dependency restores, remote contract refs and live DB requirements remain explicit project inputs. [KO]
- Stage new immutable toolkit release, verify integrity/closure/operations, then atomically activate host+toolkit-compatible installation. Interrupted download, missing asset or failing operation leaves previous complete release active. Keep previous version for rollback; Windows in-use executable/DLL cleanup waits until unused. Package managers retain their own install lifecycle, with same full-bundle postcondition.
- Rollback restores pinned engine/runtime/adapter set, not previously generated application files or database mutations. Do not independently auto-update engines, mutate project locks, or regenerate project output during toolkit update. Same-version repair must recheck payload completeness despite host version-match shortcut.
- Integrity evidence exists in npm `dist.integrity`, PyPI/crates metadata, Node SHASUMS, Buf `sha256.txt`/minisig and Temurin checksum assets. Actual assembled-byte hashes remain release-build work. No fabricated digests, footprint estimates or launch-time claims. Measure compressed/installed size and cold/warm invocation only during later qualification.
- Carry MIT copyright/license texts, Apache LICENSE/NOTICE where supplied, and full runtime/transitive notices; top-level host MIT label does not replace component terms. OpenAPI Generator explicitly assigns generated output to user while templates retain tool license; generated application dependencies still retain their own licenses. [G]
