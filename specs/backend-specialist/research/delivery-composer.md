## Contract to freeze before parallel implementation

1. **Version binding:** installed package/build revision + qualified contract version + catalog/descriptor digest. Fail `CAPABILITY_UNAVAILABLE` for old producer, missing capability, missing packaged metadata or unsupported preview/profile. Package `0.1.0` and embedded catalog `kit_commit` alone are insufficient identity. Probe read-only capabilities before preparing; never discover substitutes.
2. **Compose input:** exactly one nonempty `recipe_id` or nonempty unique `primitives`; reject both, neither, duplicates, unknown fields and invalid names. Require `expected_kind=composition|skeleton`; accept only absent/false `force`. Validate resolved filename/symbol, Python keywords and initializer collisions. Preserve exact recipe record and actual primitive set through request, source, preview and result.
3. **Mode handling:** recipe-template/ad-hoc may satisfy explicitly requested skeleton only; remove fake-ready default construction/HTTP-success behavior from qualified skeletons or make incomplete install fail explicitly. Adapter mode satisfies composition only with qualified callable/dependency contract. Delegation returns `blocked/UNSUPPORTED_OUTPUT` plus separate required operation, never generated success. Output-kind mismatch blocks before publication.
4. **Mount/runtime wiring:** use recipe default only if compatible with assigned API. Unsupported mount on shutdown composition is rejected; required callable bindings remain typed runtime parameters or explicitly supplied application references. Generation neither reads secrets nor invents dependencies such as an auth implementation. Result lists unresolved runtime wiring separately from missing generation prerequisites.
5. **Scaffold input:** require `output_dir`, explicit nonempty safe `name`, explicit profile, explicit `models` object and strict boolean `with_auth`; `owner_models={}`, `shared_models=[]`, `dry_run=false`. `{}` means no business entities in models, schemas, CRUD, routes, migrations or tests. Auth-enabled system `User` is separately declared infrastructure, not a fallback business model. An explicit empty field map means identity/timestamp-only model, if admitted by descriptor.
6. **Model convention proposal:** exact ASCII PascalCase model keys, snake_case field keys, no keywords/path fragments/quotes; reject case-folded module/table collisions and framework-reserved names (`Base`, `User`, SQLAlchemy/Pydantic reserved members). No silent capitalization or ignored custom `id`. Reserve `id`, `created_at`, `updated_at`, `owner_id` for documented generator-owned fields.
7. **Initial scalar subset proposal:** `str`, `text`, `int`, `float`, `bool`, `Decimal`, `decimal`, `datetime`, `EmailStr`, `email`, `uuid`. Reject unknown types, `?`, nested maps, relationships/constraints beyond descriptor, `json`, business `password`, `url`, and `date` until qualified end-to-end. `json` lacks schema mapping; `url` uses Pydantic HttpUrl versus SQL string; `date` ORM emits `datetime.date` after `from datetime import datetime` (`model.py:179–180,244–245`). These are concrete repair/extension points, not grounds to stringify input.
8. **Visible defaults:** UUID PK; timezone timestamps; Decimal precision 12/scale 2; string length 255, text input max 65,535, email API max 255 versus DB 320; nonnegative numeric inputs, int upper bound 2,147,483,647; extra fields forbidden but Pydantic coercion allowed; partial-update fields nullable in input while persisted required fields remain non-null. Expose those differences; reject application requirements incompatible with them.
9. **Convention-triggered behavior:** declare and test `_id` inference only for actual model targets and UUID fields, CASCADE behavior, migration ordering, rating/payment uniqueness/sensitive-field conventions; reject those special forms until parity is established. `owner_models` keys must exist, value initially exactly `"user"`, auth required; `shared_models` unique subset of owner keys. Reject dangling/custom owners and ownership without auth before generation. Remove automatic `OrderItem` injection from qualified path.
10. **Profiles:** publish explicit admitted profile/auth/effect matrix, including empty models. Candidate baseline: minimal/worker with auth false, api/full with explicit true or false; other overrides block until qualified. Full needs generation-only treatment of operational phases, with missing SBOM/lock verification honestly listed as remaining work. Do not silently claim existing full operational phases completed. Lead ratifies matrix/subset before implementation; supported full/minimal/worker paths must each have positive witnesses.
11. **Canonical result:** preserve `tool`, `status`, `producer`, `artifact_kind`, recoverable `artifacts`, `planned_files`, `observed_changes`, `effects` plus inventory completeness, `requirements`, `remaining_work`, actual `checks`, and structured `error`. Status is exactly `previewed|generated|blocked|failed|interrupted`; planned paths never become observed writes, AST success never becomes import/behavior success.
12. **Named errors:** `INVALID_INPUT`, `CAPABILITY_UNAVAILABLE`, `SELECTION_UNAVAILABLE`, `UNSUPPORTED_OUTPUT`, `OUTPUT_CONFLICT`, `PERMISSION_DENIED`, `PRODUCER_FAILED`, `INVALID_PRODUCER_RESULT`, `CANCELLED`, `TIMEOUT`. Preserve producer phase, raw mode, bounded original message/structured MCP payload, artifact references and known/unknown effects. Q supplies named failures instead of bridge parsing prose; malformed/contradictory payload fails closed without replay.

## Preparation, inventory, publication and interruption

- Introduce one producer-owned `PreparedArtifact` seam used by both operations: immutable file bytes, relative paths/modes/raw byte hashes, producer+contract/catalog identity, exact normalized request, artifact kind/raw mode, conventions, requirements, phase/check outcomes and declared effects. This is bounded generation data, not a new durable execution system.
- Compose prepares source in memory. Scaffold prepares in fresh host-managed staging with qualified, explicit temporary-write boundary and confined generation paths. Destination remains bound to actual worktree/project; staging permission must not be inferred from caller `output_dir` or forged identity fields. Avoid process-global `chdir` as isolation. Suppress incidental bytecode writes in launched producer.
- Native non-preview flow: bind → validate/capability check and preparation authority → prepare → validate actual artifact and effects → native grant for declared publication → revalidate destination → publish **that artifact**. Preview stops at same prepared artifact and exposes actual recoverable source/bundle, not planned filenames alone.
- Freeze internal `prepare_compose`, `prepare_scaffold`, `publish_prepared` call shapes under versioned producer binding. Across separate preview/publication calls, use host-owned immutable artifact reference tied to original request/producer/destination; caller cannot supply arbitrary trusted files or authority. Changed selection/destination/version, expired/missing reference or hash mismatch blocks. Never regenerate after preview and claim equal bytes; no cross-call artifact reuse implied by legacy `dry_run` alone.
- Validate every manifest entry: relative confined path, unique/case-compatible name, regular file, valid byte hash/mode; reject absolute/`..`/symlink entries. Reconcile complete staged tree against manifest, including hidden files and chmod effects. `.hugr-scaffold-manifest.json` is a narrow doc hash set, not this inventory (`scaffold_manifest.py:37–56`).
- Publication is create-only at actual open/create operation, with supported-platform no-follow/anchored-directory handling and exclusive creation. Compose may preserve existing initializer; intended module must be absent. Scaffold target must be absent or empty; fail unexpected content. Preflight followed by overwrite/replace is insufficient. Never merge populated applications or replace user files.
- Multi-file publish can partially succeed. Track each created path/hash plus created directories and unexpected changes, retain recoverable artifacts. Permission/conflict before writes → blocked; producer/contract failure → failed; cancellation/timeout → interrupted with original error. Effects are `none|observed|partial|unknown` and explicitly state inventory completeness; failed observation never becomes empty-success inventory.
- Cancellation must stop preparation/publication and await/quiesce producer work before reliable final observation. Account for child processes, not merely rejected MCP Promise. Lost reply or process death after writes retains observed/unknown effects. Preserve `{retry:false}` for all publication/mutating calls, including reconnect. Reconcile artifacts before a fresh caller-authorized attempt; existing files conflict, not fabricated idempotent success.
