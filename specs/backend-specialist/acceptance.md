## How to read this

Path prefixes: **O** `packages/orchestra`, **C** `packages/core`, **P** `packages/plugin/src`, **A** `foundation/atlas`, **SK** `packages/backend-specialist/skills`, **B** the `gustavomhss/backend-bench` repository. Runs are `https://github.com/gustavomhss/hugr-orchestra/actions/runs/<id>`. Merge SHAs were checked with `git cat-file` and `gh pr view`. Test presence is not test execution: a test counts only where a run is cited.

Status words:

- **qualified**: the cited observation happened, and only that.
- **source-only**: code and tests inspected, no matching recorded execution.
- **closed**: the cited PR has its own proof run and landed in `dev` through the close-out integration #289 (merge `524f8ec626`, epic CI green).
- **landing**: the PR is open and its evidence is not complete; the clause stays open.
- **unqualified / refused**: a required observation is missing, or the interface refuses it on purpose.

Still unconfined when the profile allows the fallback (reported as `shellWrites: unenforced`), and refused otherwise: Git Bash, Windows PowerShell 5.1 and any other program; missing write roots; denied or protected paths inside a granted tree (a deny ACE for the profile did not hold); allowed domains; globs; hosts without the omni supervisor. **Git via host** (owner decision 2026-10-11; C/src/tool-safety-git-host.ts): git cannot start inside the AppContainer (it opens NUL), so a command line that is exactly one plain `git` call runs on the host when it is read-only: status, diff, log, show, rev-parse, rev-list, ls-files, grep, blame, branch/tag listing, remote -v, describe, cat-file, merge-base, each with a closed option list. Host git runs only when the git directory and its common directory lie outside every write root (a linked worktree; a `.git` file must be named by git's own back-link), with explicit `--git-dir`/`--work-tree`, `--no-pager --no-optional-locks`, `-c` overrides for fsmonitor, hooksPath, pager, external diff, gpg programs, signature display, credentials, protocols and submodule recursion, `--no-textconv --no-ext-diff`, every `GIT_*` variable replaced, and the real git from a PATH folder outside the workspace. Writing subcommands, aliases, global options (`-c`, `-C`, `--git-dir`, `--exec-path`), file-writing or file-reading options, and git inside a compound command stay confined: the single calls fail with a `git-host-*` HOLD, compound ones with git's own `could not open '/dev/null'`. Limits: filter drivers (clean/smudge/process) cannot be overridden by name, so status, diff, blame and grep still run the filters the user's own config defines (git-lfs); that is why a workspace-held git directory never runs on the host. The system config stays read (it holds Git for Windows' `core.autocrlf`; without it a fresh CRLF checkout shows every file modified, measured). Host git follows directory junctions in the work tree (measured); a confined command cannot create a junction, symlink or hard link to a path outside its grants (measured), so only links the user made are followed.
