# Atlas — interactive design preview (v4)

The screens follow [`../DESIGN.md`](../DESIGN.md): one job per screen, three layers (visible, one tap, Technical details), plain words with the Atlas term on hover. Every field comes from [`../INVENTORY.md`](../INVENTORY.md).

- **Overview:** is Atlas fine, and what needs me.
- **Knowledge:** units; a unit's briefing, facts by kind, proven structure, connections; a fact's history.
- **Review:** changed code (with the merge check), mined suggestions (accept all, result per row), proposals to ratify.
- **Activity:** what agents read, saved and were held on, from the session receipts.
- **Health:** store access, stored objects, proofs, code index, versions.
- **Settings:** connection, territories, permissions, store.
- **Memory:** per member: project memory and the memory log.

The data is real. `data-real.js` is generated by `extract.py` from the Atlas store over its own code (`~/Documents/HuGR/atlas/.atlas`). Two parts are not read straight from the store:

- **Drift and its diffs** come from git: the change to each fact's file between the commit it was derived at and HEAD.
- **"Depends on this"** comes from import statements, standing in for the SCIP dependency axis.

That store sits in the standalone Atlas repository, which commits its projection and content store. Current Atlas therefore treats it as tracked: it would serve none of these facts (none is sealed) and refuse every write. "Real store only" says so on the Overview and in Settings › Store; Illustrated mode assumes an untracked store so curation can be shown working.

Memory is real too. `extract-spawns.py` turns the five live continuity runs in `specs/backend-specialist/evidence/continuity-live-2026-10-10` into `data-spawns.js`: Backend's task units with every invocation, the seat transcript, the checkpoints (refused ones too) and the checkpoints Atlas handed back on resume. The Awareness facets and the empty orientation reflect what the code produces today.

**Illustrated mode** is the default, and "Data" in the top bar switches it off. It adds what a working Atlas would hold after some stewardship, marked `example` in `data-illustrate.js`:

- slot types on the real facts;
- T1 and T0 ratifications, and four proposals waiting;
- seven territories with owners and tiers;
- seeded Awareness (the `taste` and `constitution` top lines);
- project-memory rules aged by their position in the shared log, PR entries, a plan that pins Own units, and task logs for Archie and Jimmy.

"Real store only" shows the store exactly as it is.

Actions are simulated. They update the screens and can be undone, and they never touch a store.

## Open it

Open `index.html` in Chrome; it works from disk (`file://`). Or serve the repository root and open `http://127.0.0.1:4791/specs/atlas-ui/mock/index.html`:

```bash
python3 -m http.server 4791 --bind 127.0.0.1
```

To regenerate the data, run this from the repository root:

```bash
python3 -I specs/atlas-ui/mock/extract.py specs/atlas-ui/mock/data-real.js
```

The page links the app's real chapter kit, the Relay parts, the fonts and the brand assets.

## Interaction

- Every screen is a URL. An open fact is `?fact=<nodeKey>`.
- `⌘K` searches facts, files, areas, memory and pages.
- In lists, `j` and `k` move and `Esc` closes the fact panel.
- `g` plus a letter jumps between screens. Press `?` to list the shortcuts.
- "All screens" lists every view. Use "State" in the top bar to see the index building and Atlas not connected.
