# Atlas — interactive design preview (v3, real store)

This preview shows the Atlas screens built on the model in [`../ATLAS-MODEL.md`](../ATLAS-MODEL.md). They follow the parts of the Atlas itself:

- **Map:** the spatial index and the scope briefing.
- **Knowledge:** the facts.
- **Curation:** the governed write path.
- **Memory:** per member.
- **History:** generations and drift.
- **Settings:** territories, write policy, index and store.

The data is real. `data-real.js` is generated by `extract.py` from the Atlas store over its own code (`~/Documents/HuGR/atlas/.atlas`). Two parts are not read straight from the store:

- **Drift and its diffs** come from git: the change to each fact's file between the commit it was derived at and HEAD.
- **"Depends on this"** comes from import statements, standing in for the SCIP dependency axis.

The one memory record is real test evidence from `specs/backend-specialist/evidence/`. The Awareness facets and the empty orientation reflect what the code produces today.

Curation actions are simulated. They update the screens and can be undone, and they never touch a store.

## Open it

Open `index.html` in Chrome; it works from disk (`file://`). Or serve the repository root and open `http://127.0.0.1:4791/specs/atlas-ui/mock/index.html`:

```bash
python3 -m http.server 4791 --bind 127.0.0.1
```

To regenerate the data, run this from the repository root:

```bash
python3 -I specs/atlas-ui/mock/extract.py specs/atlas-ui/mock/data-real.js
```

The page links the app's real chapter kit, the Relay parts, the fonts and the brand assets.

## Interaction

- Every screen is a URL. An open fact is `?fact=<nodeKey>`.
- `⌘K` searches facts, files, areas, memory and pages.
- In lists, `j` and `k` move and `Esc` closes the fact panel.
- `g` plus a letter jumps between screens. Press `?` to list the shortcuts.
- "All screens" lists every view. Use "State" in the top bar to see the index building and Atlas not connected.
