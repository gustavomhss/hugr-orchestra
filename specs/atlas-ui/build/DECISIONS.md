# Atlas UI build: decisions

Every decision is made here, before any task runs. A worker never chooses: if a brief leaves a choice open, the worker stops and reports it (see [README.md](README.md), "Worker contract"). The mock in `specs/atlas-ui/mock` is the reference for every screen, string and derivation; `specs/atlas-ui/DESIGN.md` explains it and `specs/atlas-ui/REQUIREMENTS.md` defines R1–R11.

## Architecture

**D1. Orchestra reads Atlas in process, through the boundary package.**
- Orchestra already talks to Atlas only through `@orchestra/atlas-boundary` (`modules/atlas/boundary`), a bundle of Atlas entry files.
- The build adds one more entry, `./surface`, bundled from a new Atlas module, `modules/atlas/packages/adapter-io/src/surface/index.ts`.
- Not chosen: spawning the atlas CLI (it prints text, not JSON, and no binary ships with Orchestra) and Atlas's MCP server.

**D2. The surface module is the only new Atlas API the UI uses.**
- It exposes `openSurface(repoPath)`, which returns plain JSON-serializable data and write results.
- It is built on `composeRuntime(repoPath)` (`adapter-io/src/compose.ts:163`) and the store readers. It never edits `compose.ts`, which has no line room under the godfile cap.

**D3. The snapshot shape is the mock's real-data shape.**
- `surface.snapshot()` returns exactly the object `specs/atlas-ui/mock/extract.py` writes to `window.Atlas.real`: the same keys, types and meaning. The DTO type `AtlasSnapshot` is transcribed from it in task A01.
- Three differences:
  - `reasoning` is not in the snapshot. It is fetched one entry at a time with `surface.reasoning(id)`.
  - `dependents` and `dependentCount` come from the Atlas code index (`.atlas/index.scip`, through the same dependency axis `own` uses), not from an import regex. With no index, both are `{}` and `scip` is `false`.
  - The backend-label scrub in extract.py is not ported; the UI never prints that label.

**D4. HTTP goes through a legacy Orchestra httpapi group named `atlas`.**
- It copies the `project.lean` pattern: `packages/orchestra/src/server/routes/instance/httpapi/groups/project.ts` for the endpoint declaration, `handlers/project.ts` for the handler, `WorkspaceRoutingQuery` for the directory.
- `packages/server` cannot import the boundary, so the V2 protocol is not used here.
- The client calls `sdk.client.atlas.*`, generated by `packages/sdk/js/script/build.ts`. Generated files are never edited by hand.

**D5. The Atlas store for a request is at the instance worktree.**
- `repoPath` is `Instance.worktree`, or `Instance.directory` when the worktree is `/`. This is the same rule as `maestro/atlas-memory.ts:89`.
- With no `.atlas/` there, every read returns `{ state: "empty" }`, and the UI shows its empty state.

**D6. Live refresh, phase A.**
- The page refetches the snapshot after every write it makes, on window focus, and from a Refresh button.
- No file watcher and no new server event in phase A; the file watcher is off by default.

## App

**D7. One chapter, `atlas`.**
- The chapter is registered in `packages/app-shell/src/orchestra/chapter-route.tsx` `chapterPages`, with a single entry in `navigation.ts`.
- Sub-views ride the `*rest` route segment, like Relay:
  - `overview`, `explore`, `unit/<path>`, `fact/<key>`, `review`, `activity`
  - `genesis`, `architecture`, `ownership`, `how`
  - `memory/<seat>`
- The mock's grouped sidebar (Atlas · Engine · Memory) becomes an in-page sub-navigation rail inside the chapter. The global sidebar is not changed.

**D8. Files live under `packages/app-shell/src/orchestra/chapters/atlas/`.**
- `atlas.tsx` is the page.
- `atlas-api.ts` is the transport.
- `atlas-controller.ts` holds state with `createStore`.
- `atlas-model.ts` is a pure port of `mock/model.js`.
- `atlas.css` ports `mock/atlas.css`.
- `kit/*.tsx` ports `mock/ui.js` helpers.
- `views/<view>.tsx` holds one file per sub-view.

**D9. Copy.**
- Every visible string goes through `language.t`.
- The keys live in one file per view, `packages/app-shell/src/i18n/orchestra-chapters/atlas-<view>.ts`, spread into `atlas.ts`, which `i18n/orchestra.ts` spreads once.
- Key prefix: `orchestra.atlas.<view>.<name>`.
- Strings are copied verbatim from the mock.

**D10. Tokens.**
- Use the real `--mx-*` tokens from `chapters/kit.css`.
- `--mx-warm` is defined in `atlas.css` with relay's values: dark `#c9b78f`, light `#846f45` (`relay/relay.css:7,27`).
- The mock's `--at-*`, `--hold`, `--some` and `--much` move into `atlas.css` unchanged.

**D11. Libraries.**
- Add `force-graph@1.43.5`, `d3-hierarchy@3.1.2` and `d3-shape@3.2.0` to `packages/app-shell` dependencies.
- Import them dynamically, inside the view that needs them. No CDN.

**D12. Illustrated data is not shipped.**
- The mock's Illustrated mode, `data-illustrate.js` and `data-spawns.js` stay in the mock.
- The real screen shows real data only. Where real data is empty, it shows the mock's real-mode empty text.

**D13. New capabilities stay marked until their track lands.**
- A control that needs R1–R11 renders exactly as the mock's real mode: the `New capability · Rn` marker, and a toast instead of the action.
- Track C replaces each marker with the working action.

## Engine

**D14. One shared review log for R1, R2, R3 and R11.**
- The log is `.atlas/review.jsonl`: append-only, one JSON record per line, content-keyed like `memory.jsonl`.
- It travels in git:
  - add `!.atlas/review.jsonl` to `modules/atlas/.gitignore` and to the repository `.gitignore` rule that mirrors it;
  - add `.atlas/review.jsonl merge=union` and `linguist-generated=true` to `.gitattributes`.
- Record kinds, all with `id` (the content hash through the kernel hash seam), `at` (ISO time) and `by` (actor):
  - `hold` {nodeKey}, `release` {nodeKey}
  - `proposal` {nodeKey, toTier: "T1" | "T0", reason}
  - `decision` {proposalId, verdict: "ratified" | "rejected", reason}
  - `answer` {questionId, answer, drafted?: {model, why}}
  - `memory-proposal` {member, rule, scope}
  - `memory-decision` {proposalId, verdict: "indexed" | "discarded", rule?, scope?}
- Folding rules:
  - the latest `hold`/`release` per nodeKey wins;
  - a proposal is open until it has a decision;
  - a memory proposal is open until it has a memory-decision.
- The log's module is `modules/atlas/packages/adapter-io/src/review-log.ts`: `appendReview`, `readReview` and `foldReview`.
- Staging, `StoreProjection` and the sidecar wire format are not changed. `cli/test/mine-projection-surface.test.ts` stays green.

**D15. R2.**
- `atlas promote [nodeKey...]` promotes only the given keys; with none it promotes all staged rows, as today. Held rows are always skipped.
- `atlas hold <nodeKey>` and `atlas release <nodeKey>` write review records.
- The positional threading goes through `cli-dispatch.ts`. `cli.ts` gets room by moving its promote/own intercept block into `cli-dispatch.ts` first (task B-R2-01).

**D16. R3.**
- Three commands:
  - `atlas propose <nodeKey> <T1|T0> <reason...>` (`--by` is required);
  - `atlas proposals`, which lists the open ones;
  - `atlas decide <proposalId> <ratify|reject> <reason...>`.
- Ratify re-emits the fact at the target tier through `governed-emit`, with `ATLAS_RATIFY_TOKEN`. T0 still needs the `billy` ratifier.
- Reject only writes the decision.

**D17. R11.**
- `deriveOpenQuestions` lives in `modules/atlas/packages/genesis/src/open-questions.ts`. It builds `OpenQ[]` from the store, with the same four kinds and rules as the mock's `interview()` in `mock/views-explore.js`:
  - `owner`: a unit with no territory owner.
  - `tier`: a T2 fact whose slot is invariant, contract or security-property.
  - `contested`: two live facts with the same file and the same slot.
  - `intent`: a unit with no rationale fact.
- Rank = blast × tier weight (T0 3, T1 2, T2 1), where blast is the dependent-file count from the index.
- `atlas interview` prints the `assembleInterview` batch and the deferred count; `--json` prints `{batch, deferred}`.
- `atlas answer <questionId> <answer...>` writes an `answer` record.
- A `tier` answer of T1 or T0 also writes a `proposal`, so ratification still goes through R3 and a person.
- Answered questions drop out of the next batch.
- The `align.ts` row is removed from `harness/gates/reference-model-guard.mjs` and the header count is updated.

**D18. R1.**
- `atlas_memory_emit` with kind `project` stops writing the rule. It appends a `memory-proposal` instead and tells the member it waits for the steward.
- `memory.jsonl` then holds only indexed rules, so the header and the cap gate stay unchanged.
- Indexing goes through a host action (Track C) that writes the rule as the member, through `createNativeMemory().write`.

**D19. R6.**
- Retired means the CAS fact's `authoring` is `SUPERSEDED`.
- One predicate, `isRetired(fact)`, goes in `modules/atlas/packages/knowledge/src/retired.ts`.
- It is applied at the four read points: scope pack, dependency/trigger query, own bands, constitution facet. Each reads the fact bytes from CAS. No row carrier is added.

**D20. R8.**
- `WriteRequest.replace?: true` replaces the claim set on a same-tier update, with provenance pruned the same way the raise path prunes it.
- `atlas emit --replace` sets it. T0 keeps requiring `billy`.

**D21. R7.**
- `atlas own-export <unit...> --out <file>` builds the reviewed-snapshot input from the live store with `buildOwnSources`.
- `exportOwnSnapshot` names every unit and fact that is not FRESH in its refusal.

**D22. R4.**
- `atlas territory <name> <glob...>` (`--owner` is required) writes `TERRITORY-CATALOG.json` through `publishTerritoryCatalog`, tier `human-ratified`, and only with `ATLAS_RATIFY_TOKEN` set.

**D23. R5.**
- `NativeMemory.listResumable(member)` lists the member's own task records: eventId, task, refs, at.
- `AtlasResume.admit` accepts an explicit `RecordRef`.
- The host route that dispatches the resume is Track C.

**D24. R9.**
- `own-snapshot-guard` gains `--worklist <file>`, which writes `{units: [{unit, stale: [path]}]}`, sorted.
- New command: `atlas repair --worklist <file>`. It runs own-export for those units, then `scripts/materialize-own-snapshot.mjs`, then commits on branch `atlas-repair-<short sha>` and runs `gh pr create`.
- It runs where the store exists, on a maintainer's machine or the maintenance seat. CI has no store.
- New workflow `.github/workflows/atlas-worklist.yml`: on push to `dev` and on dispatch, it uploads the worklist as an artifact.

**D25. R10.**
- New workflow `.github/workflows/atlas-guard.yml`, on `pull_request` opened, synchronize and reopened. Steps:
  1. Compute the changed files.
  2. Exit 0 unless they touch `OWN-SNAPSHOT.json` `sourceBlobs` paths, the snapshot itself, or `.orchestra/skills/own/**`.
  3. `npm ci` in `modules/atlas`, then build retrieval with `npx tsc -b packages/retrieval`.
  4. `npm run own-snapshot-guard`.
- Making the check required is a branch-protection setting. The owner turns it on; no task does it.

## Process

**D26. Three tracks.**
- **A** (UI over today's Atlas) and **B** (engine R1–R11) touch disjoint files and run in parallel.
- **C** (wire R1–R11 into the surface, the server and the UI) starts after A and B have both merged.
- The boundary's generated files are regenerated only in tasks that say so: A06 in track A, then C01 in track C. Track B never regenerates them.

**D27. Model routing.**
- `opencode-go/deepseek-v4.1-flash` takes mechanical tasks: registrations, copy files, CSS ports, docs pages, ledger edits, workflows.
- `opencode-go/beam-free` takes tasks with logic: surface reads, views, engine changes.
- Always with `--variant max`.

**D28. Verification.**
- Workers never run tests, typecheck or builds on the Mac.
- Each task's acceptance is a `bun run test:ci ...` or a typecheck workflow dispatch, run by the lead after the task.
- Atlas package tests run in the `atlas` CI job (`npm test` under `modules/atlas`, vitest), started by the `epic` label or by dispatch.
