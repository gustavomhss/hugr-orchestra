# @orchestra/maestro

Maestro coordination: the seat roster and seats, governance records and the Arsenal native safety contribution.

## Purpose and ownership

- Seats are named by id, never by display name. `src/roster.ts` is the roster; `src/seats` defines each seat (`archie`, `backend`, `billy`, `frankie`, `jimmy`, `live`, `lucy`, `patty`, `rosie`) with its prompt in `src/seats/prompt`.
- `src/v2` holds the V2 tools, seats service, workflow and governance code; `src/arsenal-*.ts` is the Arsenal contribution; `src/governed-task.ts`, `src/approval.ts` and `src/work-contract.ts` define governed work.
- `playbooks` holds the Maestro playbooks (`maestro-orchestra`, `maestro-plan`, `maestro-run`, `maestro-repo`, `frame-request`).

## Public entry points and consumers

- Export keys include `./roster`, `./seats`, `./governed-task`, `./approval`, `./arsenal-native`, `./v2/seats` and `./seat-skills-module`; `package.json` lists them all.
- `apps/cli/src/host.ts` registers `MaestroSeatsV2`; `apps/cli/script/packaged-skills.ts` and `apps/cli/script/build.ts` embed the playbooks and seat skills.

## Dependencies and boundaries

Layer `product`: it may import foundation, native, library, contract, extension-api, module, platform and product packages, never composition or app packages.

## Assets, schemas and generated files

- Seat prompts (`src/seats/prompt/*.txt`) and playbooks ship with the product. The CLI build embeds seat skill trees through `src/seat-skills-module.ts`.
- `modules/maestro/coordination/script/seat.ts` scaffolds a new seat's source files.

## Persistence, identity and lifetime

- None of its own. `src/v2/governance/records.ts` reads governed-chain event rows through the core database and never writes them; the host owns persistence and process lifetime.

## Commands

- `bun run test:ci maestro` from the repository root, or name files such as `bun run test:ci maestro test/roster.test.ts`.
- `bun typecheck` in this directory.

## Contracts and verification limits

- `test/specialist-name-guard.test.ts` fails when the backend seat's default display name appears outside `src/roster.ts`.
