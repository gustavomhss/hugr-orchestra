# @orchestra/engine-claude-code

The Claude Code engine adapter: SDK process lifetime, executable lookup, transcripts and host options.

## Purpose and ownership

- `src/sdk.ts` is the single spawn seam (`processLifetime`) and keeps the `claude_code` preset. `src/executable.ts` finds the executable and reads the SDK pin from this manifest. `src/transcript.ts` and `src/host/options.ts` cover transcripts and host options.
- `src/v2/host.ts` is the V2 `ExecutionHost`: Orchestra runs on Claude Code as a meta-harness (short preset append, context through the `UserPromptSubmit` hook, seats dispatched through Orchestra's `task` as child Sessions, as in normal mode). `src/v2/account.ts` and `src/v2/login.ts` handle the account and login.
- See `docs/specs/claude-mode/meta-harness.md` and `.orchestra/skills/claude-mode-maintenance`.

## Public entry points and consumers

- Export keys `./sdk`, `./executable`, `./transcript`, `./host/options`, `./v2/host`, `./v2/account` and `./v2/login`.
- `apps/cli/src/host.ts` registers `ClaudeCodeHost`.

## Dependencies and boundaries

Layer `product`: it may import foundation, native, library, contract, extension-api, module, platform and product packages, never composition or app packages.

## Assets, schemas and generated files

- No generated files. The Claude Code SDK version is pinned in this package's `package.json`.

## Persistence, identity and lifetime

- None of its own; the host owns persistence and process lifetime. Each SDK process lives for the scope that spawned it.

## Commands

- `bun run test:ci engine-claude-code` from the repository root; `test/preset-guard.test.ts` checks the preset rule.
- `bun typecheck` in this directory.

## Contracts and verification limits

- Governed Maestro tools (`maestro_*`, except `maestro_arsenal_*` and `maestro_workflows`) are refused until `maestro-run-governed` loads through `mcp__orchestra__skill` in the same session. The loaded flag lives in process memory and resets on restart.
