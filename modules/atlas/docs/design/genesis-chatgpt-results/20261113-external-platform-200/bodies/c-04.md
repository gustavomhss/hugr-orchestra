## P102 — docs/guides/omni.md

**Blob:** `bfaf9807bf5d42a4f6c6096ab19342e2b6d8fd9d`. **Natureza:** guia de camada nativa e seus limites documentados.

Descreve addon que inicia supervisor separado no primeiro uso, passa PID do host e usa canal privado com frames de até 1 MiB. O supervisor é dono de até 4096 árvores; Unix usa session leader e mecanismos de observação de PID/host, Windows usa Job object e named pipe. Stop tem grace, sinais apropriados para processo/PTY e escalada; a morte do host aciona limpeza e sweep. O relato de 25 mortes sem sobreviventes e tempos de parada é histórico, não benchmark desta entrega.

O comportamento do switch é parte do contrato: unset/1 usa Omni e faz fallback de opções ainda não suportadas; strict as recusa; 0, vazio ou inválido usa legado, com warning para inválido. Builds sem suporte também vão para legado. As plataformas documentadas incluem macOS, Linux glibc e Windows x64, enquanto musl/Windows ARM ainda aparecem planejados. A presença de instalador de uma plataforma no changelog não prova por si a disponibilidade de Omni nessa plataforma.

Os limites são claros: processo Unix que cria outra sessão pode escapar e matar o supervisor deixa árvores Unix vivas. O guia declara exceções de spawn existentes e suite de conformidade, mas condiciona garantia à passagem do cenário em CI. A descrição de pumps/8 MiB não permite concluir bounded memory universal do sistema só pelo texto.

**Evidências:** L3–26 — finalidade, arquitetura, shutdown e saída; L28–39 — plataformas e switch; L41–46 — escapes, allowlist e maturidade.

**Limites:** não houve leitura extra de native/omni, testes de árvore, conformance ou CI. Números de sites e cenários são contagens declaradas no guia. Não se transfere PASS histórico para o baseline.

## P103 — docs/guides/workspaces.md

**Blob:** `05cfa98531ea2a0b954191c1e761db7273fb438e`. **Natureza:** guia de gerenciamento de worktrees.

Cada workspace é apresentado como worktree Git com branch própria. A página exige projeto Git e exibe nome, branch, local/sandbox e ativo/ocioso. Escolher workspace muda onde começam novos drafts; se ficar inválido, o fallback de drafts é a raiz do repositório. Criar exige diretório pai e nome sem barras, produzindo outra branch. Nome de exibição é local ao perfil e não renomeia diretório nem branch.

Exclusão remove worktree e arquivos e não é oferecida para raiz ou workspace ativo. A confirmação adicional de mudanças não commitadas distingue remoção normal de descarte de trabalho; servidor sem capacidade de remover diretório dá encaminhamento específico. Estados vazios/falhos separam loading, nenhuma entrada, retry, funcionalidade indisponível e diretório sem Git. “Indisponível neste servidor” não deve induzir retry inútil.

**Evidências:** L3–20 — modelo, seleção e criação; L22–30 — configuração e exclusão; L32–45 — estados e perdas possíveis.

**Limites:** worktree separa diretórios/branches, sem provar isolamento de todos os recursos externos ou ausência de disputa entre agentes. Não houve criação, remoção ou troca de workspace. O nome de perfil não é metadado compartilhado.
