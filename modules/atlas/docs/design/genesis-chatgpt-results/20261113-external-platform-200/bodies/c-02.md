## P011 — .dockerignore

**Blob:** `487e9eb94ae2a3df6f55310fe6225f5e63f66bb2`. **Natureza:** filtro de contexto Docker.

**Evidências:** L1–12 — lista completa de exclusões.

## P013 — .gitattributes

**Blob:** `ab990df12bf47e70e5033bdeecb0db030b391902`. **Natureza:** atributos Git de transporte e apresentação.

O arquivo distingue três necessidades. Marca snapshots e migrações como gerados para apresentação; mantém fixtures gravadas e bundles de fronteira Atlas com `-text` para preservar bytes; fixa LF em skills embarcadas, prompts, playbooks, paletas, fixtures HttpApi, clientes gerados e schemas. Mantém padrões legados e pós-reestruturação lado a lado, cobrindo tanto `packages` antigos quanto destinos em `modules`/`tooling`.

Para JSONL sob `.atlas`, declara `merge=union` porque o formato documentado é append-only e cada linha seria um registro inteiro com chave de conteúdo; também os marca como gerados. A justificativa remete ao atributo do módulo para efeitos da ordem. Há ainda `-text` para evidência e contratos Genesis congelados, pois sua identidade usa SHA-256 dos bytes. Isso protege normalização de checkout, não concede exceções de renomeação nem valida semanticamente o material.

**Evidências:** L1–13 — gerados, fixtures e união; L14–39 — texto embarcado e derivados; L40–48 — preservação de contratos congelados.

**Limites:** `merge=union` não prova deduplicação, coerência causal, ordem correta nem resolução semântica de registros. O atributo define tratamento Git; não demonstra que os arquivos correspondentes existem ou que seus geradores foram executados.

## P200 — turbo.json

**Blob:** `c375d67bc4b2738991a62994d3a81e01cdc7c639`. **Natureza:** grafo declarativo de tarefas e identidade de cache.

O problema central documentado é cache de testes que permanecia válido após mudança em dependência workspace sem build. A tarefa transit encadeia `^transit`, fazendo o grafo de dependências participar dos hashes sem executar build. Typecheck depende de transit; build declara dist e não acrescenta predecessores. Testes ganham transit e, em alguns casos, `^build`. Omni transit inclui explicitamente fontes Rust e toolchain externos ao pacote JS.

Inputs globais incluem controles de teste, registries e skills embarcadas; variáveis globais separam as que entram no hash das encaminhadas. Exceções materializam dependências não expressas no package graph: core lê helpers/workflows e testes CLI, app depende também de web transit, CLI lê verificador desktop e fontes/skills Maestro, script incorpora registries, resolvers, inventários, recuperação e distribuição. Seu typecheck inclui fontes raiz e dependências pontuais fora do workspace.

Todos os testes explicitamente listados têm outputs vazios. Core preserva e considera `PSModuleAnalysisCachePath`, com justificativa de descoberta fria do PowerShell. CLI encaminha todas as variáveis para suites de binário, conforme comentário, mas isso não implica que todas sejam hash inputs. Os demais testes nomeados, incluindo client/schema/protocol/server/sdk-next/TUI/desktop, usam transit sem build adicional neste arquivo.

**Evidências:** L3–37 — identidade global e transit; L38–83 — core/app/CLI e ambiente; L84–138 — testes e typecheck do script; L139–200 — restantes das tarefas.

**Limites:** o arquivo não prova que dependências externas estejam completas, que comandos existam ou que um cache observado tenha invalidado corretamente. Pass-through de ambiente difere de participação no hash. Nenhuma tarefa, pacote Omni ou workflow citado foi executado ou expandido nesta unidade.
