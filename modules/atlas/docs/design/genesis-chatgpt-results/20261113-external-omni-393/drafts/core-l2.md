## 1. Host preparation, generations and ownership

The host materializes a `Spec`: validated options, final child environment, absolute cwd, resolved executable and the caller's original `argv[0]` remain separate. Resolution is not a shell expansion mechanism. `prepare` queries environment and filesystem state despite its “pure” terminology; its useful boundary is that it does not start the target process. The final child PATH controls lookup. [spawn/mod.rs, 104–126](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/spawn/mod.rs#L104-L126)

A lazy library-owned Tokio runtime carries channel work, output pumps and lifetime tasks independently of the caller runtime. Creator PID checks reject forked copies, and tree Drop avoids locks and supervisor commands outside its home process. Startup is shared among concurrent callers through a generation registry; later attempts can use a fresh generation after failure, while existing trees remain tied to the old one. Request admission reserves separate room for cleanup: 1024 normal pending requests, with cleanup permitted through 8192. Generation death settles pending requests and marks trees lost rather than silently attaching them to a replacement supervisor. [client/mod.rs, 65–92 and 264–275](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/mod.rs#L65-L92), [client/channel.rs, 277–375](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/channel.rs#L277-L375), [client/start.rs, 61–88](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/start.rs#L61-L88)

Supervisor lookup is an operational trust boundary. The Windows module-directory `trusted` function returns true and documents an assumption about per-user temporary extraction; it performs no ACL inspection. That assumption is a declaration, not something proven by the function. Linux stuck-supervisor termination requires a checked pidfd; missing identity can mean explicit abandonment. macOS checks NOTE_EXIT and start time but documents a residual check-to-signal PID reuse window. [client/start.rs, 279–285](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/start.rs#L279-L285), [client/keeper.rs, 119–139 and 229–245](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/keeper.rs#L119-L139)

## 2. Root exit, tree settlement and Release are different events

| Event | Observed meaning | Consequence for callers |
| --- | --- | --- |
| Root exit | Native status is available; descendants can remain. | `wait` and output EOF do not establish whole-tree cleanup. |
| Stop | One shared deadline targets the tree; concurrent requests retain the earliest deadline. | A later long grace does not extend an earlier short stop. |
| Release | The host no longer addresses that tree ID. | Cleanup duty and identity protection can remain until the tree ends. |
| Windows gone transition | Root exited, Job active count is zero, and member proof succeeded **or its one-second bound elapsed**. | `Stopped` can carry an unresolved per-member proof through a diagnostic-only fallback. |

The Windows tree owns a noninheritable Job with kill-on-close and no breakaway flags. The root is born with `JOB_LIST`, avoiding a runnable-before-assignment interval. The Job closes before `Stopped`; the root process handle continues pinning its PID until the released record is dropped. Root-exit handling and Release do not simply destroy all records. [windows/job.rs, 21–43](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/job.rs#L21-L43), [windows/create.rs, 27–103](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/create.rs#L27-L103), [windows/tree.rs, 75–158](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/tree.rs#L75-L158)

The stronger Windows membership proof uses completion-port births, a flush marker after emptiness, reconciliation of notification count with Job `TotalProcesses`, and identity-aware probes. A missing birth or uninspectable process remains Unknown within `Members`; `Tree::settle` makes the explicit bounded fallback decision. Unknown **Job active count** is still not treated as zero on this normal path. The unit tests intentionally blind a probe and suppress a notification to assert that fallback and its diagnostic. [windows/members.rs, 152–220](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/members.rs#L152-L220), [windows/tree.rs, 126–158](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/tree.rs#L126-L158), [windows/tests/mod.rs, 254–293](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/tests/mod.rs#L254-L293)

CORE's Unix supervisor coverage here consists of its assigned tests, not the support-only Unix implementation. Those tests demand unreaped-root pinning while session members survive, retained cleanup after Release, whole-session inventory across process groups, and refusal to confirm Stop while inventory is incomplete. They include actual PID recycling and a naive `killpg` control that must hit the unrelated newcomer. These are unusually strong test designs, but remain unexecuted specifications in this work. [unix_stop/main.rs, 66–87 and 164–191](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/tests/unix_stop/main.rs#L66-L87), [unix_pid_reuse.rs, 28–75](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/tests/unix_pid_reuse.rs#L28-L75)

## 3. Run completion and enforcement limits

`run` opens one descendant grace window when the root exits; a later stop gets only the remaining grace. Its state machine retains an explicit `Unstopped` outcome and waits for output even after a failed supervisor stop. If the root status is known, errors can retain a partial `RunOutput`. A run settling at or after its absolute deadline becomes Timeout even when timer delivery is late; cancellation and I/O failures have separate result/error rules. [process/run.rs, 175–197 and 302–330](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/process/run.rs#L175-L197)

Two background enforcement loops have a concrete availability limit. The lingering timeout watcher ends on an inventory error; the RSS watcher also ends on inventory or sampling failure. A transient incomplete inventory therefore need not be retried forever. RSS sampling occurs every 250 ms, counts descendants without duplicating Linux tasks, and forces when observed memory is strictly above the cap. It is a sampled threshold, not an allocation limit. Descendants reached by memory accounting can exceed the session/Job stop boundary; escaped workloads depend on a cooperating jail lifetime. [process/deadline.rs, 141–159](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/process/deadline.rs#L141-L159), [process/memory.rs, 30–85](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/process/memory.rs#L30-L85)

Fractional grace deserves focused maintenance review. Validation rounds up to check its allowed range but leaves `req.grace` unchanged in `Spec`; Spawn serialization uses `millis(spec.grace)`, whose `as_millis()` truncates. Public explicit-stop grace uses a helper that produces a rounded-up whole-millisecond Duration. The source paths differ; this is a static consistency finding without a behavioral reproduction. [spawn/validate.rs, 148–156](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/spawn/validate.rs#L148-L156), [spawn/mod.rs, 124](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/spawn/mod.rs#L124), [client/start.rs, 137](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/start.rs#L137), [client/mod.rs, 288–290](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/client/mod.rs#L288-L290), [process/life.rs, 132–139](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/process/life.rs#L132-L139)

## 4. Output is bounded and explicitly lossy unless the selected mode preserves it

Each stream keeps 1 MiB before its first claim and 16 MiB with an attached consumer; collection has a max-plus-one budget, and detached consumers retain none. Adjacent chunks coalesce only to a bounded size. Drops carry byte accounting and gap markers rather than silently joining unrelated fragments. Claiming is permanent: even dropping an unpolled collect future detaches its claim. Optional pipe backpressure waits only while a consumer is attached and the tree has not ended; end/cut/detach release that wait. [io/queue/mod.rs, 28–38, 124–132, 209–240 and 306–324](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/io/queue/mod.rs#L28-L38), [io/collect.rs, 21–24 and 49–74](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/io/collect.rs#L21-L24)

UTF-8 text retains incomplete sequences across adjacent chunks, then emits replacement text at a gap or end. Lines preserve UTF-8 boundaries while splitting very long lines into at most 1 MiB continued pieces. Raw byte mode is necessary when exact bytes matter. Blocking OS reader/writer threads isolate the executor but are not generally interruptible: abandoned stdin futures settle while an OS write can still hold its thread. Concurrent unawaited stdin writes can accumulate copied buffers, so the bounded-output design is not a global bound on all application-scheduled input. [io/out.rs, 107–126 and 186–203](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/io/out.rs#L107-L126), [io/stdin.rs, 75–111 and 138–151](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/hugr-omni/src/io/stdin.rs#L75-L111)

## 5. Windows owner-loop and terminal boundaries

The owner loop enforces due tree deadlines before and after waiting. Separate helpers perform channel I/O, process waits, completion-port reads and diagnostic writes. Inbox admission is 64 requests; the reply budget is 1024 plus room for per-tree exit notifications and Ready. The outbox still counts a writer's in-flight batch. These are count bounds with protocol frame limits, not a small fixed total byte budget. There is no writer-progress timeout in these queues; the design keeps deadline work independent of a blocked writer. Diagnostics queue 32 lines, drop excess new lines and later report a drop count. [windows/mod.rs, 111–135](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/mod.rs#L111-L135), [windows/queues.rs, 18–25 and 182–229](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/queues.rs#L18-L25), [windows/diag.rs, 31–68](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/diag.rs#L31-L68)

ConPTY creation starts its closer thread first, uses flags zero, closes its local PTY-side pipe copies, and transfers host ends through close-source duplication. Terminal roots have explicit null standard handles and no new-process-group flag. `ConPty::close(deadline)` itself drops ownership and ignores the deadline value; the tree owner independently terminates the Job. The 200-session test checks marker presence and handle-count thresholds; below build 26100 its assertion permits one extra handle per session plus slack. The source therefore does not offer a zero-retention claim across every supported build. [pty_windows/mod.rs, 62–111](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/pty_windows/mod.rs#L62-L111), [windows/create.rs, 34–86](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/create.rs#L34-L86), [windows_pty.rs, 172–219](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/tests/windows_pty.rs#L172-L219)

## 6. AppContainer mode has separate recovery obligations

AppContainer launch is a standalone managed child mode. It applies profile grants, starts fixed-endpoint brokers, protects guarded paths, and starts the confined root with security-capability and nested Job attributes. The broker destination is fixed to each configured `127.0.0.1:port`; client bytes cannot select it. Each route admits 64 active connections and has a ten-second connect timeout, but no transfer/idle deadline. A failed broker-pair thread spawn leaves its admission counter incremented because the spawn result is ignored. [windows/container/mod.rs, 160–230](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/container/mod.rs#L160-L230), [windows/container/broker.rs, 95–150](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/container/broker.rs#L95-L150)

Guard protection uses DACL snapshots, per-holder locked marker files and parent directory pins. Source order and error paths qualify its crash-safety description:

- `acl::protect` or placeholder creation happens **before** the state file is written. A crash or failed state write in that interval can leave no recovery record for the mutation.
- Ancestor `acl::pin` errors are skipped, so successful protection does not establish every intended rename-prevention pin.
- Reconciliation ignores a failed ACL restore or state read and still removes the state file. A later recovery can then lack the original snapshot.
- Marker-open failures and lock errors other than lock violation count as no live holder. Atomic rename is used without a durability flush.
- DACL restoration reinstates a snapshot; unrelated concurrent ACL changes can be overwritten. That last point is an inference from restoration behavior, not an observed incident.

These are exact static paths, not an executed exploit or a blanket verdict on confinement. A useful next change would make journal persistence precede irreversible protection, preserve retryable failed-restoration state, and decide whether unavailable pins/holder observations should fail closed. [windows/container/guard.rs, 37–92, 168–233](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/container/guard.rs#L37-L92), [windows/container/acl.rs, 237–287](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/container/acl.rs#L237-L287)

AppContainer's post-root cleanup differs from normal `Tree::settle`: after terminating the Job, it polls up to five seconds and breaks on either zero or an unknown active count. It then returns to guard release, whose result is ignored. This does not establish confirmed emptiness before every restoration path; maintenance should reconcile that policy with the source comment explaining why descendants must be gone before ACL restoration. [windows/container/mod.rs, 207–214 and 303–320](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/crates/omni-supervisor/src/windows/container/mod.rs#L303-L320)

## 7. Test harness precision and remaining evidence gaps

The conformance runner validates complete scenario structure and names before applicability/execution, distinguishes Harness from Product failures, and permits pending only for Product failures. A pending item that fully passes applicable cases is stale and fails the ledger check. Regex support is an intentionally restricted shared subset, not all JavaScript regex.
