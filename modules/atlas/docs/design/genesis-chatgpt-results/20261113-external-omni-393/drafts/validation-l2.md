## QA: measurement depends on the observer

Quick measured budgets are six minutes, or eighteen on Windows; full is thirty minutes. Builds and first fetch/install happen outside the measured budget. ## Useful maintenance directions from the sources

These are author observations for independent review, not approved product defects or runtime findings.

1. **Keep deadline budgets through final cleanup authorization.** QA Watch checks expiry after its first snapshot, but calls `reap`, which performs a second fresh snapshot without the request deadline. The documented “expired means nothing done” promise is not demonstrated if expiry occurs during this revalidation/kill phase. Propagating the absolute deadline would make the guarantee reviewable end to end. [watch.rs](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/qa/src/oracle/watch.rs) [mod.rs](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/qa/src/oracle/mod.rs)
2. **Make helper bounds include their real boundaries.** QA `bounded.rs` excludes spawn from its timer, has an unbounded kill/wait after timeout, and allows up to two additional one-second drain waits. Buffers have no cap, and a descendant-held pipe can turn captured output into an empty string. Windows broker's64 MiB check is also after ReadToEndAsync, not a streaming allocation limit. [bounded.rs](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/qa/src/bounded.rs) [windows-inventory.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/windows-inventory.ts)
3. **Use teardown-qualified verdict publication consistently.** V1/V2 serve/TUI use finishCampaign; a recorder or frontend cleanup failure changes the one emitted result to failure. Unix v10-exit and V2 hold call verdict before finally cleanup, allowing an emitted successful observation to precede a teardown error. V5/V6 record finalSweep arrays but do not directly make a nonempty final array a failure; earlier zero checks remain their asserted conditions. [windows-lifecycle.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/windows-lifecycle.ts) [v10-exit.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/v10-exit.ts) [v2-kill.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/v2-kill.ts) [v5-mcp.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/v5-mcp.ts) [v6-terminal.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/v6-terminal.ts)
4. **Validate plan shape where arithmetic assumes nonzero values.** Rust agent selection uses modulo commands length and cancellation divisors. The checked-in plan is valid, but malformed empty/zero configuration is not rejected before those operations. Similarly, recorder capture maps keyed only by pid are not a safe same-pid concurrent request queue. These are input-boundary limitations, not demonstrated failures of the checked-in workloads. [agent.rs](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/qa/src/rust/agent.rs) [agent.json](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/qa/workloads/agent.json) [windows-inventory.ts](https://github.com/gustavomhss/hugr-orchestra/blob/1cde2ff7a71bcf7aecb5d030917b577165135d38/native/omni/campaign/windows-inventory.ts)
5. **Align preparation claims with what is checked.** QA cached HEAD equality does not detect dirty worktrees, and installation stamps do not revalidate installed contents. Node availability is checked by successful `--version`, without parsing the advertised minimum. QA README's rust:1.96 Docker example conflicts with its manifest's1.98 requirement. ## Preservation and documentary checks

`capture.json` records exact source metadata. The active record sets cover all147 assigned paths with no duplicates. A local documentary check revalidates source bytes, Git blob hashes, SHA256, LF line counts, required fields and complete-line excerpt equality. Its output is `documentary-check.json`; it says nothing about product runtime behavior.

Original changed author files are preserved under `history/v1/`; the intermediate regex-table revision is additionally in `history/v2/`. `corrections-v2.json` records the initial mechanical adjustments. `corrections-v3.json` explains that trailing-blank-line alarms were mostly false positives in the former validator and restores Git LF numbering for regex-table, treating Unicode U+2028/U+2029 as data. `corrections-v4.json` corrects the V6 helper relationship after full V6 reading. Each delta carries before/after hashes; baseline bytes were never edited.
