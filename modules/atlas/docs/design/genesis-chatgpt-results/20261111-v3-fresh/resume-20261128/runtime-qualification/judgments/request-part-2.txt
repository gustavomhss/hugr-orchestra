## Reproduzir em GitHub Actions

O workflow é `.github/workflows/genesis-runtime-qualification.yml`.
Ele executa dois jobs Linux: a preparação residual e o comando de guards do
repositório. O `atlas-pilot.yml` permanece como evidência dos controles comuns.
Para repetir o checkout de controles efetivamente qualificado, reexecute o
[run 46114652347](https://github.com/gustavomhss/hugr-orchestra/actions/runs/46114652347),
cujo HEAD é `09a4c4afc7aab2f9a153eb059d13df0ecf15595c`.
Outra tentativa terá caminhos e IDs de candidate próprios.

A execução completa usa um checkout Git real no SHA que o evento do Actions
informa em `GITHUB_SHA`. Os seguintes comandos são os comandos do job; execute-os
somente no runner autorizado, depois do checkout e do setup de Bun do repositório.
Não defina `GITHUB_ACTIONS` manualmente para contornar a restrição do harness.

```bash
set -euo pipefail

RUNTIME_SHA=db9b4235022c4df32fe3bfd4faeea8adcd69abb7
QUALIFICATION_PATH=modules/atlas/docs/design/genesis-chatgpt-results/20261111-v3-fresh/resume-20261128/runtime-qualification
QUALIFICATION_ROOT="$RUNNER_TEMP/genesis-runtime-$GITHUB_RUN_ID-$GITHUB_RUN_ATTEMPT"

test ! -e "$QUALIFICATION_ROOT"
mkdir -p "$QUALIFICATION_ROOT"
git worktree add --detach "$QUALIFICATION_ROOT/runtime" "$RUNTIME_SHA"

(
  cd "$QUALIFICATION_ROOT/runtime/modules/atlas"
  npm ci
  bun typecheck
)

python3 "$QUALIFICATION_PATH/qualification.py" \
  --repository "$GITHUB_WORKSPACE" \
  --runtime-root "$QUALIFICATION_ROOT/runtime" \
  --state-dir "$QUALIFICATION_ROOT/data" \
  --output-dir "$QUALIFICATION_ROOT/evidence" \
  --lock "$QUALIFICATION_PATH/input-lock.json"
```

O harness prepara ambos os pacotes completos. Ele cria três worktrees de dados:
S1-03, S2 e um terceiro somente para a recusa de permissão. Cada worktree tem
HEAD verdadeiro da fonte e materialização parcial explícita
(`--no-checkout`): apenas os arquivos exigidos pelo pacote, com overlays
verificados por revisão. Nenhum estado Atlas é herdado.

O runtime usa esta porta original, com CWD em `modules/atlas` do código fixado:

```text
bun scripts/genesis-native.ts prepare <raiz-isolada> <pacote-relativo-à-raiz> <novo-arquivo-de-saída>
```

Caminhos de pacote:

- S1-03: `modules/atlas/docs/design/genesis-chatgpt-results/20261111-v3-fresh/s1/subslices/03-automation/native-package.json`.
- S2: `modules/atlas/docs/design/genesis-chatgpt-results/20261111-v3-fresh/s2/native-package.json`.

O arquivo de saída precisa ser inédito. O CLI usa criação exclusiva `wx`;
um arquivo existente produz recusa. Use raízes e arquivos novos para outra
tentativa e preserve o erro da tentativa anterior.

## Capacidades e limites

- Fonte observada: até **2.097.152 bytes** por arquivo, inclusive.
- JSON do pacote, referências e corpos: até **8.388.608 bytes** por arquivo.
- Leitura individual de CAS: limite existente de **67.108.864 bytes**.
- O hashing usa os bytes completos. SHA-256 de transporte, blob Git e versão
  de input do kernel são identidades distintas.
- Somente arquivos regulares sem symlinks nos componentes do caminho.
  Caminhos excluídos e falhas de leitura não viram ausência presumida.
- Um pacote completo e um scope por candidate. Dependências de build entre
  pacotes continuam recusadas pelo formato atual.
- A cópia precisa permanecer estável durante a operação. Não há garantia
  universal contra renames hostis concorrentes, power-loss arbitrário,
  concorrência distribuída ou autenticação criptográfica de reviewers.
- O materializador comprova a relação commit/caminho/bytes. O adapter conserva
  explicitamente `external-capture-evidence-required`.

`prepare` grava CAS e produz o candidato. Ele não cria política, ator, credencial,
projeção ou aprovação. Binding de importação, publicação, `index/read` do domínio,
aceite semântico, merge e ativação são decisões e operações separadas.
