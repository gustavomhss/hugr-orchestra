## A. Configuration: decoder, settings writer and publication

**Admission and lifetime.** `Config.Info` is the current schema. The Location loader parses JSONC with trailing commas, decodes with `onExcessProperty: "ignore"`, and uses the live legacy schema and migration when `needsUpgrade` detects old keys or MCP shape. After legacy migration it appends current `permissions` recovered from the same text, then decodes the current result. Remote instruction URLs are rejected. A nonempty readable file with parse/schema errors fails loading; empty text returns no document, and `readFileStringSafe` maps both missing and permission-denied reads to `undefined`. Consequently, “every invalid or inaccessible file must fail” is too strong. Required packaged-skill materialization precedes recoverable plugin boot. [E01, E03]

Ordinary settings order is global documents, direct ancestor/project documents, then `.orchestra` documents, with nearer discoveries applied later. Within a directory JSON precedes JSONC. Project discovery and parsed project documents are retained from Location opening. `entries()` rereads global documents and reloads policy, but does not rediscover all project configuration. `Policy.evaluate` takes the last matching wildcard statement or the caller's fallback; policy documents are reversed before loading so a user-global policy can override a repository policy. These policy statements and tool permission rules are distinct surfaces. [E01, E05]

**Settings publication is a separate path.** `updateGlobal` chooses the highest-priority existing readable global JSONC/JSON document, otherwise creates JSON. It edits JSONC properties, replaces each supplied provider definition, and replaces the entire permissions/trusted-projects arrays so removed tails do not survive. Disabled-provider edits replace exact `provider.use` denials, retain wildcard denials and unrelated statements, and rewrite a legacy `disabled_providers` list when present. The write uses the filesystem's temporary-file/rename helper and invalidates the global settings cache. This helper follows an existing symlink to its real target; it is not the Location mutation admission service. [E02, E03]

`readGlobal` is a limited settings reader with a process cache keyed by config directory and both files' mtime/size/inode signatures. It returns cloned values. A same-signature external edit can remain stale; `updateGlobal` explicitly drops the entry. `entries()` follows its own reread path. Stat failures are folded into an `"absent"` signature by this implementation; that sentinel is not evidence that an inaccessible file was physically removed. [E02, E26]

**Compatibility is active code.** Migration maps singular legacy families to current fields, including agents/mode, commands, plugins, providers, MCP, permissions, snapshots and compaction. Legacy allowlists first add a wildcard denial, then per-ID allowances that retain a matching existing denial; disabled IDs are appended last. An explicitly empty allowlist therefore differs from an omitted allowlist. Legacy schema leaves are decoded inputs to these mappings, not dead/generated material. The migration constructs an explicit result, so lossless preservation of every unknown or current-only field is not promised. The 12 upgrade source files and current leaf schemas are individually captured and mapped in coverage. [E04]

**Trust and plugin admission.** Only user-owned entries—pathless documents or paths under global config—contribute `trusted_projects`. A project cannot approve itself. Approval requires an existing absolute canonical directory and rejects a filesystem root; revoking a child entry does not remove a parent's coverage. `ConfigTrust.runnable` selects repository entries only when the directory is trusted. The external plugin loader actually applies that selection before preparing/importing project plugins, while individual setup failures are logged and recovered. This establishes that consumer's admission point, not universal authorization of every command or a grant of tool permission. [E05, E07]

The other configuration writers have their own contracts. `ConfigAgentFile.write` checks a supplied revision, protects Maestro from disable/non-primary edits, confines existing profile paths and performs a temporary rename. The revision check is optional; the exported name validator is not automatically invoked by `write`. `ConfigPluginFile.add` chooses the first existing file in its own low-to-high file list, retains an existing package unless forced, and writes through Bun. Its selection order and installation behavior should not be inferred from `updateGlobal`. [E08]

**Published schema boundary for S1-05.** The actual exported `schema/config.json` points to `Config.Info`, advertises comments/trailing commas, and declares `additionalProperties: false` for that object. The runtime loader's explicit excess-property ignore option has a different acceptance policy. `apps/cli/script/schema-files.ts` exports `configSchemaText()` from `Config.Info`, normalizes generated schema and restores model references; its main path writes config, TUI and theme outputs. The separate `schema.ts` validates one output argument, converts `Config.Info` directly and appends a newline. These are two source-visible publication paths; equality, freshness and regeneration were not executed. Both scripts, the exported schema and the schema-package Location contract are outside the 123-row ownership set. Any generated-output change must go to its owner through the official generator. No generated file was edited. [E06]

## B. Location and project boundaries

**Identity and execution placement.** `Location.Ref` contains an absolute directory and optional workspace ID; the bound Location preserves those fields and resolves its project. Project identity prefers a normalized remote hash, then the common-directory cache, then a root commit. A directory with no discovered repository resolves to the global project and filesystem root; that project root does not enlarge the active Location's file boundary. Exact project/directory membership and copy strategy are stored separately. [E09, E12]

The Location map applies replacements before hoisting globals, substitutes native tool nodes, compiles a fresh graph and uses a 60-minute idle TTL. Recovery starts only after graph construction succeeds, in its scope. `withGlobalContext` waits for completed global exports before lazy cache acquisition. Graph membership alone proves neither successful external initialization nor credentials. The current `SessionExecutionLocal` is global and Session-ID based: at drain or `withRunner` time it reads the stored Session and provides `locations.get(session.location)`. Session move resolves the destination project and rejects a different project ID before exclusive event publication. These source paths support the S1-04 Location/session handoff; optional workspace identity is not proof of remote placement or clustered ownership. [E10, E11]

**Path resolution and mutation remain separate.** `LocationMutation.resolve` rejects relative lexical escape and an internal-looking path whose resolved physical target escapes the Location root. Missing targets resolve through an existing real ancestor; dangling links have bounded traversal. Absolute external targets produce canonical `external_directory` permission resources. This function expressly does not approve the mutation. `FileSystem` independently enforces containment/type for read/list while delegating search; it is not the model tool's permission layer. [E13, E14]

`FileMutation` uses a KeyedMutex in its service instance, keyed by canonical target. Conditional writes compare bytes and write under that lock, then run the configured formatter before releasing it. The write delegates to `FSUtil.writePhysical` and onward to `PhysicalPath`; this packet does not inspect that transitive implementation or establish every OS race guarantee. These cooperating, process-local mutations do not provide cross-process locking. The source explicitly leaves multi-file rollback, watcher/edit events, LSP integration, side-effect recovery and idempotency deferred; sequential edits may be partially applied. The shared patch parser is an input grammar, not a transaction or authorization layer. [E15]

**Checkpoints retain original ownership.** Save admits nonempty UTF-8 JSON, attempt 0/1 and a nonempty fork/boundary. Identity is `forkID:attempt`. Inside a transaction, an existing record must match Session, fork, boundary, attempt and exact payload, with a matching digest; that retained record returns before consulting the current Session. Only insertion derives project/directory from the Session. An exact retry can therefore survive Session deletion or movement without assigning the old checkpoint to its new location. The table retains the Session ID without a Session foreign key, while project deletion cascades. Read requires project ID plus checkpoint ID and checks the digest; list has bounded pagination. Driver errors/defects are sanitized to a storage reason. The digest does not prove payload meaning, consumer authorization, restore success or crash recovery. [E16, E26]

**Copies are physical operations followed by membership.** The default strategy delegates to Git worktrees. Create first resolves a registered source or the project's own stored worktree, selects a strategy and collision candidate, performs strategy creation, then records exact directory/strategy membership and publishes a change. Remove requires stored strategy membership and performs physical removal before deleting membership. Refresh reconciles existence and strategy discoveries with membership in a database transaction. These orderings expose a filesystem/database boundary; they are not a transaction covering both physical worktrees and SQL. Registry duplication and strategy errors have explicit failure paths. [E17]

**Snapshots are selective and best effort.** Capture uses a separate Git directory under global data, checks Git/config enablement, scopes collection to the Location and limits untracked files to 2 MiB; capture failure may yield `undefined`. Preview/restore map selected project-relative paths to trees and reject lexical project escape. Restore removes a selected path absent from its tree. Checkout uses `read-tree` plus `checkout-index --all` and leaves other paths untouched; unlike preview/restore, the wrapper has no `enabled()` check. None of these observations establishes atomic rollback of arbitrary multi-file tool side effects. [E18, E19]

**Repository caches are mutable checkouts.** Reference parsing and branch validation define cache identity; branch-specific references have separate cache paths. `RepositoryCache.ensure` uses a per-path flock. Reuse requires a checkout exactly at the canonical cache path and a matching origin, since upward repository discovery alone could select an enclosing checkout. Invalid existing cache entries can be removed and cloned again. Refresh fetches and resets to the relevant remote branch, returning current head/branch and a cloned/cached/refreshed status. This is not immutable versioned knowledge: readers can see the latest refreshed checkout. Git operations delegate through AppProcess; native process, locking and Git behavior were not executed here. [E20]

## C. Coverage, supporting leaves and remaining evidence limits

`coverage.json` reconciles **all 123 original rows**, preserving each path/blob, legacy key and inherited read status. It adds this execution's exact capture status, semantic read ranges, responsibility group, required-needs mapping and next-read boundary. The 75 implementation files and two documents were captured; complete versus partial semantic reads are distinguished. Eight test files were also captured, with only inspected case ranges or declarations counted as read. The other 37 test files and one fixture are explicitly grouped as indexed, uncaptured regression/support material; no behavior is inferred merely from their filenames. Six additional captures establish cross-owner boundaries. Counts and byte identities are mechanical checks, not comprehension or runtime receipts.

The supporting families have distinct roles: current config schemas constrain decoded shapes; upgrade schemas supply live compatibility inputs; agent/command/provider/reference/skill plugins translate entries for their specific registries; provider option lowering separates API configuration from request options without proving native adapter compatibility. Behavior storage supplies project-scoped context records. TUI config discovery has its own project-config flag handling, so its behavior is not automatically Core Config behavior. These files are individually accounted for, with field-presence claims kept separate from consumer execution. [E21, coverage groups C02–C06]

Project support is likewise bounded. GitCLI caches a limited result set for 1.5 seconds and clears it after its patch application path; VCS exposes bounded/truncated views. Search has FFF/ripgrep integration, platform wrappers and fallback; watcher availability, enablement and failure handling are explicit, so “all files always watched” is unsupported. Ignore/protected lists are scan filters, not a permission sandbox. Guardrail and pull-request adapters invoke external process surfaces in product code; no such command was invoked in this investigation. Thin `file`/`workspace` exports and SQL/schema leaves are mapped to their owner rather than inflated into independent services. [E22–E25, coverage groups P03–P08]

For a change, first follow the specific owner and inspected ranges in coverage. A decoder/settings change must reconcile current schema, migration, settings writer, policy ordering and the unowned publisher. A Location change must preserve stored Session placement and process-global routing. A physical mutation or cache change must inspect the named transitive process/path/locking implementation and relevant test assertions before claiming stronger guarantees. Partial Git/search/VCS/adapter reads remain partial; the public interface is not a substitute for those leaves.

All product tests, CI, typechecks, guards, Atlas operations, provider calls and filesystem/Git side effects are **NOT_RUN** in this producer task. The test excerpts record intended cases only, including same-signature global-cache staleness, legacy policy precedence and sanitized checkpoint storage failure. New semantic acceptance, runtime use and subsequent L2–L4 remain separate work for the principal and independent judges. [E26]
