### Mandatory findings

#### B1 — Distinguish the schema-error prefix limit from the complete diagnostic length

**Affected artifact:** `s1.api.server-edge`  
**Criteria:** QS-1, CC-3

**Expected:** A numerical truncation claim must describe the actual bounded quantity.

**Observed:** The body says:

> “The schema-error adapter logs a reason truncated to 1,024 characters…”

But **C29, `packages/server/src/middleware/schema-error.ts` lines 10–19**, shows:

```ts
return reason.slice(0, REASON_LIMIT) + `... (${reason.length - REASON_LIMIT} more chars)`
```

The resulting logged and returned string includes an additional suffix. Consequently, “truncated to 1,024 characters” is imprecise if read as a bound on the complete diagnostic. The transmitted span also omits the definition of `REASON_LIMIT`.

**Required correction/evidence:** Supply the short pinned span defining `REASON_LIMIT` and revise the sentence to identify the prefix budget and appended omission suffix. For example, if the definition confirms 1,024:

> “For an oversized diagnostic, the adapter retains the first 1,024 characters and appends an omitted-character count; it logs and returns that bounded summary.”

Preserve the original body and submit the corrected body identity. No execution is required.

#### B2 — Support or explicitly attribute the cross-session message rejection claim

**Affected artifact:** `s1.api.session-contract`  
**Criteria:** QS-1, QS-4, CC-3

**Expected:** The claim that a cross-session message produces `MessageNotFoundError` must follow from an explicit declared contract or the relevant ownership check.

**Observed:** The operation table says that a missing **or cross-session** message returns `MessageNotFoundError`. **S16, `handlers/session.ts` lines 686–698**, demonstrates delegation to `session.message(ctx.params)` and conversion of a missing returned value into that error. It does not show how the delegated service treats a message belonging to another session. **S37** supplies intended missing-session/message assertions, but the transmitted excerpts do not establish the cross-session case.

**Required evidence or correction:** Supply one narrow pinned excerpt that establishes the cross-session condition:

- The explicit Protocol declaration/annotation, with the body attributing the guarantee to that declared contract; or
- The Core lookup/ownership condition showing that both session and message identity constrain the result.

If neither is established, narrow the body to the observed missing-result mapping and retain cross-session behavior as a mandatory unresolved ownership fact. A test name or route shape alone would not resolve this request.
