# Correction: continuity archive boundary

WP-L1B; source `1cde2ff7a71bcf7aecb5d030917b577165135d38`. Static follow-up only; original evidence-note.md remains unchanged. Its statement that the imported archive implementation is unavailable is incorrect: it exists in the nested Atlas tree. This addendum replaces that availability claim and resolves the responsibilities below.

**Source and generated binding.** `@orchestra/atlas-boundary` exports `./context` from `src/generated/context.js`; its build maps that entry to `adapter-io/src/context-log.ts` and resolves `@atlas/*` imports to the nested package sources. Selected generated symbols expose the same scrub/export/read functions. No build or generated-parity check was run. Sources: `modules/atlas/boundary/package.json:31-34`, `modules/atlas/boundary/script/build.ts:20-21,29-47,65-81`, `modules/atlas/boundary/src/generated/context.js:3`.

**Scrubbing responsibility and limit.** `scrubText` UTF-8 encodes, invokes persist's whole-buffer scrubber, and decodes. Continuity calls it before splitting and hashing archive text; export does not call it again. The scrubber scans declared shapes and replaces matches while preserving other bytes. Its four families are GitHub tokens, Slack tokens, GitHub fine-grained PATs, and AWS access-key IDs. JWTs, PEM private keys, and AWS secret access keys are explicitly outside that declaration. Slack/PAT body rules may absorb adjoining non-secret suffixes. This is a limited shape filter, not a general secrecy guarantee; imported archive callers own pre-scrubbing. Sources: `modules/atlas/packages/adapter-io/src/context-log.ts:55-73`, `modules/continuity/src/v2/archive.ts:76-89`, `modules/atlas/packages/persist/src/scrub.ts:73-109`, `modules/atlas/packages/persist/src/scrub-shapes.ts:75-142,295-326`, `modules/atlas/packages/persist/src/scrub-scan.ts:57-91`.

**Privacy and “commit.”** `exportContext` always appends new open/reference/mask-change events under `.atlas/members/<seat>/context/<session>.jsonl`; only `opts.commit === true` permits writing markdown blobs. This flag controls file emission, not a Git commit. The function does not determine repository visibility, perform Git commit/push, scrub supplied metadata, delete existing blobs, or revalidate an existing blob during export. The caller owns visibility choice and inclusion in its record commit. Path components are percent-encoded; blob paths are sharded by the hash prefix. Sources: `modules/atlas/packages/adapter-io/src/context-log.ts:60-115`, `modules/atlas/packages/adapter-io/src/layout.ts:52-77`.

The available visibility helper resolves GitHub origin URLs and reads the API: no recognized origin/network response defaults public; status 200 requires `private === true`; status 404 is explicitly private; other statuses or unreadable JSON default public. Therefore “every uncertainty defaults public” would omit a consequential 404 exception. The helper's actual connection to continuity's caller-supplied flag remains uninspected because the host caller is outside these files. No remote or credential access was performed. Sources: `modules/atlas/packages/adapter-io/src/repo-visibility.ts:17-47`, `modules/continuity/src/v2/archive.ts:143-154`.

**Integrity and recovery.** Export rejects any reference whose markdown SHA-256 differs from its ID before writing events. New references and mask deltas are appended as kernel events; the durable-log writer/reader invokes the content-key check, rejects malformed lines, and counts rejected/unreadable input. Context reading further filters to the requested Session and valid event shape, then folds events by `(at, contentHash)`. This supplies integrity checks, not authorship authentication. Sources: `modules/atlas/packages/adapter-io/src/context-log.ts:72-107,118-146,190-202`, `modules/atlas/packages/adapter-io/src/durable-log.ts:105-164`.

`readContextChunk` searches all Session logs under the requested seat, requires a reference, then verifies blob SHA-256 and UTF-8 byte length. Missing, unreadable, unreferenced, or mismatched blobs produce `undefined`; directory-read failures also become no matches. Export writes events before blobs and is not an atomic log/blob transaction; repeated successful export emits only missing references/mask deltas and skips existing blob paths. A host must not infer complete blob availability from an event alone or infer privacy cleanup from `commit: false`. Sources: `modules/atlas/packages/adapter-io/src/context-log.ts:75-115,149-187`.
