## What the engine is for, and which kind of evidence this is

Atlas represents knowledge with stable content identities, ties claims to structural source anchors, separates truth from freshness and human authority, and supplies bounded retrieval and owner-scoped memory. This unit follows mechanisms in eight engine packages; it does not infer that an exported helper is reached by a shipped command. The captured reference-model ledger explicitly lists specification implementations with no production value callers, including retrieval `pack.ts`/`drop.ts` and persist `reconstruct.ts`. The ledger itself uses direct rather than transitive reachability and acknowledges closed-ring and live-module dead-export limitations. Its declared counts are source text, not a newly executed measurement. [C/index.ts:1-12; C/status.ts:6-11; C/tier.ts:3-6; H/gates/reference-model-guard.mjs:4-18,51-56,194-236]

A content address identifies an object; a source anchor records its origin; freshness measures dependency change; a truth evaluator supplies a verdict; a governed host door controls publication. These are separate contracts. The accepted `S4:L1:ownership-boundaries` describes the ownership artifact/result distinction; this body adds the engine mechanisms that enforce parts of that contract. [K/canonical.ts:104-115; G/drift.ts:60-65,108-115; G/freshness.ts:77-119; N/lifecycle/status.ts:74-77; N/ownership/read.ts:36-95]

## Contracts and kernel: canonical identity is deliberately narrower than arbitrary JavaScript

The contracts barrel exports shared types rather than an operational service. Freshness is `FRESH|DRIFTED|STALE`; status is separately `HOLDS|BROKEN|NA|advisory`; tiers are `T0|T1|T2`. Treating a fresh object as true or a tier as authentication would collapse distinct contracts. [C/index.ts:1-12; C/status.ts:6-11; C/tier.ts:3-6]

**Observed identity rules.** Canonicalization recursively omits `grounding`, `status`, and `freshness` side-index keys; omits undefined object properties; maps a scalar undefined to null; accepts finite integers but rejects non-integer numbers; NFC-normalizes strings and keys; sorts normalized keys; and refuses normalization collisions and unsupported value kinds. UTF-8 canonical bytes feed the default BLAKE3 encoder. Thus this hash is not a Git blob SHA or transport SHA-256, and changing side-index metadata does not necessarily change object identity. Arrays, key normalization, integer-only numeric representation, and omitted keys are maintenance-critical compatibility choices. [K/canonical.ts:35-96,104-115; K/encoder.ts:7-10,30-34]

The kernel store is an in-memory Map. `put` hashes, deduplicates and catches an unaddressable object as the empty branded hash; `get` can be undefined. It retains the supplied object rather than a defensive copy. That primitive neither persists to disk nor authenticates a writer. A host must reject empty IDs and prevent later mutation of an object whose address has already been assigned. This is an inference from the primitive, not a report of a corrupted runtime. [K/store.ts:25-47]

The log primitive checks structural shape and keeps the first event at an ID; it does not itself re-hash every inserted event. `eventId` normalizes sequence to zero, excluding the ID field, and log combination is set union. The pure fold likewise normalizes sequence, resolves equal-content alternatives deterministically, and chooses a fresh non-superseded head by maximum content hash, not arrival time. Durable adapters have additional ordering and integrity rules; do not apply this kernel ordering to every committed Atlas log. [K/log.ts:42-68,82-93; K/fold.ts:66-82,102-122,177-183; A/memory-store.ts:50-70; A/knowledge-log.ts:65-83]

## Persist: portable projections, reference histories, and a real scrub/hash seam

`P/source.ts` models portable data as JSON for STORE-homed placements and trailers; a PR-only attachment is rejected and notes are an overlay rather than canonical state. Its export/import functions project the kernel store. `reconstruct.ts` supplies pure reconstruction, rewind by event-set subtraction, archive union, no-op deletion and respawn/forget operations. The ledger classifies reconstruction as a reference model, while source export/import has a documented CLI caller. These are not evidence that a real clone or rewind ran in this execution. [P/source.ts:58-91; P/reconstruct.ts:70-104,122-150; H/gates/reference-model-guard.mjs:214-236]

The transcript store scrubs an entire submitted buffer before hashing and stores the redacted bytes, returning defensive copies. It cannot join credentials split across separate `put` calls; the mitigation identity makes the selected scrub behavior explicit. The scanner recognizes four named credential-shape families (GitHub, Slack, fine-grained PAT, AWS key ID), not every possible secret. The streaming admission helper is itself described as having no production caller; the transcript buffer pass is a distinct seam and is used by the host's transcript adapter. [P/transcript-store.ts:61-97,108-115; P/scrub.ts:9-19,56-60,182-198; H/gates/reference-model-guard.mjs:232-236]

Framing, scrub policy and canonicalization affect addresses and receipts. Persist's other models remain preserved with explicit depth limits; host record rendering and logs are covered by `atlas-host-genesis`.

## Index and grounding: structural address, content drift, and truth remain separate

The index builder turns SCIP definitions/references into spatial, territory and dependency axes. It excludes local symbols and attempts declaration `dist`→`src` canonicalization against actual definitions; unresolved references remain explicit `to: null` edges. Its source warns that declaration mapping assumes mirrored source paths and can miss bundled declaration layouts. Dependency leaf identity hashes the **path**, not the current file contents, so an address is not a freshness watermark. [I/build.ts:183-186,222-244,267-293]

Reverse dependency traversal uses breadth-first search over resolved edges, removes the origin and marks under-approximation where unresolved/dynamic evidence is relevant. Co-change evidence is separate and correlational. The T0 coverage helper fails above a 0.15 hole ratio, but a missing or zero total becomes ratio zero; that return value cannot establish that a missing index was complete. These are function contracts, not measured coverage of this repository. [I/depgraph.ts:46-94; I/coverage.ts:39-58]

Drift resolves spatial or territory anchors and requires nonempty string values for every anchor; missing or different captured hashes become `DRIFTED`. Reformatting or renaming can change an anchor, while NFC-only rewriting can preserve canonical identity. The freshness calculation hashes a multiset of node/interface result state and the node's own content; callee bodies are deliberately excluded. Structural descriptions can therefore remain fresh without making a truth claim. [G/drift.ts:60-65,82-84,98-115; G/freshness.ts:77-119]

The gate normalizes incoming status and can downgrade `HOLDS` to `NA` when grounding or freshness is absent; it never promotes a claim to `HOLDS`. Knowledge status is recomputed through an evaluator and then gated, ignoring the candidate's self-declared status. Mechanical grounding establishes a source relationship, not model confidence or human ratification. [G/gate.ts:68-77; N/lifecycle/status.ts:74-77]

## Knowledge: shape, routing, human ratification, and ownership results

The basic emit lifecycle calls an injected grounding predicate before its sink. This isolated primitive is not the full shipped authorization door. `write/authz.ts`'s `isScope` checks only that scope is a nonempty string; actual actor membership belongs to host policy. For the governed path, start with `A/governed-emit.ts` and `A/policy.ts`. [N/lifecycle/emit.ts:67-70; N/write/authz.ts:1-37,58-60; H/gates/reference-model-guard.mjs:122-127]

Routing first deduplicates by content; absent node identity creates, a non-predicate can update, and a predicate comparison can supersede. The router has a closed slot vocabulary, normalizes checks, and refuses a degenerate anchor rather than inventing a wildcard. Ordinary node keys combine primary anchor, slot and optional normalized check; relation, negation, transition and test-vacuity families expose their own key constructors. Identity changes therefore affect update/dedup behavior, not merely labels shown to a reader. [N/write/router.ts:98-111,133-147,182-214,339-378,404-411]

`stage` only wraps a node; persistence is the adapter's job. Ratification requires a nonempty `by`, with literal `billy` for T0. The source explicitly describes this as a caller-supplied anti-accident check, **not authentication**. A process owner who can choose environment/input values is not cryptographically distinguished from the named ratifier. [N/ratify/ratify.ts:94-107,118-119,129-145]

Ownership values are separately strict: exact object keys, nonempty NFC text, 64-hex hashes, nonempty byte arrays with integer octets, unique criteria, at least two distinct semantic-review hashes, unique inputs/dependencies, and nonempty unique manifest roots/entries. Shape validation is useful but does not establish authority by itself. [N/ownership/shape.ts:13-76]

The low-level ownership reader requires a scope and positive safe-integer byte budget and exactly one of need/key. It loads and re-hashes artifacts, results, contracts and receipts; requires supported results; checks review PASS, contract, input hash, result hash, exact criteria and distinct reviewers; and recursively checks dependency identities/cycles. Without historical mode, an undefined current input is unavailable and a mismatched version is changed. Historical mode permits inspecting the recorded past; it does not establish current validity. [N/ownership/read.ts:16,23-95,133-150]

Body reads enforce UTF-8 validity and byte bounds, supporting selected unique second-level headings outside fenced blocks. The index call reports `bodiesReturned: false` yet internally invokes full reading with a large budget to verify body identity. It therefore avoids returning bodies, not necessarily loading their bytes. This reader explicitly lacks publication authorization; the host must first resolve a published carrier under provenance and scope. [N/ownership/read.ts:99-130,133-179; A/ownership-access.ts:18-48]

Update planning validates the historical manifest, observes declared inputs with tri-state semantics, returns HOLD on unavailable observations, treats proved absence/version changes as change, propagates over declared dependencies and derives a topological frontier and unaffected set. It plans candidate work; it does not authorize arbitrary recipe execution or publication. Empty/unavailable/absent cannot be flattened without losing that safety distinction. [N/ownership/update-plan.ts:31-90]

## Retrieval: reference pack policy, live Own, and reproducible host artifacts

The reference pack sorts by hits, then PageRank, then key; places T0 before T1; excludes T2; and enforces a strict prefix under the token budget. Its constructor catches unsupported axis/error cases as an empty pack. The source and ledger identify this as a reference policy, with `A/retrieval-model.ts` as the shipped pack assembler; a green test over this helper would not prove the CLI query changed. The reference drop policy preserves pins, tracks per-kind drops and requires re-grounding or rejects a stale pack. [R/pack.ts:124-180,225-252; R/drop.ts:133-174,198-201; H/gates/reference-model-guard.mjs:194-213]

Own is separately reachable through `A/own-source.ts`. Its advisory bands have per-band and total caps; overflow IDs remain pull-reachable, pointers do not inline the full drill, and deduplication makes Own win over an identical pack node by replacing the duplicate with a pointer. Epic Own is grounded in goals rather than pretending every goal is a code anchor. Errors in the constructor path return empty results, so callers need contextual diagnosis rather than interpreting emptiness as proof that nothing exists. [R/own.ts:210-260,320-343,359-370; H/gates/reference-model-guard.mjs:194-200]

Host context reads verify project/catalog identity, the exact snapshot/static-artifact correspondence and current source blobs, a COMPLETE graph receipt, Own cap, pointer shape and available drill units before returning READY; failures HOLD. Own artifact verification compares source-blob identities and source anchors, expected membership, duplicate paths, body rendering, unchanged unimpacted units and removed artifacts. Snapshot parsing permits export only when fresh; materialization produces skills and coverage from a bounded snapshot and verifies exact generated content and source blobs. These are the entry points for repairing stale static Own content; do not bypass them by editing a generated skill. [R/host-context.ts:95-157; R/own-artifact.ts:263-274,343-390; R/own-snapshot.ts:192-262]

Calibration's off-Atlas helper counts served/off-Atlas events deterministically per territory. Unknown territory rate is zero and its threshold is supplied by the caller. This counter is not evidence that unobserved needs were satisfied. [R/offatlas.ts:59-81]

## Memory: owner filtering and recoverable history, without a confidentiality claim

The partition sends predicates/advisories to knowledge and other accepted shapes to memory; memory insertion checks kind, partition and nonempty owner. Owner scoping controls default injection, but `readRepoBytes` can read all plaintext repository records: source comments explicitly distinguish scoped injection from confidentiality. The header combines awareness, orientation and the owner's project rules; this composition returns an empty budgets list, so that function alone does not enforce a token cap. Explicit recall needs an owner/kind/task/PR selector or returns empty. [M/kinds.ts:78-82,110-118; M/inject.ts:85-96,115-141,181-186]

Project rules use cited-governing hits, not mere mentions; decay is tied to logical waves. The rule log is insert-only with active/archive ranking and respawn, while hard deletion throws. Awareness caches facets by source key and re-rolls changed inputs in one shared wave; orientation folds the latest derived tail while preserving the supplied goal. These lifecycles are maintenance contracts for replay and prompt injection, not proof that every Orchestra consumer is wired. [M/rules.ts:134-136,159-184,272-307; M/awareness.ts:244-277; M/orient.ts:164-193]

Portable memory requires a named scanner; a detected hit throws before persistence. Scanner effectiveness is delegated rather than guaranteed by the interface. The durable adapter reads legacy and member memory files, sorts by sequence and appends at local head+1; orientation uses a payload-hash key rather than event-wide integrity. Those choices differ from knowledge's ordering/trust and must not be silently unified during a layout migration. [M/portable.ts:117-128; A/memory-store.ts:45-70; A/orientation-store.ts:59-76]
