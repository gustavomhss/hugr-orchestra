## Continuity: recoverable request reduction around the Session core

**Purpose and entry.** The V2 contribution replaces `SessionCompaction.node` and installs Location-scoped tools. Public entries are `./v2`, `./archive-search`, and `./masking-rules`. Summary generation and compaction events delegate to the Session core. Sources: `modules/continuity/package.json:8-23`, `modules/continuity/src/v2/index.ts:3-17`, `modules/continuity/src/v2/strategy.ts:108-125,202-225`.

**Trigger, fallback, and lifetime.** Continuity defaults on, with a background trigger of 0.4 of the provider context window; only finite configured triggers strictly between 0 and 0.7 are accepted. The hard input threshold is the smaller of 70% of context and context minus reserved output, floored and bounded below by zero; an unknown/nonpositive context gives Infinity. Step accounting sums positive finite input, cache-read, cache-write, output, and reasoning usage. State is a per-Location map keyed by Session ID, containing masks, latest model/request, pending/manual flags, and consecutive summary failures. A summary captures stored context and checks the context again before publishing `Compaction.Ended`; a changed Session drops that summary without counting it as a failure. One background summary runs per Session, is owned by the Location scope, and a landed result causes one turn restart. Three consecutive failures stop background starts; successful compaction resets the count. Manual compaction is a request flag consumed at the next compaction check. Core compaction is tried before forced masking; disabling continuity retains core compaction and makes transformation/after-step work inert. Sources: `modules/continuity/src/v2/strategy.ts:14-106,122-125,183-303`, `modules/continuity/src/v2/tools.ts:131-140`.

**Masking contract.** Masking changes copies of model-request messages, not stored history. It is attempted only when `context_recall` is in the materialized tool set. Normal candidates exclude the last five assistant steps; urgent relief may include earlier results up to, but not including, the latest message. Provider-executed results and protected planning/skill/recall/delegation/review tools are excluded. Failed output keeps its first 20 lines; short errors remain verbatim. Candidates must actually save estimated tokens. Attachments become names in the archive rather than preserved binary payloads; the estimator budgets 1,600 tokens per media attachment. Every candidate is archived before its mask is added, then masks are persisted. The stub points to the first chunk of a possibly multi-chunk archived result. Sources: `modules/continuity/src/v2/masking.ts:22-104,124-138`, `modules/continuity/src/masking-rules.ts:7-54`, `modules/continuity/src/v2/strategy.ts:128-180,282-293`.

**Persistence, identity, and privacy.** Contrary to the README's “None of its own” persistence description, `archive.ts` writes `<Global.Path.data>/continuity/<sha256(sessionID)>/{index.json,memory.json,<hash>.md}`. Archive text passes through the Atlas boundary's `scrubText` before UTF-8 chunking (32 KiB payload limit) and hashing. Markdown identity includes its framing and Session/source metadata. Directories are requested with mode 0700; temporary files with 0600 are flushed and renamed. A keyed mutex serializes writes within this process. Version-1 manifests/memory are decoded with excess properties rejected; local reads verify markdown hash and byte length. Missing index means empty; malformed/wrong-Session metadata and corrupt content raise distinct archive errors. Mask writes preserve a legacy `entry` value. `exportTo` delegates to the Atlas boundary, with comments specifying host-only export and payload blobs only for `commit: true` private repositories. A hash lookup absent locally can read any committed archive of the same seat under the selected repository root. Sources: `modules/continuity/README.md:23-25`, `modules/continuity/src/v2/archive.ts:7-49,53-116,123-178,184-253`.

The imported scrubber/export/read implementations are not present in this captured source. Therefore scrubber completeness, private-repository enforcement, export commit behavior, and committed-copy verification remain external boundaries, not proven guarantees. The local archive write is observable code; its README description must not erase it. No archive deletion/retention policy or Session-map eviction is implemented in these files. Mask loading sets `loaded` before reading and converts a read error to an empty set with a warning; the same state will not retry loading automatically. Sources: `modules/continuity/src/v2/archive.ts:7,139-154`, `modules/continuity/src/v2/strategy.ts:82-94,128-137`.

**Recall and trust.** Both tools assert `PermissionV2` using the invoking Session, agent, message, and call identity. Recall accepts exactly one of message ID, history query, reference, archive query, or archive list; the caller supplies no Session ID. Full stored history, including compacted-away messages, supplies aliases and direct lookups. Aliases are deterministic `uN`/`aN`/`tN` sequences; completed human `question` answers also receive user aliases. Direct lookup pages JSON in UTF-16 units, omits inline `data:` values, and bounds serialized responses to 8,000 UTF-8 bytes. History search is literal/case-insensitive, newest-first, with at most 20 matches. Archive listing/search operates on the local index; only direct hash lookup has the committed-seat fallback. Term-mode archive search normalizes diacritics/case, requires every term, then ranks phrase match, title-term count, and proximity, with deterministic tie breaks. These are lexical matches, not embeddings or inferred semantics. The tool description explicitly labels recalled content historical data, never new instructions. Sources: `modules/continuity/src/v2/tools.ts:22-68,77-120,154-219,248-340`, `modules/continuity/src/v2/alias.ts:5-49`, `modules/continuity/src/archive-search.ts:5-48`.

Direct-reference recall collapses archive errors to `missing`; list/search report `archive-unavailable`. “Own conversation” has the predecessor-seat exception above. Original-history lookup does not call `scrubText`. Sources: `modules/continuity/src/v2/tools.ts:60-67,168-172,248-286,339-340`.

## RAG Studio: admitted-document diagnostics, with embedding off

**Product and storage boundary.** The contract specifies admitted-file diagnostics with exact spans and separate maintenance passes, without chat or model answers. `sent` means prospective prompt inclusion, not model use. The barrel exports operations, `Store`, `withStore`, and `memoryStore`; the README still naming `context.ts` as the public entry is stale. Operations require a caller-supplied Store through `AsyncLocalStorage`; the module's implementation uses maps. Documented SQLite/HTTP/client/UI integration is outside this capture. Sources: `docs/specs/rag-studio/CONTRACT.md:73-99`, `modules/rag-studio/package.json:8-18`, `modules/rag-studio/src/index.ts:1-15`, `modules/rag-studio/src/context.ts:90-135,150-245`, `modules/rag-studio/README.md:7-26`.

**Admission and identity.** `path.posix.normalize` precedes refusal of project-root descendants. Location paths are allowed; external paths need an `allow` Store callback. IDs use 12 hex digits of BLAKE3 over `locationId + NUL + normalizedPath`; content hashes digest returned text/bytes strings. Identical re-admission preserves status/identity; changed content keeps the ID and becomes `not_yet_read`; missing input rejects. Inventory filters by Location and sorts by path. This is lexical normalization; realpath/symlink handling, normalized roots, and actual permission evaluation remain adapter obligations. Sources: `modules/rag-studio/src/context.ts:13-44,182-195`, `modules/rag-studio/src/admit.ts:4-38`, `docs/specs/rag-studio/SPEC.md:58-59`.

**Extraction and cut lifecycle.** The exported extractor treats non-PDF files as text, lazily loads `unpdf`, joins page strings with LF, and marks a PDF with any blank page (or no pages) `no_text_layer`. That failure returns an empty `bytes` string; successful extraction returns extracted text rather than raw PDF bytes. Consequently raw-file-byte identity must not be inferred from this adapter. `parseSource` reads again, marks no-text-layer failures `failed` and drops their chunks; success stores current text/hash, marks `read`, records `reparsedHash`, deletes old chunks, and creates one document-wide chunk with UTF-16 offsets. It tags that chunk with the current boundary string. `rechunk` actually implements `line` splitting; every other boundary acts as a whole document. Parser/tokenizer strings affect revision metadata/hash, but these captured functions do not select alternate parser/tokenizer implementations from those strings. Chunk-text replacement always refuses. Sources: `modules/rag-studio/src/extract.ts:3-16`, `modules/rag-studio/src/parse.ts:4-49`, `modules/rag-studio/src/rechunk.ts:5-43`, `modules/rag-studio/src/span.ts:1-3`, `modules/rag-studio/src/revision.ts:31-60`, `docs/specs/rag-studio/SPEC.md:25-30`.

**Revision and retrieval semantics.** Defaults are plain/document/utf16, lexical true, embedding false, K=4. A revision snapshots sorted source IDs and content hashes, hashes the four configurable pipeline fields, and records its Location, parameters, and fill. Fill is failed for a Location failure flag, orphan chunk, missing member, or source/chunk hash mismatch. `setPipeline` converts K with `Number` and other fields with `String`; its field union is a TypeScript contract, with no runtime field/value validation in this function. Search requires an existing revision but uses its Location to filter current sources/chunks; it excludes missing, unread, failed, wrong-Location, and hash-stale sources, then performs case-sensitive substring matching and orders by source path/start. It does not consult the revision's stored membership/hash list. Thus snapshot metadata is observable, but replay of historical corpus contents is not established by this implementation. Sources: `modules/rag-studio/src/context.ts:46-55,76-88`, `modules/rag-studio/src/revision.ts:5-78`, `modules/rag-studio/src/search.ts:4-25`.

**Question, trace, and proof contracts.** `ask` rejects missing/failed revisions, Location failure, and any live stale chunk in that Location; it then filters search results to the revision boundary, retains the first K, concatenates their exact stored text, and records hits/dropped/K. Diagnosis distinguishes no admitted owner, only unread/failed owners, a read owner missing from hits, a dropped hit, and a retained hit. Results contain all four reason keys, status/span, hits, dropped IDs, prompt text/IDs, and `retrievalOptional = matches.length <= K`; there is no model call. `saveQuestion` stores text/span/revision after checking revision existence. Retrieval proof requires exact chunk span equality, saved revision equality, a trace, matching K when both values exist, and inclusion after dropped IDs are removed. Citation proof slices a containing current chunk at the saved coordinates and checks the sentence, rather than merely checking an ID. Sources: `modules/rag-studio/src/ask.ts:9-40`, `modules/rag-studio/src/lights.ts:4-30`, `modules/rag-studio/src/prompt.ts:3-12`, `modules/rag-studio/src/report.ts:3-33`, `modules/rag-studio/src/proof.ts:4-33`, `modules/rag-studio/src/context.ts:137-148`.

An unresolved linkage is directly visible: `ask` calls `record(revisionId, ...)`, while retrieval proof requests `store.trace(questionId)`. `record` stores exactly the supplied key. Tests that assert successful retrieval proof manually insert traces keyed by the saved question ID. A complete public ask/save/proof linkage cannot be claimed from these files. Comparison additionally treats the proof-set ID as the snapshot string, requires equal snapshots and exactly one changed pipeline field, and iterates all questions returned by the Store; the module does not filter that list by revision or Location. It resolves changed spans against current chunks/source text. These observations identify caller/Store obligations and historical-proof uncertainty, not an observed runtime failure. Sources: `modules/rag-studio/src/ask.ts:29`, `modules/rag-studio/src/trace.ts:3-6`, `modules/rag-studio/src/proof.ts:12-25`, `modules/rag-studio/src/compare.ts:5-50`, `modules/rag-studio/test/acceptance.test.ts:245-266`, `modules/rag-studio/test/proof.test.ts:57-71`.

**Maintenance and exclusions.** `noteBytes` detects changed readable text, makes the source unread, and clears its reparse marker without cutting. Reparse changes source text/hash/status only; failed reads set a Location failure flag. Rechunk requires `reparsedHash === contentHash`, replaces only that source's chunks, and sets their cut policy. Removal deletes a source row, leaving chunks until explicit orphan deletion; orphan deletion scans the Store and removes chunks lacking sources. `runPass` dispatches exactly one operation; redo-numbers returns `not_applicable` without work. `runPasses` refuses multiple/zero passes and throws on a singleton; callers execute via `runPass`. `enableEmbedding` always returns `embedding_off`. No embedding-model invocation or vector representation is present in the inspected production module. Multirow replacement has no transaction API in the Store contract, so durable rollback/partial-write behavior is unverified. Sources: `modules/rag-studio/src/reparse.ts:4-38`, `modules/rag-studio/src/rechunk.ts:18-43`, `modules/rag-studio/src/orphan.ts:4-15`, `modules/rag-studio/src/passes.ts:7-17`, `modules/rag-studio/src/guard.ts:3-6`, `modules/rag-studio/src/embed-off.ts:1-3`, `modules/rag-studio/src/context.ts:92-123`.
