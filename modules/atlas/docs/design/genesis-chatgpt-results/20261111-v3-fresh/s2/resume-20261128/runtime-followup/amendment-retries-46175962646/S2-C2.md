**Result: No.** Packaged builds must not trust `ELECTRON_RENDERER_URL` to select a support page. The cited baseline says packaged origin selection ignores the development URL; a page from an arbitrary origin must not gain the privileged renderer’s authority.

**Enforcement boundary:** The shared IPC wrapper checks `senderFrame.url` against the renderer origin. For wrapped `ipcMain.handle` channels, an untrusted call rejects with `Untrusted IPC sender`; for wrapped `ipcMain.on` channels, the event is dropped. That protection applies only to channels registered through the wrapper. Dock registers separately and checks its owning window’s main frame. Live and WSL register directly, outside the shared origin gate, so their handlers and preload/navigation reachability need separate review. Navigation also denies non-renderer navigation or opens it externally, and `window.api` is exposed by the app renderer preload. (S2-C2-1, `s2.l2.desktop-web`, “Privilege is checked at each request boundary”; S2-C2-2, `s2.l1.desktop-web`, §2 “Windows, persistence and IPC authority.”)

**Safe fix:** Keep packaged origin selection independent of `ELECTRON_RENDERER_URL`; preserve isolation, sandboxing, disabled Node integration, constrained navigation, and sender checks at each privileged IPC admission point. Audit separately registered handlers and preload exposure too; the shared wrapper alone does not cover them.

**CSP limits:** Only `object-src 'none'; base-uri 'self'` is enforced. The broader policy is report-only, with packaged compatibility cited as the reason. CSP therefore cannot replace origin validation, navigation controls, or IPC sender and handler checks. (S2-C2-1, `s2.l2.desktop-web`; S2-C2-2, `s2.l1.desktop-web`, §2.)
