### Session rendering and interactive requests

The session route reads location from the session, synchronizes catalog/editor/history on entry and attempts workspace bootstrap before rendering. Failure to load a session produces a toast and returns home. Root-session views aggregate child permission/question requests, hide normal prompt interaction while a request is pending and retain display preferences in KV. Wide layouts reserve sidebar space; this is source-observed layout logic, not a rendered-width result. (`packages/tui/src/routes/session/index.tsx:129–252`.)

Permission UI moves through decision/always/reject stages and replies with both session and request identity. “Always” confirmation describes the intended approval scope; actual authorization belongs to the server. Question UI preserves answer order, supports single/multiple/custom selection and provides explicit reject. Automatic approval is a separate context setting consumed on permission-asked events. Message renderers handle queued inputs and compaction summaries. Tool rendering dispatches recognized names, retains a generic fallback and can hide successful details; generic expanded output is a local display state. (`packages/tui/src/routes/session/permission.tsx:111–178,399`; `packages/tui/src/routes/session/question.tsx:14–78,128–131`; `packages/tui/src/context/permission.tsx:12`; `packages/tui/src/context/sync.tsx:248–250`; `packages/tui/src/routes/session/message.tsx:29–115`; `packages/tui/src/routes/session/tool.tsx:41–155`.)

### Terminal, editor, attention and themes

Clipboard combines OSC52 output with platform-specific commands. External editing writes a temporary file, suspends the renderer and restores it in `finally`. Editor integration discovers lock files or configured ports, uses loopback connections, carries selections into pending prompt context and cleans up reconnect/poll/socket work. Windows terminal helpers are platform/TTY guarded; the presence of an exported guard does not establish that every helper is active in `run`. ## Browser UI library

### Public primitives, accessibility and lifecycle

The UI README and manifest establish a Solid library with both component generations current, explicit component/context/theme exports and font/audio/style wildcards, with no workspace dependencies. App-shell and session-ui supply higher layers. Representative v1 Button/Dialog/Tooltip wrap Kobalte primitives and expose styling attributes; labels/content still depend on callers. Dialog close labels use i18n. The dialog provider manages stacked roots and opener focus, distinguishes detached lifetime from `showOwned`, and delays removal for closing. (`packages/ui/README.md:3–18`; `packages/ui/package.json`; `packages/ui/src/components/button.tsx:5–20`; `packages/ui/src/components/dialog.tsx:34–56`; `packages/ui/src/context/dialog.tsx:34–101,188–260`.)

V2 Field generates label/control identifiers and synchronizes `aria-labelledby`, descriptions and invalid state onto recognized controls. V2 Dialog composes header/body/footer and translates the close affordance. SegmentedControl handles controlled/uncontrolled value, deselection, Home/End and left/right DOM-order focus. Its arrow handler does not consult direction; the RTL skill requires direction-aware behavioral review. This is a concrete verification gap, not a blanket finding that every RTL interaction fails. (`packages/ui/src/v2/components/field-v2.tsx:40–109`; `packages/ui/src/v2/components/dialog-v2.tsx:63–106`; `packages/ui/src/v2/components/segmented-control-v2.tsx:45–86,158–183`; `.orchestra/skills/rtl-aware-development/SKILL.md:8–40`.)

Scroll helpers avoid editable targets and respect nested scroll ownership; custom thumbs are vertical. Auto-scroll tracks working/settling/user interruption and excludes nested gestures. Motion spring subscriptions attach, snap across a state key, and dispose. These inspected mechanisms support family-level accounts of other controls/styles, not universal keyboard, animation or accessibility correctness.
