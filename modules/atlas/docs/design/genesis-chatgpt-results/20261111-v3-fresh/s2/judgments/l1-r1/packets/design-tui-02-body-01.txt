## Terminal application

### Entry, ownership and lifetime

`@orchestra/tui` exports `run`, configuration, runtime, keymap, providers and plugin surfaces. Current ownership explicitly permits core because the terminal runs in that process; dependencies and direct imports corroborate this. The older extraction specification's SDK-only/no-core target is not the current architecture. The README also says assets/generated files are “None,” while the actual tree and theme imports contain 33 preset JSONs: that sentence cannot substitute for the inventory. (`packages/tui/package.json`; `packages/tui/src/index.tsx:1`; `packages/tui/README.md:7–22`; `packages/tui/src/routes/session/tool.tsx:1–6`; `docs/specs/tui-package.md:5–31`.)

The CLI adapter `runTui` loads resolved config and supplies transport, directory, Global paths and pluginHost to `run`. Its supplied `start` and `dispose` methods are empty. `attach.prepare` enforces fork/continue/session relationships, creates authorization headers, preflights a requested session, and preserves a remote directory if it is not an existing local path. The run handler separates attached/daemon transport; `--mini` rejects incompatible command/JSON/non-TTY use before entering the TUI. These are inspected boundary adapters, not a claim that all CLI execution is covered. (`apps/cli/src/tui.ts:7–41`; `apps/cli/src/commands/handlers/attach.ts:34–66`; `apps/cli/src/commands/handlers/run.ts:35–113`.)

`run` scopes renderer acquisition/release with Effect, disables automatic Ctrl-C exit, initializes key routing, registers plugin/audio cleanup and handles SIGHUP by destroying the renderer and resolving shutdown. It waits for shutdown before final output. The provider chain supplies runtime, routes, transport, theme, selection, dialogs, synchronization and editor contexts. `App` invokes the injected host and marks readiness in `finally`, including after startup failure. The route union is home/session/plugin, and initial route data is validated. Continue waits for bootstrap; specified-session fork waits for complete synchronization. (`packages/tui/src/app.tsx:136–146,180–359,384–416,474–533`; `packages/tui/src/context/route.tsx:6–53`; `packages/tui/src/context/runtime.tsx:3–49`.)

The lifecycle regression source actually calls `run` with a mocked renderer/test renderer and asserts destruction, cleared title, one host disposal and restored SIGHUP listener count. Its second case checks epilogue ordering after cleanup. That is stronger linkage than a reimplemented algorithm test, but remains unexecuted and does not establish real-terminal restoration. (`packages/tui/test/app-lifecycle.test.tsx:10–118`; `packages/tui/README.md:37–40`.)

### V2 transport, hydration and state

`SDKProvider` constructs the V2 client and action/catalog adapters. It accepts an injected event subscription or starts an abortable SSE loop, batches events over a short interval, marks disconnection offline and backs off reconnection. Cleanup stops the stream, subscription and timers. The injected-event branch has different connection monitoring from SSE. `useEvent` separates event payload from directory/workspace envelope metadata; it does not itself enforce location filtering. (`packages/tui/src/context/sdk.tsx:9–128`; `packages/tui/src/context/event.ts:9–31`.)

`SyncProvider` maintains bootstrap state, session lists, message projections, request queues and per-session hydration bookkeeping. Bootstrapping obtains catalog/project data before partial readiness, then ancillary commands/integrations/status before complete readiness; fatal bootstrap errors exit. Events project only already-synced or actively hydrating sessions. Message history is newest-first internally and reversed for display, bounded to the latest 100 projected rows. Directory/workspace filtering is a separate predicate. (`packages/tui/src/context/sync.tsx:57–190,384–473`; `packages/tui/src/context/session-history.ts:12–15,77–90,239–242`.)

`session.sync` coalesces concurrent loads, fetches session/history/todo, and preserves message IDs touched by live events while history was in flight. It clears the hydrating/in-flight markers in `finally`. A rejected history request becomes an empty list, so successful session synchronization does not prove complete history retrieval. The read regression mounts the production providers, delays history and verifies a live delta survives; another case avoids projection for an unsynced session. (`packages/tui/src/context/sync.tsx:498–537`; `packages/tui/test/cli/cmd/tui/sync-live-hydration.test.tsx:137–189`; `packages/tui/test/cli/cmd/tui/sync-fixture.tsx`.)

`DataProvider` is a separate normalized cache, with location keys serialized from directory and workspace ID. Initial refreshes use `Promise.allSettled` and log failures. Catalog loading maps provider/model/agent/config endpoints into terminal choices, filters disabled providers and retains stable agent IDs separately from display names. `createSessionActions` switches agent then model; prompt optionally admits editor context through synthetic input with `resume:false`, then posts prompt/files/agent source spans. Revert stages files; unrevert clears staging. Read tests assert actual adapter request paths and order. (`packages/tui/src/context/data.tsx:35–52,243–256`; `packages/tui/src/context/catalog.ts:24–80,174–215`; `packages/tui/src/context/session-actions.ts:7–92`; `packages/tui/test/context/session-actions.test.ts:88–125`.)

### Selection, local persistence and prompt admission

Local state validates model choices against catalog data and falls back through explicit/configured/recent/provider defaults. Per-agent keys use stable identity; recents deduplicate and cap at ten. Model preferences, KV, prompt history and stash live under Global state paths. KV snapshots are serialized through a same-process promise chain with file locking; atomic writes use a temporary file and rename. These observations do not establish cross-process read-modify-write merge safety. History/stash retain up to 50 records and tolerate damaged entries; neither is the server conversation journal. (`packages/tui/src/context/local.tsx:36–49,65–98,165–245`; `packages/tui/src/context/kv.tsx:15–60`; `packages/tui/src/util/persistence.ts:22–33`; `packages/tui/src/prompt/history.tsx:11–37`; `packages/tui/src/prompt/stash.tsx:15–45`; `packages/tui/src/util/agent.ts:3–27`.)

Prompt submission has an in-flight guard around awaited admission, synchronizes IME/plain text, rejects disabled/empty/autocomplete-owned input and requires agent/model selection. For a new session it resolves the requested directory/project copy before creating the session. Extmarks expand into text/file/agent parts. The dispatch branch handles demo, shell, recognized slash command or normal prompt; it then records history, clears input and schedules navigation. Several action promises are launched with rejection handlers instead of awaited success, so clearing does not establish server acceptance or rollback. (`packages/tui/src/component/prompt/index.tsx:919–1089`.)

The submit-race test explicitly mirrors the production shape rather than importing the mounted prompt. Its intended single-admission assertion therefore cannot alone prove production integration. Autocomplete owns a keyboard mode while visible, tracks input position and inserts source-bearing extmarks. Moving can create a Git worktree project copy or move an existing session and inject non-resuming context. Component-level history/stash/frecency files are compatibility re-exports; `component/prompt/cwd.ts` is verified empty. (`packages/tui/test/cli/tui/prompt-submit-race.test.ts:1–20,52–97`; `packages/tui/src/component/prompt/autocomplete.tsx:90–210`; `packages/tui/src/component/prompt/move.tsx:20–63,115–133`; `packages/tui/src/component/prompt/{history,stash,frecency}.tsx`; `packages/tui/src/component/prompt/cwd.ts`.)

### Session rendering and interactive requests

The session route reads location from the session, synchronizes catalog/editor/history on entry and attempts workspace bootstrap before rendering. Failure to load a session produces a toast and returns home. Root-session views aggregate child permission/question requests, hide normal prompt interaction while a request is pending and retain display preferences in KV. Wide layouts reserve sidebar space; this is source-observed layout logic, not a rendered-width result. (`packages/tui/src/routes/session/index.tsx:129–252`.)

Permission UI moves through decision/always/reject stages and replies with both session and request identity. “Always” confirmation describes the intended approval scope; actual authorization belongs to the server. Question UI preserves answer order, supports single/multiple/custom selection and provides explicit reject. Automatic approval is a separate context setting consumed on permission-asked events. Message renderers handle queued inputs and compaction summaries. Tool rendering dispatches recognized names, retains a generic fallback and can hide successful details; generic expanded output is a local display state. (`packages/tui/src/routes/session/permission.tsx:111–178,399`; `packages/tui/src/routes/session/question.tsx:14–78,128–131`; `packages/tui/src/context/permission.tsx:12`; `packages/tui/src/context/sync.tsx:248–250`; `packages/tui/src/routes/session/message.tsx:29–115`; `packages/tui/src/routes/session/tool.tsx:41–155`.)

### Configuration, keys, dialogs and plugins

`TuiConfig.Info` owns theme, keybindings, plugins, attention, prompt, scrolling, diff, cursor and mouse configuration. Resolve disables terminal suspend when unsupported and supplies Ctrl-Z undo, enables mouse by default, and leaves attention disabled with subordinate sound/notification defaults. CLI loading decodes each file, merges later scalar values and merges keybinding/plugin-enabled maps. Core file discovery is delegated, not inspected. Keymap centralizes legacy-to-command translation, leader timing, key aliases and a mode stack whose symbol-based disposers tolerate out-of-order removal. Modal dialogs coordinate that stack, focused renderables and escape handling. (`packages/tui/src/config/index.tsx:61–75,101–135`; `apps/cli/src/tui-config.ts:10–30`; `packages/tui/src/config/keybind.ts:41–45,252–447`; `packages/tui/src/keymap.tsx:53–133,214–243`; `packages/tui/src/ui/dialog.tsx:70–165`; `packages/tui/src/ui/dialog-select.tsx:23–90`.)

Plugin interfaces expose commands/status/routes/slots and injected host start/dispose. Route registrations stack by name, newest wins, and disposing restores the previous entry. Slots require registry setup. The API facade creates an abort signal but does not abort it here, while `onDispose` returns a no-op; this is not a complete disposal implementation. Builtins enumerate 12 home/sidebar/system contributions. Diff-viewer registers session/working/branch comparison routes; which-key contributes commands/slots and starts disabled; notifications deduplicate pending requests and respond to busy-to-idle transitions. Their presence does not prove default activation, particularly with the inspected CLI's empty host. (`packages/tui/src/plugin/runtime.tsx:12–69`; `packages/tui/src/plugin/api.ts:11–51`; `packages/tui/src/plugin/slots.tsx:25–64`; `packages/tui/src/feature-plugins/builtins.ts:21–35`; `packages/tui/src/feature-plugins/system/diff-viewer.tsx:48–103,794–820`; `packages/tui/src/feature-plugins/system/which-key.tsx:532–604`; `packages/tui/src/feature-plugins/system/notifications.ts:31–80`.)

### Terminal, editor, attention and themes

Clipboard combines OSC52 output with platform-specific commands. External editing writes a temporary file, suspends the renderer and restores it in `finally`. Editor integration discovers lock files or configured ports, uses loopback connections, carries selections into pending prompt context and cleans up reconnect/poll/socket work. Windows terminal helpers are platform/TTY guarded; the presence of an exported guard does not establish that every helper is active in `run`. Clipboard/editor child-process sites are explicitly allowlisted. None was exercised. (`packages/tui/src/clipboard.ts:23–125`; `packages/tui/src/editor.ts:26–100`; `packages/tui/src/context/editor.ts:112–180,276–318,390–407`; `packages/tui/src/terminal-win32.ts:30–130`; `script/spawn-allowlist.json:64–65`.)
