## Terminal application

### Entry, ownership and lifetime

`@orchestra/tui` exports `run`, configuration, runtime, keymap, providers and plugin surfaces. Current ownership explicitly permits core because the terminal runs in that process; dependencies and direct imports corroborate this. The older extraction specification's SDK-only/no-core target is not the current architecture. The README also says assets/generated files are “None,” while the actual tree and theme imports contain 33 preset JSONs: that sentence cannot substitute for the inventory. Its supplied `start` and `dispose` methods are empty. `attach.prepare` enforces fork/continue/session relationships, creates authorization headers, preflights a requested session, and preserves a remote directory if it is not an existing local path. (`apps/cli/src/tui.ts:7–41`; `apps/cli/src/commands/handlers/attach.ts:34–66`; `apps/cli/src/commands/handlers/run.ts:35–113`.)

### V2 transport, hydration and state

`SDKProvider` constructs the V2 client and action/catalog adapters. It accepts an injected event subscription or starts an abortable SSE loop, batches events over a short interval, marks disconnection offline and backs off reconnection. Cleanup stops the stream, subscription and timers. The injected-event branch has different connection monitoring from SSE. `useEvent` separates event payload from directory/workspace envelope metadata; it does not itself enforce location filtering. (`packages/tui/src/context/sdk.tsx:9–128`; `packages/tui/src/context/event.ts:9–31`.)

`SyncProvider` maintains bootstrap state, session lists, message projections, request queues and per-session hydration bookkeeping. Bootstrapping obtains catalog/project data before partial readiness, then ancillary commands/integrations/status before complete readiness; fatal bootstrap errors exit. Events project only already-synced or actively hydrating sessions. Message history is newest-first internally and reversed for display, bounded to the latest 100 projected rows. Directory/workspace filtering is a separate predicate. (`packages/tui/src/context/sync.tsx:57–190,384–473`; `packages/tui/src/context/session-history.ts:12–15,77–90,239–242`.)

`session.sync` coalesces concurrent loads, fetches session/history/todo, and preserves message IDs touched by live events while history was in flight. It clears the hydrating/in-flight markers in `finally`. A rejected history request becomes an empty list, so successful session synchronization does not prove complete history retrieval. The read regression mounts the production providers, delays history and verifies a live delta survives; another case avoids projection for an unsynced session. (`packages/tui/src/context/sync.tsx:498–537`; `packages/tui/test/cli/cmd/tui/sync-live-hydration.test.tsx:137–189`; `packages/tui/test/cli/cmd/tui/sync-fixture.tsx`.)

`DataProvider` is a separate normalized cache, with location keys serialized from directory and workspace ID. Initial refreshes use `Promise.allSettled` and log failures. Catalog loading maps provider/model/agent/config endpoints into terminal choices, filters disabled providers and retains stable agent IDs separately from display names. (`packages/tui/src/context/data.tsx:35–52,243–256`; `packages/tui/src/context/catalog.ts:24–80,174–215`.)

## V2 session action boundary

`createSessionActions(client)` is a narrow adapter over the supplied `Orchestra.make` client. It exposes create, prompt, interrupt, compact, shell, permission reply, revert, unrevert and command. Its comment explicitly targets V2 `/api/session/:id/*` and records that legacy `/session/:id/*` abort/shell/command/summarize/revert/unrevert routes are not served by the V2 server. Compatibility here translates caller inputs and action names into V2 methods; the function has no legacy-route fallback. The table states the requests selected by this adapter, corroborated by pinned protocol declarations and unexecuted request assertions, not by a live server exercise. Every route below uses POST. (`packages/tui/src/context/session-actions.ts:4–82`; `packages/tui/test/context/session-actions.test.ts:5–27,30–149`.)

| Adapter operation | V2 path | Payload and specific boundary |
|---|---|---|
| `create` | `/api/session` | Sends agent and model; translates model `modelID` to `id`, preserving providerID and optional variant. Sends `location: { directory, workspaceID }` only when directory is truthy; workspaceID alone is therefore not forwarded. The source comment assigns omitted-directory placement to the server's working directory. |
| Selection before `prompt` or `command` | `/api/session/:sessionID/agent`, then `/api/session/:sessionID/model` | Awaits `{ agent }`, then `{ model: { providerID, id, variant } }`. Selection is session state, rather than agent/model fields embedded in the final prompt or command. |
| `prompt` | Optional `/api/session/:sessionID/synthetic`, then `/api/session/:sessionID/prompt` | After selection, a truthy context sends `{ text: context, resume: false }` and is awaited; absent/empty context skips it. The final payload is `{ prompt: { text, files, agents } }`. The protocol success is an admitted input, not completed model execution. |
| `command` | `/api/session/:sessionID/command` | After selection, sends command, arguments and mapped files. The adapter requires an arguments string and files array; it has no agents/context field. The protocol describes rendering a configured command or MCP prompt and admitting the result. |
| `interrupt` | `/api/session/:sessionID/interrupt` | No body from this adapter. The protocol describes interruption of execution owned by the current process and an idle no-op. |
| `compact` | `/api/session/:sessionID/compact` | No model/body from this adapter; its comment uses the session's own model. Protocol result is `{ data: { compacted: boolean } }`; the description permits false when nothing needed summarizing and refuses a running session as busy. |
| `shell` | `/api/session/:sessionID/shell` | Sends `{ command }`, with no agent/model. The protocol requires a nonempty command and describes recording command/output in the session's location for the next turn without starting a turn. |
| `reply` | `/api/session/:sessionID/permission/:requestID/reply` | Carries both identities and a reply of `once`, `always` or `reject`; the wrapper does not expose the protocol's optional message field. |
| `revert` | `/api/session/:sessionID/revert/stage` | Sends `{ messageID, files: true }`; it stages or moves a reversible boundary with file changes. It does not call the separately declared revert commit route. |
| `unrevert` | `/api/session/:sessionID/revert/clear` | Clears the staged revert with no body. |

The route/payload witnesses are `packages/tui/src/context/session-actions.ts:10–79`; `packages/protocol/src/groups/session.ts:157–165,301–394,431–443,464–479,550–582,655–665`; `packages/protocol/src/groups/permission.ts:119–134`; and `packages/tui/test/context/session-actions.test.ts:30–149`. Protocol descriptions in the table are declared semantics; their presence does not establish runtime success.

The adapter's `Model` shape is `{ providerID: string; modelID: string; variant?: string }`. Prompt callers must supply text, agent, model, files and agents arrays, using empty arrays when there are none. A file's legacy-facing `url`/`filename` become `uri`/`name`; only its optional `source.text` span is copied as start/end/text, with `value` renamed to `text`. Other legacy file-source fields are not forwarded. Agent mentions preserve name and map their optional source start/end/value to start/end/text. Thus editor context is a separate non-resuming synthetic request, while mention source spans remain in the final prompt. Session actions use sessionID, and permission replies additionally require requestID; directory/workspace placement is accepted only by create in this wrapper. (`packages/tui/src/context/session-actions.ts:4–5,19–53,60–79,84–92`; `packages/tui/test/context/session-actions.test.ts:65–85,88–125,127–149`.)

The awaits establish order within one call, not an atomic transaction or a lock across callers. The adapter supplies no catch/rollback, cancellation option or retry loop: a failed selection or synthetic request stops later steps, and an earlier successful step is not undone here. Prompt/command expose none of the protocol's optional id, delivery or resume controls, and synthetic is sent without an explicit id; this boundary therefore does not establish stable-ID retry reconciliation after an ambiguous failure. Returned client promises/results are passed through. The test recorder uses the real client and a replaced transport to assert paths, bodies, context/no-context branches and order, but those tests were only read; they do not establish a passing run, server execution, authorization or filesystem reversal. (`packages/tui/src/context/session-actions.ts:9–92`; `packages/protocol/src/groups/session.ts:333–367,464–472`; `packages/tui/test/context/session-actions.test.ts:5–27,30–149`.)

## Terminal interaction and supporting contracts

### Selection, local persistence and prompt admission

Local state validates model choices against catalog data and falls back through explicit/configured/recent/provider defaults. Per-agent keys use stable identity; recents deduplicate and cap at ten. Model preferences, KV, prompt history and stash live under Global state paths. KV snapshots are serialized through a same-process promise chain with file locking; atomic writes use a temporary file and rename. These observations do not establish cross-process read-modify-write merge safety. History/stash retain up to 50 records and tolerate damaged entries; neither is the server conversation journal. (`packages/tui/src/context/local.tsx:36–49,65–98,165–245`; `packages/tui/src/context/kv.tsx:15–60`; `packages/tui/src/util/persistence.ts:22–33`; `packages/tui/src/prompt/history.tsx:11–37`; `packages/tui/src/prompt/stash.tsx:15–45`; `packages/tui/src/util/agent.ts:3–27`.)

Prompt submission has an in-flight guard around awaited admission, synchronizes IME/plain text, rejects disabled/empty/autocomplete-owned input and requires agent/model selection. For a new session it resolves the requested directory/project copy before creating the session. Extmarks expand into text/file/agent parts. The dispatch branch handles demo, shell, recognized slash command or normal prompt; it then records history, clears input and schedules navigation. Several action promises are launched with rejection handlers instead of awaited success, so clearing does not establish server acceptance or rollback. (`packages/tui/src/component/prompt/index.tsx:919–1089`.)

The submit-race test explicitly mirrors the production shape rather than importing the mounted prompt. Its intended single-admission assertion therefore cannot alone prove production integration. Autocomplete owns a keyboard mode while visible, tracks input position and inserts source-bearing extmarks. Moving can create a Git worktree project copy or move an existing session and inject non-resuming context. Component-level history/stash/frecency files are compatibility re-exports; `component/prompt/cwd.ts` is verified empty. (`packages/tui/test/cli/tui/prompt-submit-race.test.ts:1–20,52–97`; `packages/tui/src/component/prompt/autocomplete.tsx:90–210`; `packages/tui/src/component/prompt/move.tsx:20–63,115–133`; `packages/tui/src/component/prompt/{history,stash,frecency}.tsx`; `packages/tui/src/component/prompt/cwd.ts`.)

### Session rendering and interactive requests

The session route reads location from the session, synchronizes catalog/editor/history on entry and attempts workspace bootstrap before rendering. Failure to load a session produces a toast and returns home. Root-session views aggregate child permission/question requests, hide normal prompt interaction while a request is pending and retain display preferences in KV. Wide layouts reserve sidebar space; this is source-observed layout logic, not a rendered-width result. (`packages/tui/src/routes/session/index.tsx:129–252`.)

Permission UI moves through decision/always/reject stages and replies with both session and request identity. “Always” confirmation describes the intended approval scope; actual authorization belongs to the server. Question UI preserves answer order, supports single/multiple/custom selection and provides explicit reject. Automatic approval is a separate context setting consumed on permission-asked events. Message renderers handle queued inputs and compaction summaries. Tool rendering dispatches recognized names, retains a generic fallback and can hide successful details; generic expanded output is a local display state.
