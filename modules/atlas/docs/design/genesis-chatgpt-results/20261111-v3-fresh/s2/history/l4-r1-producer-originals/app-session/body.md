# App/session operational maintenance

## Orientation

Use this protocol for changes or failures in the shared app/session surface at source revision `1cde2ff7a71bcf7aecb5d030917b577165135d38`. It builds on accepted L1–L3, preserving the app unit's 59-family scope and representative depth. Desktop main/preload, TUI actions and reusable UI retain their own owners; rendering them in the app does not transfer their authority. [Accepted basis: `s2.l3.app-session` § “Reading the handoffs”; `s2.l3.desktop-web` § “Orientation and evidence boundaries”; `s2.l3.design-tui` § “Orientation and accepted ownership”.]

The protocol is **maintenance guidance inferred from static evidence**. Explicit **instructions** below come from captured repository guidance. Existing assertions are verification candidates, not passing results. This campaign performs documentation work only. The source, dependency and evidence files bind every route to accepted bodies or pinned captures.

## Maintenance protocol

Start with the trigger and retain its identities: source revision, host/platform, connection key, transport-credential generation without disclosing secrets, server/directory scope, session or draft/tab, request ID, policy revision and callback generation. Distinguish a never-dispatched action, an ambiguous response, admitted input, visible user turn and completed provider work. For an exact retry, keep session, encoded prompt and delivery equivalent; preserve the separate context-projection comparison. A returned route value cannot revive an expired A→B→A callback. [Basis: `s2.l3.app-session` §§ “Enter the intended server and workspace”, “Submit once, then hand the draft to its session”.]

For a contract change, trace Schema → Protocol/Server → generated Client → app adapter → session/UI consumers. **Instructions:** keep browser-safe serializable contracts in Schema and runtime services with their domain; do not tighten legacy ID validators without a compatibility/migration decision. Public Protocol or Server `HttpApi` changes require `bun run generate` from `packages/client`, with review of generated diffs instead of hand-editing either generated tree. Client runtime may depend on Schema/Protocol, never Core/Server. [Sources: `packages/schema/AGENTS.md:3–9,71–83`; `AGENTS.md:1–2`.]

Include the TUI consumer when changing shared prompt contracts: its agent/model/synthetic/prompt operations are ordered but non-atomic, and its wrapper does not expose the protocol retry controls. Include the desktop owner when failure concerns startup, preload capability or native persistence: local HTTP-success readiness differs from WSL's authenticated health checks; a healthy remote fallback is not local-child recovery. Do not hide the recorded stable-exit restart discrepancy in a shared-app workaround. [Basis: `s2.l3.design-tui` § “Terminal input becomes admission through ordered, separate operations”; `s2.l3.desktop-web` § “Launch, choose a server and identify the health decision”.]

**Instructions for presentation changes:** use `language.t`/`language.plural`, keep existing English text and keys byte-for-byte, and keep plural/fallback logic in shared language APIs. Verify terminology with the prescribed external corpora when translating. Agent-screen work also preserves stable seat IDs, excludes secrets, defers large Atlas reads beyond roster paint and updates `docs/guides/agent-screen.md`. [Sources: `packages/app-shell/AGENTS.md:23–34`; `packages/session-ui/AGENTS.md:3–7`; `.orchestra/skills/agent-screen-maintenance/SKILL.md:8–41`.]

Update the real generator input and affected outputs together: app palette, UI tokens/sprites and desktop/TUI schemas have different producers. Preserve authored CSS and asset provenance limits. A user-facing change still updates its guide; maintenance skills/docs remain repository-only and must not become shipped seat skills. When a factual contract changes, refresh affected source pins, explanations and downstream build dependencies; navigation alone is not factual evidence. [Basis: `s2.l1.app-session` § “Assets, localization and verification evidence”; `s2.l3.design-tui` § “Generated products reach consumers through distinct maintenance paths”; **instruction:** `AGENTS.md:146–154`; dependency-refresh recommendation is an inference.]

## Verification and boundaries

For a future authorized code change, select focused regression evidence by failure boundary. Admission/policy uses `packages/app-shell/src/components/prompt-input/submit-admission.suite.ts`; owner/credential changes use `packages/app-shell/test-browser/prompt-admission-owner.suite.ts` and `server-transport.test.ts`. Health, permission ancestry and terminal scope have the corresponding `src/utils/server-health.test.ts`, `src/context/permission-auto-respond.test.ts` and `src/context/terminal.test.ts` under app-shell. Worker disposal uses `packages/session-ui/src/components/markdown-worker-queue.test.ts`. Delayed admission/handoff has `packages/app-shell/e2e/regression/draft-admission-handoff.spec.ts`. These are accepted assertion scopes, not complete integration or runtime evidence. [Basis: `s2.l1.app-session` § “Assets, localization and verification evidence”.]

**Prescribed gates, not executed here:**

- From the repository root, `bun run test:ci <package> [test files...] [-t pattern] [--os linux|windows|both]`. Confirm the runner's package selector rather than guessing it from a display name. Exact files run in given order; directory arguments are substring filters. The runner uploads a working-tree snapshot to a temporary branch, so this no-remote-write campaign cannot invoke it. Tests belong on GitHub Actions; root reserves any local-test exception to the owner, and this campaign has none. Full-suite cadence is per epic, with change-scoped tests per unit. [`AGENTS.md:156–179`.]
- Run `bun typecheck` from affected package directories, specifically `packages/app-shell` and/or `packages/session-ui`; their captured scripts invoke `tsgo -b` and `tsgo --noEmit`. Do not substitute direct `tsc`. Run `bun run check:guards --base origin/dev` before declaring an authorized product change complete. [`AGENTS.md:194–205`; `packages/app-shell/package.json`; `packages/session-ui/package.json`.]
- Before session/timeline edits, record a production benchmark baseline; compare afterward. Benchmark serially, retain raw diagnostics and assert scenario/metric completion without machine-dependent thresholds. `test:bench` includes Bun tests and Playwright; its manual status does not waive the root test policy. Resolve an authorized execution route before claiming this obligation satisfied. [`packages/app-shell/AGENTS.md:1–4`; `packages/app-shell/e2e/performance/AGENTS.md`; `packages/app-shell/package.json`.]
- Before editing/reviewing E2E tests, read the package's required official Playwright guides. Assert required UI state and exact identities; register waits before triggers, avoid timing sleeps and never retry state-changing actions. Manual benchmarks stay outside normal discovery. [`packages/app-shell/e2e/AGENTS.md:1–22`.]

Stop before restarting the app/server, blindly reissuing an uncertain mutation, claiming post-crash provider continuation, or expanding a presentation check into an OS/security/accessibility verdict. App guidance forbids agent restarts; root guidance requires separate continuation design. Keep browser/native draft durability, IPC coverage, terminal buffering, SkillV2 enforcement, focus/RTL/translation and asset gaps explicit. Report which authorized gate actually ran and its evidence; none ran here. Navigate to `s2.l4.desktop-web`, `s2.l4.design-tui` or `s2.l4.entry` for their declared common headings. [Sources: `packages/app-shell/AGENTS.md:6–8`; root `AGENTS.md:199–216`; `s2.l2.app-session` § “Verification limits and ownership use”; accepted L3 boundary sections above.]
