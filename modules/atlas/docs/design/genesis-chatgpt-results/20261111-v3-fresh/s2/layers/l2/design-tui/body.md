## Terminal lifetime and synchronized navigation

The TUI owns the OpenTUI/Solid application and runs through the CLI's injected transport, configuration and plugin host. Current ownership permits Core dependencies because it runs in the backend process. The older extraction proposal's SDK-only target describes historical intent. Another real discrepancy remains: the package README says there are no assets/generated files, although theme imports and the assigned inventory contain 33 presets. Maintain against the pinned manifest, implementation and inventory together. (`packages/tui/README.md:7–30`; `s2.l1.design-tui`, **Terminal application / Entry, ownership and lifetime**.)

`run` scopes renderer acquisition, keymap registration, plugin/audio cleanup and SIGHUP listener removal. Renderer destruction releases the shutdown wait before the epilogue is printed. Plugin startup marks the application ready in `finally`, including after startup failure; readiness is not proof that plugins loaded. Routes are home/session/plugin. Continue waits for bootstrap, while an explicit-session fork waits for complete synchronization to avoid the documented reconciliation race. (`packages/tui/src/app.tsx:180–359,384–416,474–533`; `s2.l1.design-tui`, **Terminal application / Entry, ownership and lifetime**.)

The terminal's SDK provider either consumes injected events or manages an abortable SSE reconnect loop; their connection monitoring differs. Event-envelope decoding and directory/workspace filtering are separate responsibilities. Sync projects only hydrated or hydrating sessions, merges event-touched messages over an in-flight history result, and coalesces concurrent hydration. A history failure becomes an empty list, so a synchronized session can still lack history. The displayed projection is bounded to the latest 100 rows. The separate DataProvider caches by directory/workspace identity and logs settled refresh failures. **Maintenance implication:** diagnose transport, location selection, bootstrap and history projection independently before treating a blank session as an empty server journal. (`packages/tui/src/context/sync.tsx:498–537`; `s2.l1.design-tui`, **Terminal application / V2 transport, hydration and state**.)

## V2 actions and prompt admission

The terminal session-action adapter translates inputs to V2 client calls; it has no legacy-route fallback. Before prompt or command, it awaits agent selection and then model selection. A truthy editor context adds an awaited synthetic request with `resume: false` before the final prompt. The protocol declares prompt success as durable input admission, not completed provider execution. These awaits order one invocation but provide no transaction, cross-caller lock, rollback or retry. (`packages/tui/src/context/session-actions.ts:7–79`; `packages/protocol/src/groups/session.ts:301–374,464–479`; `s2.l1.design-tui`, **V2 session action boundary**.)

Creation forwards location only when directory is truthy; workspaceID alone is omitted. Model `modelID` becomes `id`. File `url`/`filename` become `uri`/`name`, and only the optional text span is retained from file-source metadata. Mention spans similarly rename `value` to `text`. Prompt requires files and agents arrays; command exposes files and arguments but no context or agents input. Neither wrapper exposes the protocol's optional prompt/command id, delivery or resume controls. **Maintenance implication:** an ambiguous failure cannot be treated as a reconciled stable-ID retry at this boundary. (`packages/tui/src/context/session-actions.ts:19–92`; `packages/protocol/src/groups/session.ts:333–367`; `s2.l1.design-tui`, **V2 session action boundary**.)

| Operation | Declared boundary and adapter behavior |
|---|---|
| Interrupt / compact | Interrupt addresses execution owned by the current process; idle interruption is a declared no-op. Compact uses the session model, can report no compaction, and declares running sessions busy. |
| Shell | Sends a command without agent/model; the protocol describes recording command/output in the session location without starting a turn. |
| Permission reply | Sends sessionID, requestID and once/always/reject; the adapter omits the protocol's optional message. UI confirmation does not establish server authorization. |
| Revert / unrevert | Stages a reversible boundary with `files: true` or clears it. The wrapper does not call the separately declared commit route. |

These are pinned declarations and call selections, not observed server outcomes. (`packages/tui/src/context/session-actions.ts:55–63`; `packages/protocol/src/groups/session.ts:379–394,431–443,550–582,655–665`; `packages/protocol/src/groups/permission.ts:119–134`; `s2.l1.design-tui`, **V2 session action boundary**.)

At the prompt, an in-flight guard protects overlapping submission; IME text, autocomplete ownership, agent/model selection and new-session directory resolution precede dispatch. Extmarks supply text/file/agent parts. Demo, shell, slash command and ordinary prompt take different branches. Several action promises only attach rejection handlers; history append, input clearing and navigation can occur before acceptance. The submit-race test mirrors the production shape rather than mounting the prompt. **Gap:** actual prompt integration and failure recovery remain unexecuted. (`packages/tui/src/component/prompt/index.tsx:919–1089`; `s2.l1.design-tui`, **Terminal interaction and supporting contracts / Selection, local persistence and prompt admission**.)

## Terminal configuration, persistence and extensions

`TuiConfig.Info` controls input, appearance, scrolling, plugins and attention. Resolution defaults mouse on and attention off; unsupported terminal suspension disables that binding and adds Ctrl-Z undo. CLI loading decodes each file, lets later scalar keys win and merges keybinding/plugin-enabled maps. File discovery remains Core-owned; repository examples and user guides do not prove the entire discovery path. (`packages/tui/src/config/index.tsx:61–75,101–135`; `apps/cli/src/tui-config.ts:10–30`; `s2.l1.design-tui`, **Terminal interaction and supporting contracts / Configuration, keys, dialogs and plugins** and **Storybook, fixtures and design records**.)

Selection validates catalog choices, retains stable agent IDs independently of display names, and caps recent models at ten. KV, preferences, prompt history and stash live under Global state paths. Same-process serialization, locking and temporary-file rename protect writes without establishing cross-process merge safety. History/stash cap at 50 and tolerate damaged records; they serve local recall, not durable conversation ownership. Compatibility prompt-history/stash/frecency exports and the empty `component/prompt/cwd.ts` are boundaries to preserve, not separate persistence mechanisms. (`s2.l1.design-tui`, **Terminal interaction and supporting contracts / Selection, local persistence and prompt admission**; instruction: `AGENTS.md`, **Agent Names**.)

Keymap aliases, leader timing and a disposable mode stack mediate dialogs, focused controls and autocomplete. Plugin routes stack by name, with removal restoring earlier registrations; slots require setup. Builtins provide home/sidebar/system features, including diff views, which-key and notifications, but installation and activation are separate. The inspected CLI host has empty start/dispose methods; the API lifecycle signal has no abort here and `onDispose` is a no-op. **Maintenance implication:** feature files do not establish active features or complete cleanup. Trace the injected host before changing a plugin. (`apps/cli/src/tui.ts:27–40`; `packages/tui/src/plugin/api.ts:11–51`; `packages/tui/src/plugin/runtime.tsx:12–69`; `s2.l1.design-tui`, **Terminal interaction and supporting contracts / Configuration, keys, dialogs and plugins**.)

## Terminal display, native integrations and simulation

Session entry synchronizes its location, editor, catalog and history; load failure returns home with a toast. Root-session views aggregate child permission/question requests and suppress normal prompt interaction while requests are pending. Permission decisions retain session/request identity; questions preserve answer order and allow rejection. Tool rendering has recognized-name dispatch and a generic fallback, while preferences and disclosure are local display state. Transcript export sorts selected message kinds and optionally includes reasoning/tool details/metadata; omitted kinds make it a presentation projection. (`packages/tui/src/util/transcript.ts:22–82`; `s2.l1.design-tui`, **Terminal interaction and supporting contracts / Session rendering and interactive requests** and **Supporting contracts: display, export, demos and replay**.)

Small helpers carry meaningful contracts: duration units differ between formatters, model parsing preserves slashes, Windows paths have a realpath fallback, previews bound Unicode code points, and patch summaries return empty on failure. Error formatting can set `process.exitCode`. Renderer helpers clear titles, cache frame-local layout, choose scroll behavior and clean timers; selection clears before asynchronous clipboard success. Parser declarations mix pinned URLs with moving query branches. **Maintenance implication:** preserve these units, side effects and provenance when changing apparently cosmetic code. (`s2.l1.design-tui`, **Terminal interaction and supporting contracts / Supporting contracts: display, export, demos and replay**.)

Clipboard combines OSC52 with platform commands. External editing suspends the renderer and restores it in `finally`; editor integration owns loopback/reconnect/poll cleanup. Windows helpers are platform/TTY guarded, not universally active. Focus/config-gated attention sanitizes and bounds text; lazy audio resources have disposal. Their source contracts and spawn allowlist do not establish native behavior. Mini/demo commands instead manufacture local messages and requests without provider execution; the waiting map has no observed abandoned-request cleanup. Mini replay filters/tails display, and thinking disclosure defaults to hidden with legacy migration. (`s2.l1.design-tui`, **Terminal interaction and supporting contracts / Terminal, editor, attention and themes** and **Supporting contracts: display, export, demos and replay**.)

## Browser UI ownership, lifecycle and accessibility

`packages/ui` supplies the Solid library; both component generations remain current, and app-shell/session-ui add higher layers. Its declared package boundary has no workspace dependencies. Representative Kobalte-based controls supply primitive behavior and styling hooks while callers supply meaningful content and labels. V2 Field wires generated IDs, descriptions and invalid state only onto recognized control slots. This is a concrete association mechanism, not proof for arbitrary nested controls. (`packages/ui/README.md:3–18`; `packages/ui/src/v2/components/field-v2.tsx:40–109`; `s2.l1.design-tui`, **Browser UI library / Public primitives, accessibility and lifecycle**.)

DialogProvider owns roots, stack removal and conditional opener-focus restoration; closing is delayed. Ordinary dialog roots are detached, whereas `showOwned` opts into the caller's lifetime. Lists virtualize ordinary rows while retaining active/focused items, with combobox/grid semantics. Scroll helpers respect editable targets and nested ownership; auto-scroll tracks work, settling and user interruption. Spring subscriptions dispose and snap across state keys. **Maintenance implication:** preserve focus and resource ownership across navigation, independently of styling. (`packages/ui/src/context/dialog.tsx:34–101,188–260`; `s2.l1.design-tui`, **Browser UI library / Public primitives, accessibility and lifecycle**.)

SegmentedControl supports controlled/uncontrolled values, deselection and Home/End. Its left/right handler follows DOM order without consulting direction. The RTL maintenance instruction requires direction-aware interaction review; this establishes a specific verification gap, not a universal RTL failure. No browser, screen-reader, motion or contrast result is inferred. (`packages/ui/src/v2/components/segmented-control-v2.tsx:45–86,158–183`; `.orchestra/skills/rtl-aware-development/SKILL.md`; `s2.l1.design-tui`, **Browser UI library / Public primitives, accessibility and lifecycle**.)

Context helpers gate children on readiness and reject absent/falsy context. FileComponentProvider injects a component; WorkerPoolProvider selects supplied pools without creating or disposing workers. Custom-element typing does not register an element. Markdown configures links, highlighting and math, with text fallback for failed language loading; parser configuration alone does not establish final-HTML sanitization. These ownership and trust limits remain with consumers. (`packages/ui/src/context/helper.tsx:3–38`; `packages/ui/src/context/worker-pool.tsx:4–20`; `s2.l1.design-tui`, **Browser UI library / Public primitives, accessibility and lifecycle**.)

## Localization, direction and two theme systems

UI policy requires i18n keys for visible copy and accessible labels, preserves intentional English source text, and requires terminology/corpus verification. Runtime keeps locale and layoutLocale independent, uses English fallback, caches at most 32 plural-rule entries and substitutes missing template parameters with empty strings when substitution runs. The 63 dictionary/shared-copy files do not establish 63 validated languages. Glossaries are guidance; complete key/corpus/translation quality was not audited. The TUI's separate policy remains English-only. (`packages/ui/AGENTS.md`; `packages/ui/src/context/i18n.tsx:20–68`; `packages/tui/README.md:28–30`; `s2.l1.design-tui`, **Browser UI library / Localization and desktop themes**.)

Terminal themes use `defs` plus `theme`. Priority is defaults, plugin installs, custom files, then generated system palette; configuration selection outranks persisted choice and SIGUSR2 triggers discovery refresh. Desktop themes instead have identity plus light/dark variants resolved into both generations of CSS tokens. Their schemas and storage paths must not be interchanged. (`packages/tui/src/theme/index.ts:120–182`; `packages/tui/src/context/theme.tsx:37–60,121–179`; `s2.l1.design-tui`, **Terminal interaction and supporting contracts / Terminal, editor, attention and themes** and **Browser UI library / Localization and desktop themes**.)

Browser ThemeProvider lazily loads presets, normalizes the old default ID, persists choice, responds to storage/media changes and guards asynchronous preview before commit/cancel. The imperative loader separately owns a style element and exposes `auto` scheme; its URL loader returns JSON without runtime schema decoding. **Maintenance implication:** choose the intended API and validate downloaded theme input at its responsible boundary rather than relying on a TypeScript annotation. Token/CSS and representative preset evidence does not establish every selector, palette or contrast state. (`packages/ui/src/theme/context.tsx:87–104,147–222,337–379`; `packages/ui/src/theme/loader.ts:6–30,78–111`; `s2.l1.design-tui`, **Browser UI library / Localization and desktop themes**.)
