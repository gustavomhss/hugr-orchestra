# Genesis S2 — desktop/web maintenance runbook

## Orientation

`s2.l4.desktop-web` prescribes maintenance at source revision `1cde2ff7a71bcf7aecb5d030917b577165135d38`, using accepted `s2.l3.desktop-web` for integrated boundaries and `s2.l1.desktop-web` for precise implementation/test locations. **Instructions** below attribute repository rules; **protocol** denotes maintenance recommendations derived from that evidence. ## Maintenance protocol

**1. Establish the failed boundary before editing.** Record source/build/channel and OS, owned versus shared server mode, selected server key and credential-context generation, directory/window identity, and relevant profile/tab/runtime generation. Distinguish local launch failure from healthy-remote selection, stream disconnection, rejected capability and uncertain native effect. Read run-scoped main/server/renderer diagnostics; compare launch-stage timestamps and cold/warm behavior. Preserve logs as data. Startup guidance's older timings are context, not a present performance budget. (`s2.l3.desktop-web`, “Launch, choose a server and identify the health decision” and “Reconnect without transferring work to a replacement owner”; `.orchestra/skills/desktop-startup-maintenance/SKILL.md:10–37`; `.orchestra/skills/app-log-hygiene/SKILL.md:8–16`.)

**2. Choose the edit owner and evidence needed to deepen it.** The following routes are recommendations grounded in accepted source observations; they do not authorize product rewrites. **Instruction:** child creation uses `ChildProcessSpawner`, `Process` or `Process.interactive`, with existing exceptions recorded in `script/spawn-allowlist.json`; additions require the lead. Preserve the main README's distinct RPC authorities and named native-workflow paths. (`AGENTS.md:168–173`; `apps/desktop/src/main/README.md:29–34`.)

| Trigger | Precise owner and safe boundary | Evidence to deepen before claiming resolution |
|---|---|---|
| Slow/failed startup or failed restart | `apps/desktop/src/main/` startup (`index.ts`, `owned-serve.ts`), CLI/environment owners; renderer initialization consumes readiness. Keep `userData/global`, publication-after-health and drained-close ordering. | Launch stages, first-child exit/deadline and restart-after-stability cases. The existing mode-selection test is insufficient restart evidence. |
| Invalid IPC or response save | `apps/desktop/src/preload/`, main `ipc.ts` and separately registered handlers; `response-download.ts` in main/renderer. Keep sender/frame, token/handle, sequence and temporary-file ownership. | Foreign sender, sequence gap, partial write, unowned collision and cancellation across rename. Review actual reachability per channel. |
| Stale Dock/native/Linux operation | Main `app-dock*`/`linux-workspace*`, agent hooks `modules/app-dock/src`, guest helpers under `apps/desktop/resources/`. Keep profile revision, tab generation, runtime/binding/process identity and separate RPC authorities. | Delayed attachment/rebind, cancellation after dispatch, slot retention and actual process disappearance; a provider ACK cannot establish the UI postcondition. |
| WSL unavailable or Live capture incomplete | `apps/desktop/src/main/wsl/` plus renderer WSL connections; main `live-*`, dedicated preloads/overlay. Retain distro generations and permission/availability/reachability distinctions. | WSL artifact/authentication/timeout evidence on Windows; requested-source denial, unsent segments and real capture/protection evidence on the applicable OS. |
| Lost drafts, close hang or failed update | Main window/preload flush, store/draft and updater owners. Keep per-window ACKs, WAL/blob ownership, ready-cache revalidation and resource-stop order. | Bounded/coalesced flush, WAL-aware backup negative control, stop/install failure and packaged child-close behavior. |
| Web/shared behavior changed | `apps/web/src/entry.tsx` owns browser adaptation/distribution; `packages/app-shell` owns shared UI/contexts/contracts/assets. Keep default-server preference separate from current-origin authentication. | Credential replacement, route/disposal, ambiguous admission and matching shared browser/E2E coverage. |

Location/evidence basis: `s2.l1.desktop-web`, §1 “Startup, readiness and shutdown,” §2 “Windows, persistence and IPC authority,” §4–8; `apps/desktop/src/main/README.md:3–34`; `apps/web/README.md:3–6,31–33`. The accepted L3 “Cross renderer, preload and main with a scoped capability,” “Move from a visible Dock to a browser, native or guest effect,” and “Finish capture, persistence and installation at the right boundary” explain the retained handoffs.

**3. Preserve invalid and unknown outcomes.** Reject stale ownership or invalid payloads at the responsible admission boundary; do not weaken validation merely to make a caller succeed. Desktop-owned HTTP-success readiness, WSL authenticated-body/wrong-password checks, shared-app PID-or-healthy startup and stricter ongoing probing are distinct contracts. Preserve that distinction during compatibility work. Maintain explicit uncertain results when dispatch or termination cannot be settled; reacquire current evidence before another effect. (`s2.l3.desktop-web`, “Launch, choose a server and identify the health decision,” “Cross renderer, preload and main with a scoped capability,” and “Move from a visible Dock to a browser, native or guest effect.”)

**4. Coordinate shared admission and UI/API changes.** Replacing credentials must retire the old context even if the server key stays equal; A→B→A does not restore an old callback. A failed first-send response may follow durable admission: preserve dispatched session/request identity for exact retry and keep optimistic display recovery separate from server outcome. Reconnect/canonical reads establish neither provider continuation nor clustered recovery. When a public Protocol/Server HttpApi changes, regenerate Client and coordinate affected adapters; never hand-edit its generated trees. (`s2.l3.desktop-web`, “Reconnect without transferring work to a replacement owner”; instruction: `AGENTS.md:1–2,209–211`.)

**5. Propagate the change to owned products and documentation.** Preserve typed native phrases/placeholders and intentional English while updating localization; verify terminology using the prescribed corpora and record uncertainty. Keep dialog/worker lifetime with its actual owner, terminal/desktop theme schemas separate, and generator ownership limited to demonstrated products. Update the relevant user guide for user-facing changes. For generated Dock corpus documents, update the handwritten inputs in `apps/desktop/docs/corpus/app-dock/generate-corpus.mjs` and regenerate its named products; stored “measured”/“ready” labels do not execute tests. Rebuild affected host outputs and stage matching executable companions; a remembered update-ready version or declared build check is not installed-package proof. (`s2.l3.desktop-web`, “Carry changes through shared UI and distribution”; `s2.l1.desktop-web`, §9 “Web, languages, media and historical evidence”; instructions: `apps/desktop/AGENTS.md:5–14`; `packages/app-shell/AGENTS.md:23–34`; `AGENTS.md:146–154`.)

## Verification and boundaries

**Future implementation gates; none ran here.** After a separately authorized code change, use change-scoped remote tests and package typechecks, retaining exact revision, command, OS and results. The CI helper uploads a working-tree snapshot; that remote operation requires task authorization. Full-suite cadence is once per epic. A package's local test script is not authorization to bypass the root default; local tests need the root rule's explicit owner exception. (`AGENTS.md:156–179`.)

| Working directory | Prescribed route | Scope |
|---|---|---|
| Repository root | `bun run test:ci desktop <files>` | Select affected desktop tests; root supports `--os linux`, `--os windows` or `--os both`. |
| `apps/desktop` | `bun typecheck` | Run the declared package script; do not invoke `tsc` directly. |
| `apps/web` | `bun typecheck` | Browser-host typecheck; shared UI/browser/E2E harnesses belong to `packages/app-shell`. |
| `packages/client` | `bun run generate` | Required after public Protocol/Server HttpApi changes. |
| Repository root | `bun run check:guards --base origin/dev` | Required before calling an implementation change done; handle findings under guardrail instructions. |

Proof scripts run outside ordinary Bun discovery. Session/timeline edits require a production benchmark baseline and after-change comparison. Use injected clocks for stream-liveness edges. OS-dependent reaping, WSL, capture, signatures/installers and accessibility require appropriate environment evidence beyond mocks or stories. (`s2.l1.desktop-web`, §2, §5, §8; `apps/desktop/src/main/README.md:26–27`; `packages/app-shell/AGENTS.md:3–4`; `.orchestra/skills/desktop-startup-maintenance/SKILL.md:30–34`.)

**Stop at missing authority or evidence.** Preserve unknown outcomes when identity/reaping or write completion cannot be established, and hand the unresolved boundary to its owner. Do not restart the running app/server during this campaign. Keep known findings open: stable-child backoff indexing, early-credential comment, differing health predicates, partial enforced CSP, nonuniform IPC admission and hardcoded startup English. No automatic repair follows from documenting them. Visual/locale/media quality, native/provider effects, release integrity and family-supported/metadata-only branches remain unproved. (`AGENTS.md:199–205`; `packages/app-shell/AGENTS.md:6–8`; `s2.l3.desktop-web`, “Verification status and remaining evidence.”)
