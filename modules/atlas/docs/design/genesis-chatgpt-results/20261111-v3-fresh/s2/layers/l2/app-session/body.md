## Composition, identity and asynchronous ownership

AppBaseProviders establishes theme, palette, language, errors/query, WSL, model preferences and reusable dialog/file composition. AppInterface adds server/global state, settings, connection gating, routing, tabs, permissions and notifications. Drafts receive file, prompt and comment providers; real session workspaces also receive terminal state. Restored navigation and draft hydration gate entry. The surrounding shell survives content errors, while route changes reset the content boundary; fatal renderer reporting, manual reporting and updates have separate triggers. [s2.l1.app-session §Authority, composition and identity]

Three identities explain which state may survive a transition:

| Identity | Observed lifetime | Maintenance inference |
|---|---|---|
| Server connection key | Navigation/persistence identity survives display changes. | Preserve stable route and storage ownership. |
| Transport credentials | URL, username, password or HTTP token changes dispose the old same-key context. | Old asynchronous work must not commit under replacement credentials. |
| Server scope plus directory | Workspace providers can remain mounted across sibling sessions; lineage resolves the directory. | Session callbacks need their own ownership checks. |

Generation captures permanently expire when an owner departs, including A→B→A. Equality of the returned route value cannot restore the earlier operation's authority. Path normalization preserves drive/UNC/root conventions but does not resolve filesystem identity; supplied-ID prefix checks and Math.random fallbacks do not establish authentication strength. ## Durable admission, optimistic state and draft storage

The reusable session-ui editor owns interaction commands: mode, history, completion and IME-aware Enter. App-shell owns policy, attachments, session creation, persistence and network submission. Its first-send path captures credentials, directory, draft/tab and generation owner, retains an admission record across composer remounts, resolves the session/worktree, acknowledges subagent policy through serialized writes and a canonical read, then validates owner and policy again at dispatch. An earlier failed policy write remains a barrier. [s2.l1.app-session §Prompt admission and draft ownership]

Admission and promotion have different meanings. Core reconciles an existing request ID only when session, encoded prompt and delivery agree; conflicting reuse fails. Prompt context additionally participates in projection equivalence, so these comparisons must stay distinct. New admission requires a durable sequence and projected record before returning. Promotion later materializes a transcript user message; admission alone establishes neither a rendered turn nor completed assistant work. **Instruction:** root AGENTS keeps admission separate from execution, with `resume: false` admitting without the advisory wake. [s2.l1.app-session §Prompt admission and draft ownership; `AGENTS.md` §V2 Session Core]

In this submit path, optimistic presentation can be removed. The failure path can remove an optimistic message and restore consumed input while retaining a dispatched session/request: a failed response may follow successful admission. Only a never-dispatched attempt whose session is confirmed empty may delete that session. This is a narrower observation than a guarantee that every failure branch restores all state. After admission, draft handoff carries later edits into the session unsent and avoids overwriting newer input. **Maintenance inference:** preserve request identity for an exact retry; clearing a busy indicator does not settle server outcome. [`packages/app-shell/src/components/prompt-input/submit.ts:409–475,546–579,659–674`; s2.l1.app-session §Prompt admission and draft ownership]

Prompt scopes distinguish drafts from sessions, while tab-owned memory outlives a composer mount. Persist separates global/workspace/draft/window and remote namespaces, migrates canonical-local keys and guards edits during asynchronous hydration. IndexedDB draft documents can refer to SHA256-addressed image blobs, with version and cleanup logic. **Gap:** these mechanisms were not exercised against quota limits, interrupted writes or real migrated stores. [s2.l1.app-session §Prompt admission and draft ownership]

## Transport, liveness and canonical recovery

The app adapter converts generated-client results to app view contracts. Scoped fetch composes context, Request and call abort signals; readiness retains success and retries rejected attempts. Startup accepts numeric PID **or** `healthy: true`, whereas the separate health probe requires `healthy === true`. Health polling needs two consecutive failures before declaring down and considers recent stream activity. Preserve this static discrepancy when diagnosing a successful startup followed by an unhealthy probe. [s2.l1.app-session §Transport, stream health and canonical recovery]

Raw stream bytes establish liveness, including comment heartbeats with no decoded event. The client batches events and merges only adjacent deltas with matching identity/directory, preserving intervening order. It reconnects after 45 seconds of silence with bounded backoff. The server installs its bounded 4,096-event subscription before `server.connected`, sends 15-second comment heartbeats and emits frames without replay IDs. **Interpretation:** reconnect plus canonical reconciliation is the supported model; durable replay, universal losslessness and overload recovery were not demonstrated. [s2.l1.app-session §Transport, stream health and canonical recovery]

Canonical sync preserves streamed values touched during a fetch, uses tombstones/generations against late resurrection, pins active sessions/ancestors and pages to user-turn boundaries. Recovery coalesces reads, rejects superseded generations and repeats a GET when policy changes in flight. Its local read receipt is not a backend event revision; compatibility snapshots lack canonical V2 policy provenance. Admission enters pending-input state, promotion creates a transcript entry, and incomplete promotion context requests recovery. Stable part IDs are adapted to renderer ordinals rather than sorted as content. **Maintenance inference:** keep transport health, event adaptation and authoritative rereads separately diagnosable. [s2.l1.app-session §Transport, stream health and canonical recovery]

## Permission requests and terminal boundaries

Request discovery walks the viewed session and descendants. Auto-accept walks ancestry with cycle protection; explicit false defeats directory fallback, and Relay hook asks always require a live response. Responses are server-scoped, pending-checked and deduplicated; failure releases the dedup entry for deliberate retry. Empty scope cannot support “always.” Questions retain per-request selection/custom-answer state; saved permissions explicitly list, remove and refetch. These are client coordination rules, with backend authorization still outside this proof. [s2.l1.app-session §Requests, terminals and auxiliary lifetimes]

Terminals persist by server/workspace and retain exited agent terminals for viewing. Attach fetches a connection token before opening the WebSocket. Cursor advancement uses JavaScript string length, hence UTF-16 code units; reconnect distinguishes an exited/missing PTY from a recoverable connection loss. The Ghostty serialization addon requires activation and can serialize terminal state or plain active-buffer text; its xterm.js-port header does not prove equivalence. **Instruction:** agent PTYs remain the Core bash tool's `AgentTerminal.run` path after sandbox wrapping, with sanitized model output and nonce-bound shell marks. Root guidance records an unresolved slow-WebSocket-reader growth limit. No PTY or slow-reader experiment ran. [s2.l1.app-session §Requests, terminals and auxiliary lifetimes; `AGENTS.md` §Terminal and PTY]

## Skills catalog, content and editing ownership

Skills illustrates why catalog validity, visibility and write eligibility need separate decisions. `readSkills` accepts the complete list response's `.data` array, including empty, requiring string `name`, `location` and `content`; `description`, `mtime` and `internal` are optional and nullable with their declared string/number/boolean types. A malformed entry fails the entire load. The decoder provides no nonempty, uniqueness or path-safety refinement. Visibility removes `internal === true` and descendants under any supplied `/SKILL.md` folder, including internal-parent folders; it does not delete entries. Search covers name/description/location, and sorting orders project/global/builtin then name. [s2.l1.app-session §Skills catalog, editing and ownership]

Ownership follows location, not name. Literal `/builtin/` is builtin; normalized paths under the current directory are project, and the remainder global. Within a project, `.orchestra/skills/own/` is governed before other checks; lowercase `.md` under `.orchestra/skills/`, `.orchestra/skill/`, `.claude/skills/` or `.agents/skills/` is editable, otherwise fixed. **Gap:** these lexical rules establish neither symlink/dot-segment safety nor server filesystem enforcement. [s2.l1.app-session §Skills catalog, editing and ownership]

The server-scope/directory warm cache paints promptly while refreshing. Only a successfully decoded/filtered/sorted list updates it. Statuses 404/405/501 become unavailable; malformed or other failures become error, distinct from empty, with Retry. Read cancellation and disposal suppress late results. Add sends name/description/content; edit additionally maps location to path and forwards optional mtime. The dialog permits editing only for add or `edit` access, prevents duplicate busy submissions, and applies disposal checks. Save/remove close only the originating dialog and reload; a saved-but-unlisted location remains visible as a notice. Write calls lack the page abort signal: suppressing late UI updates does not cancel an already sent write. [s2.l1.app-session §Skills catalog, editing and ownership]

The pinned `/api/skill` GET/PUT/DELETE declarations and handler confirm service delegation and conflict/error mapping. The API description reserves new files for project `.orchestra/skills` and calls global/builtin/Atlas-governed files read-only; this is attributed contract intent, not an inspected filesystem implementation. **Maintenance inference:** change decoder, editor payload and API together while preserving mtime/path ownership and unknown write outcomes. [s2.l1.app-session §Skills catalog, editing and ownership]
