## Purpose and responsibility
This component owns durable Session input admission and retry reconciliation at the facade/admission/retry boundary, not provider execution, promotion, or visibility. The caller supplies a prompt (with optional ID, delivery, context, and `resume`) and receives an admission receipt; the component normalizes identity/delivery, admits or reconciles an existing record, and only then advises execution. Durable admission precedes advisory wake unless `resume: false`, and admission is not execution or model-visible history. ## Contract and state model
Normalization at facade entry, in observed order, is: `messageID = input.id ?? SessionMessage.ID.create()`, prompt hooks run, `prompt = resolvePrompt(input.prompt)`, `delivery = input.delivery ?? "steer"`, build an `expected` record (sessionID, messageID, prompt, delivery), call `SessionInput.admit` (adding non-empty `promptContext.reminders` only), convert `LifecycleConflict` defects to `PromptConflictError`, re-check `equivalent(admitted, expected)`, then, only if `input.resume !== false`, call `execution.wake(admitted.sessionID)` and return the admitted receipt. Retry equivalence (`equivalent`) is the observed/implemented comparison: it compares delivery plus `matchesPrompt` — session ID and JSON-stringified encoded prompt. It does *not* compare prompt context, time, or sequence. No authorized rationale for that field selection was supplied. Projection behaviour supplied in L1:identity: `projectPrompted` first updates an input row matching ID, session ID, and null `promoted_seq`, then checks `matchesProjection`; if no row was updated, an existing row must match projection fields and the requested promoted sequence or conflict; if absent, it inserts a row with admitted and promoted sequence both set to the promoted sequence. Wake boundary, both coordinator branches: `execution.wake` registers newly recorded work and may coalesce. In the implemented coordinator, `wake(key)` has two branches — if an entry is active it sets `pendingWake = true` and returns without starting new work (coalesced follow-up); if no entry is active it creates an entry, stores it, and starts `drain(key, false)`. By contrast, explicit `run(key, runOptions)` joins an existing entry by awaiting its `done`, or creates an entry and starts `drain(key, true)`, awaiting its `done`. Admission therefore does not synchronously execute a provider call and does not guarantee completion: an active wake is only a coalesced flag, and an idle wake starts a wake drain whose provider/execution outcome is outside this component's contract. Interface comments describe this as process-local, advisory behaviour; they are not runtime proof of serialization or delivery. ## Conditions and failure boundaries
- Exact retry: same ID, equivalent session/prompt/delivery → return original record, no duplicate admission; a resume retry re-wakes. Changed prompt or delivery on a reused ID → `LifecycleConflict` → `PromptConflictError`; the facade's own `equivalent(admitted, expected)` re-check is a second conflict gate even if `admit` did not die.
