## Purpose and responsibility
This component owns durable Session input admission, its pending/promoted row state, the `SessionInput.Admitted` receipt, and projection of `PromptAdmitted`/`Prompted` events into that row. It does not own the runtime drain, provider execution, or visible-history rendering beyond the promotion write that makes admitted input visible. The intended boundary separates three things that must not be conflated: durable admission, promoted input, and visible user history. Admitted input is outside model-visible history until promotion 【L1:authority#Evidence register @ 82d5d832e8ded04256460acf8296edc21b19121a3cda5047b58416ffe82210db】, citing `docs/specs/v2/session.md:3-50 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Product rationale for these rules is not supplied and is not inferred 【L1:authority#Evidence register @ 82d5d832e8ded04256460acf8296edc21b19121a3cda5047b58416ffe82210db】.

Durable carriers are the `session_input` row and the event sequence carriers. ## Contract and state model
Intended contract: durable admission precedes advisory wake unless `resume: false`; exact-retry reconciliation only on matching Session/prompt/delivery; conflicting reuse fails; admitted input becomes visible only at `Prompted` promotion 【L1:authority#Evidence register @ 82d5d832e8ded04256460acf8296edc21b19121a3cda5047b58416ffe82210db】, citing `AGENTS.md:207-218 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085` and `docs/specs/v2/session.md:3-50 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`.

Intended atomic visibility, labelled as intended only: the spec states the `Prompted` projector atomically writes the visible message and promotes the inbox row in the same transaction 【L1:authority#Evidence register @ 82d5d832e8ded04256460acf8296edc21b19121a3cda5047b58416ffe82210db】, citing `docs/specs/v2/session.md:3-50 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Inspected projector call sites are separate: `Prompted` projection dies if `event.durable` is undefined, calls `SessionInput.projectPrompted(db, {..., promotedSeq: event.durable.seq})`, then calls `run(db, event)`; `PromptAdmitted` projection dies if `event.durable` is undefined, calls `SessionInput.projectAdmitted(db, {admittedSeq: event.durable.seq, ...})`, and shows no `run(db, event)` call 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】, citing `packages/core/src/session/projector.ts:283-311 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. The bodies of `projectPrompted`, `projectAdmitted`, and `run(db, event)` are not supplied in that excerpt, so visibility timing, ordering, idempotency, and transaction boundaries are not established from the projector excerpt alone 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】.

State transitions that must stay true:
- Admitted/pending: a row exists with `admitted_seq` set from the admitted event/receipt and `promoted_seq` null. `PromptAdmitted` sets `admittedSeq` from `event.durable.seq` and does not, in the shown lines, call `run` 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】.
- Promoted: `Prompted` sets `promotedSeq` from `event.durable.seq`, then calls `run(db, event)` 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】. Promotion is the visibility boundary; admission without promotion must not be treated as visible history.
- Both projectors die on missing `event.durable` 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】.
- Delivery timing differs by delivery kind: `steer` promotes at the next safe provider-turn boundary including continuation, `queue` stays FIFO while a drain requires continuation and promotes exactly one when otherwise idle 【L1:authority#Evidence register @ 82d5d832e8ded04256460acf8296edc21b19121a3cda5047b58416ffe82210db】, citing `docs/specs/v2/session.md:155-185 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Why a violation matters: treating a pending row as promoted would expose unpromoted input as visible history; treating a promoted row as merely admitted would lose the delivery/sequence carrier that distinguishes promotion order and retry reconciliation.

## Conditions and failure boundaries
Retry equivalence is narrower than projection matching. `equivalent` compares delivery and `matchesPrompt`; `matchesPrompt` compares session ID and JSON-stringified encoded prompts, and does not compare prompt context, time, or sequence 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】, citing `packages/core/src/session/input.ts:291-302 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Consequence: a caller retry may be equivalent despite context/time differences, whereas projection reconciliation must match those fields 【L1:identity#Reuse and conflicts @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】. Expanding `equivalent` to include context/time/sequence, or shrinking `matchesProjection` to `equivalent`, would change retry and reconciliation semantics in opposite directions.

Projection matching adds prompt-context JSON equality and epoch-millisecond time equality to `equivalent` 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】, citing `packages/core/src/session/input.ts:304-317 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. The existing-row projection fallback also requires equal promoted sequence 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】, citing `packages/core/src/session/input.ts:200-252 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Changing any of context, time, or promoted-sequence checks changes which historical or duplicate projection is accepted.

Admission identity: `admit` first looks up by `input.id`; if found, returns the stored record only when `equivalent(existing, input)` holds, otherwise dies with `LifecycleConflict` 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】, citing `packages/core/src/session/input.ts:48-93 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. With no existing record, it tries historical reconciliation before publishing `PromptAdmitted`, and its defect handler returns a row only if equivalent 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】. The facade converts `LifecycleConflict` to `PromptConflictError`, and any other defect dies 【L1:entry-storage-execution#Evidence register @ 42b281f6c7d585de1a3449efe5da0dcb257607ea36f70c25a344cf2a234a9b31】.

Historical reconciliation requires a durable `Prompted` event version, rechecks in an immediate transaction, looks up the message by ID, requires matching session and user-message type, and takes delivery from original event provenance because user projections omit delivery 【L1:identity#Evidence register @ 3c59da7d6729280b9bc75e8dca0e8bd434e7982e18220ddc6e48b90918f7a460】, citing `packages/core/src/session/input.ts:96-160 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`. Removing provenance delivery, or substituting delivery from the projected user message, would break legacy exact-retry reconciliation.

Projection fallback/insertion: `projectPrompted` first updates an input row matching ID, session ID, and null `promoted_seq`; after update it checks `matchesProjection`.
