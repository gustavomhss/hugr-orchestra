they did not consume each other's answers or the previous L4 answers.

The original [operational output](L4-sol-operational.body.md) correctly returned OP-5 BLOCKED: its supplied
L3 explained behavior but lacked the approved public transport reference. That body was not relabelled or
silently rewritten. Before spending a complete layer review, the lead prepared one source-bound supplement
against six exact same-baseline Protocol/Server/Schema files; both judges independently accepted it.
Only the SAME operational Sol session then revised. The other three model bodies stayed unchanged.

The reference body's original candidate-status text is preserved verbatim; its acceptance is carried by
the release above, not retroactively attributed to its author. One judge initially returned a malformed
manifest ID; [original answer](OP-supplement-terra-2-v1.original-decision.json) was preserved and not counted.
A [same-session linked identity correction](OP-supplement-terra-2-v1-identity.decision.json) settled the exact
binding before producer reuse. It was not silently normalized by the lead.

The supplement describes Orchestra public request/receipt/observation contracts, **not the external OpenCode
campaign CLI**. No real request, credentials, deployment authority or runtime outcome is supplied. Missing
internal cutoff/continuation/provider evidence still requires a precise handoff rather than invented endpoints.
