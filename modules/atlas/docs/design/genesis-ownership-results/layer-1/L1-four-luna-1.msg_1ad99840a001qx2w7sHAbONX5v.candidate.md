## Reuse and conflicts

**Observed behavior:** Admission uses ID to find a candidate, then applies `equivalent`; a mismatch is a lifecycle conflict. Historical reconciliation obtains delivery from durable-event provenance and checks it against the canonical record and request. Projection matching adds prompt context and creation time to retry equivalence, while the existing-row projection fallback also requires equal promoted sequence. These are distinct predicates, not one unified identity rule. (Citations: `packages/core/src/session/input.ts:48-93 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`; `packages/core/src/session/input.ts:96-160 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`; `packages/core/src/session/input.ts:200-252 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`; `packages/core/src/session/input.ts:291-317 @ c9b8e54cbf2c6c2c4bb59bbda2dc878430a54085`.)
